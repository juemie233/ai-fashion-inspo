## 1. 一句话结论

**手机是「随手采集 + 随手浏览 + 轻编辑」的工具，不是「桌面工作台」**。凡是需要表格批量操作、长时间跑任务、依赖 PC 环境（Playwright / ComfyUI）的功能，都留在电脑上。

判定标准（按顺序问）：

1. **数据是否已在手机上可获得？** 只调 `/api/*` 的天然可移植；依赖 PC 本地进程（ComfyUI、Playwright、Ollama）的手机只能当遥控器；
2. **交互是否适合触屏？** 瀑布流、多列网格、滑动、长按、拍照、相册多选适合；密集表格、右键、拖拽排序、多选批量打标签不适合；
3. **是否需要长时间驻留？** 采集 / 人脸扫描 / 批量出图是分钟级到小时级，RN 息屏即断，手机只适合「发起 + 看进度 + 看结果」；
4. **使用频次与场景？** 通勤翻素材、买衣服拍照入库是高频；改标签规则、清数据、管模型是低频且危险。

> 实践版判定公式：**只要有一步需要「盯着多个字段做决策」，就不移植。**

| 分享 Intent | **多图**（≤12 张）逐张入库并给一条汇总；内容重复（409）单列「已在库中」；含链接文本 → `/inspirations/from-url`（带标题提示）；`webUrl` 兜底；其它提示不支持 | `expo-share-intent@3.1.0`，仅 Android |
| 视频浏览 | 卡片「▶ 视频」角标；详情用 `expo-video`（封面帧 + 原生控件 + 全屏 / PiP），容器按封面比例 | 2,760+ 条视频素材 |
| 深色模式 | 跟随系统，无需重启；颜色全部走令牌 | 错误边界页固定亮色（有意取舍） |
| 设置 | 后端地址（可复制 / 从剪贴板粘贴）、**API Key**（掩码回显，请求自动带 `X-API-Key`）、诊断（版本 / 地址 / Key 状态 / 离线缓存）、清缓存 | 扫码填地址未做（Web 无出码面，见规划 §11.5） |

### 2.2 不移植（理由）

| 页面 | 理由 |
| --- | --- |
| 采集管理 `/scraper` | 依赖电脑 Playwright + 浏览器环境，手机只能当遥控器 |
| 素材管理 `/admin` | 密集表格 + 批量勾选，桌面工作流，误触成本高 |
| 数据治理 `/admin/governance` | 批量清理 / 不可逆操作，不该放在随手可点的设备上 |
| 数据洞察 `/admin/insights` | 图表 + 向量库状态，屏幕装不下 |
| AI 模型管理 `/models` | 运维配置（模型文件 / 显存 / ComfyUI 参数），一年改一次 |
| 人脸库扫描 `/face-scan` | 分钟级批处理 + 逐条决策，手机只看最终人物列表 |
| 模特照片上传 `/model-photos` | 565 行重度上传流程（多角度 / 裁剪 / 绑定） |
| 标签高级管理 `/tags/advanced` | 分类树维护、规则配置 |

补充判断：**瀑布流**不做（RN 测量抖动）；**拖拽排序**不做（触屏与滚动冲突，改上移 / 下移）；**右键 / hover** 改长按菜单；**批量打标签**不做（选完标签看不到画面，易打错）。

### 2.3 手机「反向优势」（比 Web 更强，优先做）

1. **拍照即入库**：相机 → 上传 → 自动 AI 打标；
2. **相册多选批量上传**：一次 20 张，逐张进度；
3. **以图搜图**：逛街拍同款找相似（手机是自然入口）；
4. **分享到 App**（Android Share Intent）：小红书 / 抖音点分享直接进素材库。

## 3. 跨端复用与统一约定

| 可直接复用 | 不可复用 |
| --- | --- |
| `shared/types/*`（`@shared/*` 路径别名，`api.ts` 已引用分页 / 枚举 / 标签类型） | Vue 组件（模板 / CSS / Arco 全不通用） |
| 接口契约与错误格式 `{detail: "..."}`；axios 客户端 baseURL 动态注入 + `normalizeBaseUrl` | 图表（Arco / 自绘 → RN 需 victory-native / skia，本就不移植洞察页） |
| 纯函数：`sourceLabel`（两端各一份，需同步维护）、时间格式化 | 表格类页面（全部不移植） |

**新增功能时遵守**：图标一律用 `mobile/components/Icon.tsx`（不要写 `<Ionicons>`）；大图浏览用 `ImageViewer`；列表用 `FlatList`（两列 `numColumns={2}`），分页用 `onEndReached`；后端字符串字段渲染前做类型兜底（`sourceLabel` / `getFileUrl` 已加）。

### 3.1 UI 设计系统（0.8.0 起，新增页面必须遵守）

| 项目 | 约定 |
| --- | --- |
| 令牌唯一真源 | `mobile/constants/theme.ts`：颜色 / 字阶（11·12·13·15·17·22）/ 间距（4·8·12·16·20·24·32）/ 圆角 / 图标尺寸 / 触控区 44 |
| 禁止字面量 | `app/**`、`components/**` 里**不允许**出现十六进制颜色与裸 `borderRadius: 数字`；由 `__tests__/theme.tokens.test.ts` 扫描文件系统强制执行 |

| 文案字典 | `mobile/constants/labels.ts`：标签分类 / 平台 / 任务类型 / 任务与出图状态 / 排序 / 筛选（改一处全站生效） |
| 基础组件 | `components/ui/`：`AppText`·`Button`·`IconButton`·`Chip`·`SegmentedTab`·`MediaCard`·`ScreenHeader`·`BottomSheet`·`EmptyState`·`ErrorState`·`Skeleton`·`Badge`·`ListRow`·`Snackbar` |
| 页面骨架 | Tab 四页自绘 `ScreenHeader`（原生 header 关闭）；Stack 页保留原生 header（返回手势）；列表页统一三态（骨架 / 错误+重试 / 空态） |
| 图片 | 统一 `expo-image`（`transition` + `memory-disk` 缓存）；比例用 `hooks/useAspectRatio`（图片 `onLoad` 后的真实宽高 + 内存缓存），**不要**用 RN 的 `Image.getSize`（见 §5.2） |
| 底部弹层 | 统一 `ui/BottomSheet`（安全区、遮罩可点关闭、键盘避让、`maxHeight 88%`），不要再手写 `Modal + 高度写死` |

## 4. 构建 Android APK（本机手册）

手机没有 Google Play → 装不了 Expo Go → **只能自建 APK**。以下为实测固定动作（2026-10-23 起，2026-11-01 随 0.8.0 复验）。

### 4.1 工具链（一次性）

| 组件 | 位置 |
| --- | --- |
| JDK 17 | `C:\Users\Administrator\jdk17\jdk-17.0.20.1+1`（系统默认 java 是 25，Gradle 8.10 不认，**必须显式 `JAVA_HOME`**） |
| Android SDK | `C:\Users\Administrator\AndroidSdk`（platform-tools / platforms;android-35 / build-tools 35 / NDK 26.1 / CMake 3.22） |

### 4.2 首次构建：必须用短真实路径

项目在 `...\Desktop\Claude Code\...`（带空格），CMake 会把源路径压成 `Claude_Code`，react-native-reanimated 的 C++ 对象路径超 Windows MAX_PATH → ninja `mkdir` 失败。`mklink /J` 和 `subst` 都会被 Gradle / CMake 解回真实路径（都试过，无效）——只能**真实复制**到短路径构建：

```bat
:: 首次或依赖大改：/MIR 全量镜像
set MSYS_NO_PATHCONV=1
robocopy "<repo>\mobile" "C:\mb" /MIR
cd C:\mb\android
set JAVA_HOME=C:\Users\Administrator\jdk17\jdk-17.0.20.1+1
set ANDROID_HOME=C:\Users\Administrator\AndroidSdk
.\gradlew assembleRelease
:: 产物：C:\mb\android\app\build\outputs\apk\release\app-release.apk
```

> Git Bash 下 `robocopy` 的 `/E`、`/MIR` 会被 MSYS 当路径转换（`/E` → `E:/`），必须 `MSYS_NO_PATHCONV=1` 或改用 cmd。

### 4.3 日常构建与提速（纯 JS 改动）

**日常不要用 `/MIR`**：它会删掉 `C:\mb\android\build`、`.cxx`，等于每次全量重编 native（几分钟）。日常用 `/E`（只覆盖不删除），保留缓存后一次 **30~40 秒**：

```bat
set MSYS_NO_PATHCONV=1
robocopy "<repo>\mobile" "C:\mb" /E
cd C:\mb\android && .\gradlew assembleRelease
```

提速配方（实测 6m37s → 31s；无改动重跑 9s）：

| 做法 | 收益 | 说明 |
| --- | --- | --- |
| **不要加 `--no-daemon`** | 最大 | 冷启 JVM + 重新配置 2~3 分钟，daemon 复用后配置阶段几秒 |
| **纯 JS 改动不要清** `android/.cxx` / `build/` | 最大 | 清一次就全量重编 reanimated、expo-modules 的 C++；只有动原生依赖才需要清 |
| `reactNativeArchitectures=arm64-v8a` | 中 | 手机是 arm64，编 4 个 ABI 纯浪费（仓库侧已配） |
| `org.gradle.caching=true` + `jvmargs -Xmx4096m` | 中 | 任务产物复用；2G heap 偏小（已配） |
| **Defender 排除** `C:\mb`、`~/.gradle`、`AndroidSdk`、仓库目录 | 大 | 实时扫描极拖慢（62s → 31s）；`Add-MpPreference -ExclusionPath` 需管理员（已配） |
| 不要开 `--configuration-cache` | — | Expo / RN 插件有 45 处不兼容，直接 BUILD FAILED（试过） |

**两个环境陷阱**：Gradle 依赖走本机代理（clash 7890，`android/gradle.properties` 的 `systemProp.http(s).proxyHost/Port`；代理没开就删掉，依赖已缓存时不影响增量构建）；**npm 不要设代理**（走 npmmirror，设了必 `ECONNREFUSED`）。

**更快的日常开发路子（尚未落地）**：装一次 debug APK + `npx expo start --host lan`，手机同网 Fast Refresh，改 JS 秒级生效、完全不用打包。当前仍以 release 包为主。

### 4.4 原生依赖变更（prebuild 固定流程）

0.8.0 加 `expo-image` / `expo-linear-gradient` / `expo-haptics` 时走过一遍：

1. `npx expo install <包名>` —— 由 Expo 选 SDK 52 匹配版本；装完立刻核验 `expo-linking` / `expo-font` / `expo-asset` / `expo-router` 没被 `--legacy-peer-deps` 剪掉；
2. `npx expo prebuild --platform android --clean` —— `--clean` 会清空 `android/`，所以第 3、4 步必须重做；
3. 复核生成物：`AndroidManifest.xml` 的 `android.intent.action.SEND` 数量 = **1**（非 `--clean` 重跑会变 2，见 §5.1）、`supportsPictureInPicture="true"`、`app/src/main/assets/fonts/Ionicons.ttf` 仍在、`usesCleartextTraffic="true"`；
4. 重打 `android/gradle.properties` 提速配方（jvmargs 4096m / `reactNativeArchitectures=arm64-v8a` / `android.kotlinVersion=1.9.24` / `org.gradle.caching=true`）；
5. 同步到构建目录：`MSYS_NO_PATHCONV=1 robocopy mobile C:\mb /E`。

### 4.5 版本号与配置真源

- **唯一真源是 `mobile/app.json`**：`expo.version`、`expo.android.versionCode`、`expo-build-properties` 里的 `usesCleartextTraffic`、各 config plugin 都在这里；`prebuild` 会写进 `android/app/build.gradle`。
- **不要再正则改 `C:\mb\android\app\build.gradle`**——那是 0.5.0 之前的旧做法，`/MIR` 会用仓库旧文件覆盖副本，按字符串替换会静默失配（踩过：打的包版本号没变）。
- `mobile/package.json` 的 `version`（当前 0.1.0）**不参与构建**，不要拿它当版本号。
- `prebuild --clean` 后**唯一需要手补的**是 `android/gradle.properties` 的 `android.kotlinVersion=1.9.24`：RN 0.76 带 Kotlin 1.9.24，而 `android/build.gradle` 的 ext 默认 1.9.25，会让 expo-modules-core 报 Compose 1.5.15 与编译器不匹配。`usesCleartextTraffic` 不需要手改（已在 `app.json`）。

## 5. 真机踩坑（都已修，新增功能勿回退）

### 5.1 构建与原生

| 坑 | 现象 | 根因与修法 |
| --- | --- | --- |
| **图标空白** | 真机所有图标（Tab / 按钮 / 爱心 / 返回）全空白、无报错 | `@expo/vector-icons` 挂载时判 `Font.isLoaded('ionicons')`，而 expo-font 只认自己 `loadAsync` 过的字体 → 判假，渲染空 `<Text />`。结论：字体由 `app.json` 的 `expo-font` plugin 内嵌 `assets/fonts/Ionicons.ttf`（家族名 = 文件名 `Ionicons`），`Icon.tsx` 直接用 family 画码点；**不要改回 `<Ionicons>`**，也不要在 `_layout` 用 `useFonts` 做字体门（加载失败会整页白屏）。这类只有真机能复现，用 `adb logcat` + 探针最快 |
| **视频播放** | 点开视频报「找不到模块」 | `expo-video` 是原生模块（SDK 52 对应 `~2.0.6`，`expo-av` 已弃用）；装完必须重跑 `prebuild` + 完整重建。`app.json` 配 `["expo-video", { "supportsPictureInPicture": true, "supportsBackgroundPlayback": false }]`；播放器封装 `components/VideoPlayer.tsx` |
| **分享 Intent** | 分享后重复入库 / 不生效 | `expo-share-intent@3.1.0`（对应 SDK 52；4.x 起要 SDK 53+）；`app.json` 配 `androidIntentFilters: ["image/*","text/*"]` + `disableIOS: true`，prebuild 写入 `ACTION_SEND`（改配置必须重跑 prebuild）；处理逻辑在 `components/ShareIntentBridge.tsx`，处理完必须 `resetShareIntent()` |
| **分享过滤重复** | 分享面板里应用出现两份 / manifest 里 `ACTION_SEND` 变成 2 段 | 非 `--clean` 重跑 `prebuild` 时 `expo-share-intent` 插件不幂等，会往已有 manifest 再插一遍；`--clean` 重跑，或手动删掉重复的一段（判定：段落内容完全一致） |
| **npm 依赖被删** | 打包失败 / 缺包 | `npm i --legacy-peer-deps` 会**删掉一批包**（实测两次：删 `expo-linking`、删 63 个）；装完立刻检查 `expo-linking` / `expo-font` / `expo-asset` / `expo-router` 是否还在 |
| **mergeDexRelease 文件占用** | `:app:mergeDexRelease` 报「另一个程序正在使用此文件」 | `./gradlew --stop` + 删 `app/build/intermediates/dex/release/mergeDexRelease` 再构建 |

### 5.2 运行时与适配

| 坑 | 现象 | 根因与修法 |
| --- | --- | --- |
| **冷启动请求竞态** | 首次进页面「加载失败」，重进又好，时好时坏 | 页面 mount 就发请求，而 `loadApiBaseUrl()`（读 AsyncStorage）未完成 → baseURL 还是默认 `10.0.2.2`。修法：`apiClient` 请求拦截器里 `await ensureBaseUrl()`（缓存 Promise），`saveApiBaseUrl` 后同步刷新；新增「启动即请求」页面不用再关心顺序 |
| **图片比例探测** | 详情页横图上下大片灰；测试里 `Image.getSize` 抛 `Cannot read properties of undefined (reading 'then')` | RN 0.76 把 `Image.getSize` 改成 Promise 实现，而 jest-expo 的原生桩仍是回调式（`success(320,240)`），两者对不上。改用图片渲染后的 `onLoad` 读 `source.width/height`（`hooks/useAspectRatio` + 内存缓存），既不额外发请求也不依赖原生桩 |
| **深色模式** | 切系统深色后个别页面白底白字 / 纯白卡片刺眼 | 颜色必须走 `constants/theme.ts` 令牌（`useStyles(makeStyles)`）；`app.json` 的 `userInterfaceStyle` 必须是 `automatic`，否则系统不上报暗色；错误边界在 Provider 外，错误页固定亮色（有意取舍） |
| **分享文本 URL 解析** | 抖音 / 小红书文案中链接紧贴中文（`…/abc123/，谢谢`） | `utils/extractUrl.ts` 排除中文与全角标点；`shareIntent.test.tsx` 覆盖 9 项 |
| **占位层盖住图片**（0.8.0 验证发现） | 列表所有缩略图只显示灰块 | `MediaCard` 里占位底色 View 画在 Image **之后**（同级后画的在上层）。改为先占位、后图片 |
| **Tab 标签被裁**（0.8.0 验证发现） | 系统字体 1.15× 时标签下缘被屏幕边缘切掉 | 固定 52 高不够。改为 `56 + 安全区 + (fontScale-1)×24`，1.3× 下实测不裁 |
| **搜索模式行重叠**（0.8.0 验证发现） | 「关键词 / 语义」与下面 chip 行叠在一起 | 分段控件传了 `flex: 1`，在高度自适应的列容器里塌成 0 高度。去掉 `flex` 让其自然撑满整行 |

### 5.3 数据规模与测试

| 坑 | 现象 | 根因与修法 |
| --- | --- | --- |
| **标签墙 ANR** | 2.2 万标签渲染 chip 墙 → JS 阻塞、系统无响应 | 改 FlatList 虚拟列表 + 默认 60 个 + 搜索最多 200 条，并加「标签库加载失败 → 重试」；`GET /api/tags` 一次 4.3 MB / 8.2 秒，需会话级缓存 |
| **持久化缓存污染用例** | 加了队列/离线缓存后，同一文件的后续用例读到上一轮的缓存，断言全乱（错误态被缓存顶掉） | 凡是渲染带持久化的页面的用例，`beforeEach` 里 `await AsyncStorage.clear()`；`expo-image` 的静态方法（`loadAsync`/`prefetch`/`clear*Cache`）要在 `jest.setup.ts` 的 mock 里补齐 |
| **手势库在 Jest / Android 的坑** | 测试里 `useAnimatedStyle` 报错；真机手势完全不响应 | ① Jest：`setupFiles` 加 `react-native-gesture-handler/jestSetup`，并在 `jest.setup.ts` 里 `jest.mock('react-native-reanimated', () => require('react-native-reanimated/mock'))`；② 真机：`GestureHandlerRootView` 必须包住手势树，**Modal 内是独立原生视图树，要在 Modal 里再包一层**；③ 不需要写 `babel.config.js`，`babel-preset-expo` 会自动挂 reanimated 插件 |
| **保存相册/分享的两个坑** | ① 把素材 URL 直接传给 `saveToLibraryAsync` / `shareAsync` 无效；② Android 13+ 权限返回 denied，把用户挡在「没有相册权限」 | ① 素材地址是 `http://后端/api/files/...`，先用 `expo-file-system.downloadAsync` 下到缓存目录再操作，用完 `deleteAsync`；三个模块都是原生模块，用 `require` 包起来在缺失时给「请更新 App」，避免旧 APK 崩页。② `WRITE_EXTERNAL_STORAGE` 在 Android 13+ 已被系统忽略（申请必然 denied），但保存自己写入的图片走 MediaStore **不需要权限**；`utils/mediaActions.ts` 的 `canSaveWithoutPermission` 在 API≥33 时跳过权限拦截，且只申请写权限（`requestPermissionsAsync(true)`） |
| **异步状态不包裹 act** | 测试里满屏 `not wrapped in act(...)` 警告、慢 | 骨架屏呼吸动画在 `JEST_WORKER_ID` 存在时不启动循环（`components/ui/Skeleton.tsx`），否则 Animated 每帧 setState 干扰用例 |

## 7. 风险与注意事项

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 后台任务中断 | RN 息屏后 JS 停跑，轮询会断 | 任务中心只在前台轮询；文案「回到 App 自动刷新」 |
| 局域网依赖 | 手机必须与电脑同网，换 WiFi 就失效 | 错误态给「检查后端地址」入口 + 一键重试 |
| 大数据量列表 | 后端 total 3 万+，翻到底不现实 | 必须筛选 / 搜索；列表用 `thumbnail_path`，详情 / 全屏才取原图 |
| 危险操作 | 删除 / 垃圾桶在手机上极易误触 | 一律二次确认；批量删除只给「移入垃圾桶」（可恢复），详情页删除收进「更多」 |
| 设备差异 | 主力验证机 nova 7 Pro（1080×2340 / 423dp） | 布局用 flex + 百分比；小屏与字体放大通过 `adb wm size` / `font_scale` 模拟验证 |
| 服务启停 | 本项目的后端 / worker 由用户手动管理 | 移动端只提示「需要重启服务」，不自动执行脚本 |
