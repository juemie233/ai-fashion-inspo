# 移动端后续工作规划（2026-11-12）

> 状态：**P0 全部实施 + P1 全部实施（二维码扫描除外，见 §11.5）**（2026-11-12，0.9.0 / versionCode 34，实施记录见 §11）；P2 按需排期
> 范围：`mobile/`（React Native / Expo SDK 52）与手机端使用的 `/api/*` 接口
> 结论：**不再把 Web 的桌面功能往手机上搬**。下一步优先把「拍照即入库 / 以图搜图 / 分享入库 / 随手浏览」这四条手机独有链路做闭环，并补上任务中心、上传队列、看图手势三个明显断点。
> 说明：本文只做规划，未改任何代码。

---

## 1. 现状盘点

### 1.1 已有能力

当前手机端是 **4 个 Tab + 9 个 Stack 页**：

| 模块 | 已有能力 | 边界 |
| --- | --- | --- |
| 素材库 | 两列网格、三态、下拉刷新、无限滚动、收藏、筛选、排序、长按多选 | 不做真瀑布流 |
| 上传 | 相册多选 ≤20、拍照、逐张进度、失败重试、可移除 | 队列只在内存；息屏/杀进程会断 |
| 搜索 | 关键词分页、语义检索、以图搜图（相册）、标签多选、最近搜索、常用标签 | 以图搜图不能直接拍照/框选 |
| 详情 | 大图按比例、全屏看图、收藏、标签编辑、移入垃圾桶、相似推荐、原链接 | 看图只有「点击关闭」，不能缩放/保存 |
| 任务中心 | 列表、进度、失败原因、取消、活跃时 3 秒刷新 | 只拉前 30 条；没有阶段文案/结果摘要/分页 |
| 人物 | 博主/模特分段、搜索防抖、作品墙分页 | 只读，不做新建/编辑/合并/人脸扫描 |
| 标签 | 浏览、搜索、改名 | 合并/删除/颜色/排序留 Web |
| 合集 | 合集宫格、合集详情、多选「加合集」 | 不能新建/改名/排序 |
| 出图记录 | 批次列表、候选图网格、全屏预览 | 只读，不能确认入库 |
| 分享 Intent | Android 图片入库、链接入库 | 单图/单链接，失败反馈弱 |
| 视频 | 角标、详情播放器、全屏/PiP | 不下载/不编辑 |
| UI/主题 | 设计令牌、14 个基础组件、深色模式、触觉反馈、三态 | — |

当前测试口径以 `mobile/package.json` 与 `npm test` 输出为准；README 记录为 **246 用例 / 25 个文件**（`docs/mobile/移动端.md` 的 243/24 是 0.8.0 旧值，后续应同步）。

### 1.2 现有断点

1. **上传队列不持久化**：`mobile/app/(tabs)/capture.tsx` 的队列是组件内 `useState`，App 被杀、切后台过久或息屏后，未完成的上传直接丢失。
2. **任务中心信息不足**：`mobile/app/tasks.tsx:32` 固定 `fetchTasks(1, 30)`，没有翻页；`mobile/components/TaskRow.tsx` 只显示类型/状态/进度/错误，后端已有的 `last_stage`、`result_summary`、运行台账都没有展示。
3. **看图能力偏弱**：`mobile/components/ImageViewer.tsx` 只支持「点任意处关闭」，不能双指缩放、双击放大、保存到相册或分享。
4. **合集只能消费不能维护**：`mobile/app/collections.tsx` 只读；后端已有合集创建、改名、排序接口（`POST /api/collections`、`PATCH /api/collections/{id}`、`PATCH /api/collections/order`），手机没有入口。
5. **以图搜图只能从相册选**：`mobile/app/(tabs)/search.tsx:209` 只调用 `launchImageLibraryAsync`，逛街现场拍摄同款还要先退出 App 拍照再回来。
6. **鉴权头缺失**：`mobile/services/api.ts` 的 axios 只设 `Content-Type`；TODO 已记录 mobile 与浏览器插件连接后端时不带 `X-API-Key`，后端一旦设置 `API_KEY`，手机端会被拦。

## 2. 判定原则

沿用 [移动端.md](移动端.md) 的四条判定：

1. **数据是否已在手机上可获得**：只调 `/api/*` 的天然可移植；依赖 PC 本地进程（ComfyUI / Playwright / Ollama）的手机只能当遥控器。
2. **交互是否适合触屏**：瀑布流、多列网格、滑动、长按、拍照、相册多选适合；密集表格、右键、拖拽排序、批量打标签不适合。
3. **是否需要长时间驻留**：采集 / 人脸扫描 / 批量出图是分钟级到小时级，手机只适合「发起 + 看进度 + 看结果」。
4. **频次与风险**：通勤翻素材、买衣服拍照入库是高频；改标签规则、清数据、管模型是低频且危险。

> 实践版公式：**只要有一步需要「盯着多个字段做决策」，就不移植。**

## 3. P0：最近 1–2 周值得做的 5 件事

### P0-1 上传队列持久化 + 前台续传

| 项 | 内容 |
| --- | --- |
| 目标 | App 被杀/切后台后，未完成的上传不丢；回到前台可以继续 |
| 现状 | `mobile/app/(tabs)/capture.tsx` 队列只在 `useState`；失败项可重试，但队列本身不落盘 |
| 改造 | 队列写入 AsyncStorage（uri/状态/进度/错误）；启动时恢复 `pending/error` 项；提供「继续上传 / 全部重试 / 清空已完成」；上传前检查本地文件是否还存在 |
| 不做 | 真正的 Android 后台长传（需要 foreground service / WorkManager，复杂度和功耗都高）；只做「前台续传」 |
| 验收 | 杀进程重进 → 队列还在；息屏 2 分钟后回前台 → 可继续；本地文件被删 → 该项标记失败并可移除 |
| 预估 | 2–3 天 |

### P0-2 任务中心升级：分页/筛选 + 阶段文案 + 结果摘要

| 项 | 内容 |
| --- | --- |
| 目标 | 长任务不再「只看到前 30 条」，能看到当前阶段和完成摘要 |
| 现状 | `fetchTasks(1, 30)`；`TaskRow` 只渲染 progress/done/total/error |
| 改造 | 列表触底加载 / 类型与状态筛选；渲染 `last_stage`（如「第 4/21 个作者」）；完成后展示 `result_summary`；点行进入任务详情（阶段 + 运行记录） |
| 依赖 | `/api/tasks` 已支持 page/size/filter；`TaskOut` 已有 `last_stage`、`result_summary`；`/api/tasks/{id}/runs` 已有台账接口 |
| 验收 | 100+ 任务可翻页；运行中显示阶段；成功后显示摘要；取消语义不变 |
| 预估 | 2–3 天 |

### P0-3 图片查看器补齐手势与保存/分享

| 项 | 内容 |
| --- | --- |
| 目标 | 手机看图具备基本工具能力 |
| 现状 | `mobile/components/ImageViewer.tsx` 只有「点击关闭」 |
| 改造 | 双指缩放、双击放大/还原、单击切换控件、保存到相册（`expo-media-library`）、系统分享（`expo-sharing`）；视频仍走现有播放器 |
| 验收 | 缩放不误触关闭；保存后相册可见；分享面板能带图；Android 返回键行为正确 |
| 预估 | 1–2 天 |

### P0-4 合集创建/改名/上下移动

| 项 | 内容 |
| --- | --- |
| 目标 | 手机上也能整理收藏夹，而不是只能 Web 操作 |
| 现状 | `collections.tsx` 只读；多选「加合集」可现场新建，但合集页本身不能维护 |
| 改造 | 合集页右上角「新建」；长按/更多菜单「改名」「删除」；详情/列表支持上移/下移（不做拖拽） |
| 依赖 | 后端已有 `POST /api/collections`、`PATCH /api/collections/{id}`、`PATCH /api/collections/order`、`DELETE` |
| 验收 | 新建后立即出现在宫格；改名刷新保持；排序与 Web 一致；删除有二次确认 |
| 预估 | 2 天 |

### P0-5 以图搜图支持直接拍照 + 框选

| 项 | 内容 |
| --- | --- |
| 目标 | 逛街看到同款，直接在 App 里拍 → 搜相似 |
| 现状 | `search.tsx` 只从相册选图 |
| 改造 | 增加「拍照搜」入口；拍完可选「使用原图 / 裁剪主体」（`expo-image-picker` 的 `allowsEditing` 或 `expo-image-manipulator`）；沿用 `POST /api/search/vector` |
| 验收 | 拍照 → 裁剪 → 返回相似结果；取消/失败不破坏当前列表；语义模式仍禁用标签与以图搜图 |
| 预估 | 2 天 |

### 4.1 分享 Intent 的具体范围

- 多张图片一次分享（目前单图）；
- 分享文本中的 URL / 标题提取，失败给出「不支持的内容类型」；
- 重复入库/判重命中时明确提示「已在库中」，而不是静默成功或仅 toast；
- iOS 不在当前交付范围（自建 Android APK），不引入 iOS 专属工作量。

### 4.2 出图候选的边界

- 只做「看 + 勾选 + 确认入库/丢弃」，不做参数面板/提交（依赖 PC ComfyUI）；
- 先确认 `confirm` 对移动端与云端的返回结构一致；失败要有可读原因；
- 不做批量下载原图到手机相册（可后续单独做）。

## 5. P2：可选/需要产品拍板

| 项 | 说明 |
| --- | --- |
| 任务暂停/恢复 | 文档目前明确「暂停/恢复/删除留 Web」。如果要做，先只给 `batch_analyze`、`vector_backfill`、`quality_check` 等白名单类型做「暂停/继续」，不要一次铺开 |
| 本地完成通知 | 任务完成时发本地通知（`expo-notifications`）。注意：App 被杀后轮询不可靠，只能做「前台/短时后台」提示，不承诺推送 |
| 随机灵感 | 素材库加「随机一张 / 摇一摇」，适合通勤翻素材；需要后端随机接口或客户端随机 |
| 详情页元数据编辑 | 标题/备注/评分；需确认后端字段与权限，避免和 Web 的批量编辑冲突 |
| 单标签合并/删除 | 目前标签页只改名；合并/删除仍是 Web 的高风险操作，不建议轻易下放 |

## 6. 明确不做

| 功能 | 理由 |
| --- | --- |
| 采集管理 `/scraper` | 依赖电脑 Playwright + 浏览器环境 |
| 素材管理 `/admin` | 密集表格 + 批量勾选，误触成本高 |
| 数据治理 `/admin/governance` | 不可逆批量操作，不该放在随手可点的设备上 |
| 数据洞察 `/admin/insights` | 图表 + 向量库状态，屏幕装不下 |
| AI 模型管理 `/models` | 运维配置，一年改一次 |
| 人脸库扫描 `/face-scan` | 分钟级批处理 + 逐条决策 |
| 模特照片上传 `/model-photos` | 565 行重度上传流程 |
| 标签高级管理 `/tags/advanced` | 分类树、规则配置 |
| 拖拽排序 / 真瀑布流 | 触屏冲突、RN 测量抖动；用上移/下移与规则网格替代 |
| 批量打标签 | 选完标签看不到画面，容易打错 |
| 完整离线写同步 | 冲突合并/幂等/回滚成本远高于收益 |

## 8. 风险与依赖

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| RN 后台限制 | 息屏/切后台会暂停 JS，上传和轮询都会断 | 只承诺前台续传；文案明确「回到 App 自动继续/刷新」 |
| 新原生依赖 | 保存相册/分享/扫码需要 `expo-media-library`、`expo-sharing`、`expo-camera` 等，需重新 prebuild / 构建 APK | 先确认 Expo SDK 52 兼容版本；构建由用户手动执行，不自动跑脚本 |
| 后端接口契约 | 任务阶段、合集排序、出图 confirm 的字段/权限需与 Web 一致 | 先读 `/api/*` 现有 schema，必要时补契约测试；不改后端行为 |
| 鉴权 | 设置 `API_KEY` 后读接口仍开放、破坏性接口需要 header；手机当前不带 | 增加 `X-API-Key` 设置与拦截器；Key 只存本机 AsyncStorage，不写日志 |
| 数据规模 | 3 万+ 素材、2 万+ 标签 | 列表继续用缩略图/分页；标签走会话缓存与虚拟化 |
| 测试与真机 | 手势、分享、相册权限只有真机能验证 | 每个 P0 补 jest 用例；至少在一台真机逐项验收 |
| 构建 | APK 需要短路径 + JDK 17 + 显式 `ANDROID_HOME` | 按 `docs/mobile/移动端.md` §4 执行；用户手动构建 |

## 9. 验收清单

每个功能落地时至少确认：

- [ ] `cd mobile && npm run type-check` 通过；
- [ ] `cd mobile && npm test` 通过，新增行为有渲染/纯函数用例；
- [ ] 设计令牌检查通过（无裸颜色/字号/圆角）；
- [ ] 裸字符串检查通过（非 `<Text>` 节点无字符串）；
- [ ] 深色模式、字体 1.3×、小屏（360×640）不破版；
- [ ] 真机（nova 7 Pro 或当前主力机）走通主路径 + 失败路径；
- [ ] 涉及上传/删除/入库的操作有二次确认或可恢复语义；
- [ ] 不自动执行构建/重启脚本，需要时提示用户手动执行。

### 11.3 与规划的偏差（以代码为准）

| 规划 | 实际 | 原因 |
| --- | --- | --- |
| 「上传前检查本地文件是否还存在」（P0-1） | 用 `expo-image` 的 `loadAsync` 探测，**没有**引入 `expo-file-system` 做 `getInfoAsync` | 探测只需「能否解码」；P0-3 才因为「远程图要落盘」引入 file-system |
| 「列表/详情展示 `last_stage`」（P0-2） | 阶段文案取自 `result.stage` + done/total，**没有**改后端 `TaskOut` | 规划误记 `TaskOut` 已有该字段（实际只有 `task_queue.last_stage` 列，且只在暂停时写）；不新增后端字段可零契约风险 |
| 「合集页右上角新建」（P0-4） | 改成列表顶部工具条「新建合集」 | 页面是原生 header（Stack 页保返回手势），在页面内做入口可直接单测，也避免操作 navigation 对象 |
| 「新建/改名/删除 + 上移下移」（P0-4） | 未做「排序模式」批量重排，只做单条上移/下移 | 与规划一致（规划本身排除拖拽），单条移动已能覆盖整理需求 |
| 走 `allowsEditing` 裁剪（P0-5） | 只对相机入口开启，相册多选/单选保持原图 | 多选与裁剪互斥；相册选图用户通常已选好构图 |
| 「出图候选…确认入库/**丢弃**」（P1） | 丢弃只做「整批丢弃」，**没有单张丢弃** | 后端只有 `POST /runs/{id}/cancel`（删批次+目录），没有单张丢弃接口；单张丢弃会让目录与记录不一致 |

### 11.5 唯一未做项：扫 Web 二维码填地址

现状：**设置页已能「复制当前地址 / 从剪贴板粘贴」**，替代手敲局域网 IP；
API Key 已支持，请求自动带 `X-API-Key`。

为什么没做扫码：`扫 Web 二维码填地址` 需要两端配合——Web 端要有一块「显示二维码」的界面，
而当前 Web 没有设置/关于页（二维码要有出码面才扫得到）。补齐需要：
1. 后端加一个只读接口返回本机局域网地址（`/api/system/mobile-connection`）；
2. Web 加一处出码 UI（可用已装的 Python `qrcode` 生成 PNG，无需前端依赖）；
3. 移动端加 `expo-camera` 扫码页（SDK 52 对应 ~16.1）。

三条都是新增改动，其中 2/3 跨端且要再引一个原生模块，故本轮不做；触发条件：Web 侧提供出码面。
