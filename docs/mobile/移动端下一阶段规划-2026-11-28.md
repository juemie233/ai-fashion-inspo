## 2. 本阶段目标（按用户选择）

1. **通勤顺手**：手机上能给素材打星、按评分筛 / 排，整理收藏夹不再必须回电脑；
2. **手机也能采集**：选抖音收藏夹或博主 → 发起下载 → 看进度 → 结果入库/回滚；
3. **手机也能出图**：选档位/参数/参考图 → 提交 → 轮询 → 候选入库（依赖 PC 或云端在线）；
4. **体验更完整**：平板/折叠屏双栏、任务可控（暂停/恢复）、版本更新可感知、完成可通知。

## 4. 逐项方案

### 4.0 前置：三项真机验收（第一批第一天）

**目标**：把「有代码没验证」的三项在真机上跑通，暴露的 bug 并入对应功能提交。

| 项 | 操作步骤 | 判定标准 |
| --- | --- | --- |
| 分享接收 | 系统相册选 1 张 → 分享 → 穿搭素材库；再选 2 张分享一次 | 单张弹「已入库」或「已在库中」；多张弹一条汇总（已入库 N / 已在库中 M / 失败 K） |

### 4.1 A：评分（1.5 人日）

**契约（后端已就绪，不改后端）**
- 写：`PATCH /api/inspirations/{id}` body `{rating: 0..5}`（0 = 取消评分）；
- 读：`GET /api/inspirations?rating_min=3&unrated=false&sort=rating`（列表已支持）；
- 排序：`sort=rating`（Web 已用，稳定分页由后端保证）；
- 批量：无专用批量接口 → 多选后逐条 PATCH（上限按多选上限，串行 + 进度提示；失败逐条回报）。

**交互方案**
| 位置 | 交互 |
| --- | --- |
| 素材库卡片 | **长按**已有「多选」；评分放在**卡片右下角小星条**？——不做（误触率高）。改为：长按 → 多选态顶栏加「打星」动作 → 弹 0–5 星选择，批量提交 |
| 素材详情 | 操作栏（收藏 / 编辑标签 / 原链接 / 更多）上方加一行五星，点星即提交（乐观更新 + 失败回滚），显示「未评分 / 3 星」 |
| 素材库筛选 | 筛选胶囊行后追加「≥3 星」「未评分」两个可横滑胶囊（复用 `Chip`，选中即带 `rating_min=3` / `unrated=true`） |
| 排序弹层 | `SORT_OPTIONS` 加「评分」（`sort=rating`），与 Web 一致 |
| 详情页元信息 | 「评分」一行（只读展示，点击跳到打星） |

**改动面**：[`services/api.ts`](../../mobile/services/api.ts)（`rateInspiration`、`TaskItem.rating` 已有字段）、[`app/(tabs)/index.tsx`](../../mobile/app/(tabs)/index.tsx)、[`app/(tabs)/search.tsx`](../../mobile/app/(tabs)/search.tsx)、[`app/detail/[id].tsx`](../../mobile/app/detail/[id].tsx)、[`constants/labels.ts`](../../mobile/constants/labels.ts)（排序/筛选文案）、`components/ui/StarRating.tsx`（新组件）。

**边界**
- 单用户场景，不做「多人评分 / 平均分」；
- 0 与「未评分」同义（后端 `rating=0` 即清空），UI 上「0 星」不显示为 0 而显示「未评分」；
- 评分**不参与** AI 质量审核与相似推荐（延续 Web 契约），手机端文案不要暗示它影响 AI。

**测试**：`services/api` 单测（PATCH body/错误回滚）、`StarRating` 组件（点击/禁用/大字体）、详情与列表渲染用例、筛选与排序参数拼装。

### 4.2 B：任务暂停/恢复（0.5 人日）

**契约（后端已就绪）**
- `GET /api/tasks/meta` → `pausable: string[]`（白名单：`tag_network_analyze` / `batch_analyze` / `multi_analyze` / `quality_check` / `f2_import` / `vector_backfill`），**动态读取，不硬编码**；
- `POST /api/tasks/{id}/pause`、`POST /api/tasks/{id}/resume`。

**交互**：任务行在 `进行中` 时多一个「暂停」次按钮（白名单类型才显示）；`已暂停` 时显示「继续」。二次确认不做（可逆操作），但要 Toast/haptics 反馈；自动刷新沿用现有 3 秒轮询，暂停后状态会自然刷新。

**改动面**：[`services/api.ts`](../../mobile/services/api.ts)（`pauseTask`/`resumeTask`/`fetchTaskMeta`）、[`components/TaskRow.tsx`](../../mobile/components/TaskRow.tsx)、[`app/tasks.tsx`](../../mobile/app/tasks.tsx)、[`app/task/[id].tsx`](../../mobile/app/task/[id].tsx)（详情页也要能暂停/继续）。

**测试**：白名单判断（不在列表的类型不显示按钮）、暂停/继续后状态刷新、失败提示。

### 4.3 C：应用内更新提示（1.0 人日）

**为什么要做**：自建 APK 没有应用商店，用户不主动看 GitHub/Gitee 就不知道有新版本。

**方案（推荐，零手动步骤）**
1. 后端新增 `GET /api/app/release`：读取**入库**的 `backend/app_release.json`（`{version, version_code, download_url, notes, released_at}`），文件不存在返回 404 而不是报错；
2. 后端新增 `GET /api/app/download`：把 `backend/storage/app_release/*.apk` 作为附件下载（`FileResponse`，只允许该目录下的文件，防路径穿越）。**APK 文件本身不入库**（`.gitignore`），由发版脚本复制进去；
3. 手机端：设置页「关于」区显示「检查更新」；启动时静默检查一次（节流 1 次/天），发现 `version_code > 本地` 弹「发现新版本 vX」→「去下载」用 `Linking.openURL(下载地址)`（复用系统浏览器下载安装），「暂不」记住本次版本号。

**改动面**：`backend/app/routers/app_release.py`（新，已登记位置）+ `main.py` 注册 + `backend/app_release.json`（新，入库）；手机端 [`services/api.ts`](../../mobile/services/api.ts)、[`app/(tabs)/settings.tsx`](../../mobile/app/(tabs)/settings.tsx)、`utils/appUpdate.ts`（新）。

**边界**：不自动安装（Android 需要用户点安装包）、不做后台静默下载；`download_url` 允许外部 URL（如 Gitee Releases），后端下载接口只是兜底。

**待你拍板**：APK 放哪 —— ① 后端 `storage/app_release/`（手机走局域网下载，零配置）还是 ② Gitee Releases（外网可下，但要手动上传）？默认按 ①，`download_url` 留外部 URL 覆盖能力。

### 4.4 E：f2 采集入口（3–4 人日，第二批）

**契约（后端全通，不改后端）**
| 用途 | 接口 |
| --- | --- |
| 收藏夹清单 | `GET /api/scraper/f2-collects` |
| 博主清单 | `GET /api/scraper/f2-authors` |
| 下载前预览 | `GET /api/scraper/f2-preview`（按作者/夹统计将下载多少） |
| 提交下载 | `POST /api/scraper/f2-import`（`mode` / `collect_ids` / `allow_all_collect` 等） |
| 进度 | `GET /api/scraper/f2-status` + `GET /api/tasks/{id}`（走任务中心） |
| 结果 | `GET /api/scraper/f2-tasks/{task_id}/results` |
| 回滚 | `POST /api/scraper/f2-tasks/{task_id}/rollback/preview` + `/rollback` |

**交互方案（三步）**
1. 采集页顶部加「抖音采集」卡（现只有「本地上传」）→ 进入 `app/scrape/f2.tsx`（新页面）；
2. 页内两段控件：**收藏夹**（多选列表：夹名 / 数量 / 最近收藏时间，全选/反选）与 **博主**（搜索 + 多选）；底部「预览」给「将下载 N 个作品 / 涉及 M 个夹」；
3. 确认后提交 → 跳任务详情（复用 `/task/[id]`）看进度；任务完成在结果页（`app/scrape/f2-result/[taskId].tsx`）展示「入库 N / 跳过 M / 失败 K」，可「回滚本次」（二次确认，说明只删本次入库）。

**关键风险**
- **Cookie 失效 / 风控**：刚才修的那个「读取收藏夹失败」就是典型——现在错误文案已包含 ModuleNotFoundError 这类内部错误，F2 采集入口要**把错误分类**：Cookie 失效 → 引导「去电脑跑一次 f2 登录」；风控 → 「稍后重试」；其它 → 展示原始原因（折叠）。
- **长任务**：f2 下载可能十几分钟，靠任务中心轮询即可；手机端**不做**前台服务常驻。
- **重复入库**：后端已有内容去重与结果回滚，手机端不要自己判重。

**改动面**：`app/scrape/f2.tsx`、`app/scrape/f2-result/[taskId].tsx`（新路由）、`app/(tabs)/capture.tsx`（入口卡）、`services/api.ts`（f2 一组接口 + 类型）、`utils/f2Errors.ts`（错误分类，纯函数可测）。

**测试**：错误分类纯函数、收藏夹/博主列表渲染与多选、提交参数拼装（`collect_ids[]` 数组序列化）、结果页三态、回滚二次确认。

### 4.5 F：手机端提交出图（3–4 人日，第二批）

**契约（后端已就绪）**
- `GET /api/generate/models`：档位、默认参数、预期耗时、是否云端（`size`/`watermark` 专属）；
- `POST /api/generate/runs`：`{kind: t2i|i2i, prompt, negative?, width, height, steps, cfg, seed, count(1–4), model_key?, reference_ids?, pose_id?, size?, watermark?, group_id?}`；
- 进度：`GET /api/generate/runs/{id}`；入库：`POST /api/generate/runs/{id}/confirm`（手机端已有）。

**交互方案**
1. 出图页（[`app/generate.tsx`](../../mobile/app/generate.tsx)）顶部加「+ 新建出图」→ `app/generate/new.tsx`（新页面）；
2. 表单：模型档位（底部弹层单选，显示「云端/本地 + 预期耗时」）→ 提示词（多行，带「从素材反推 prompt」按钮，复用 `POST /generate/prompt/preview`）→ 尺寸（1:1 / 3:4 / 4:3 / 9:16 预设）→ 张数（1–4）→ 高级（步数/CFG/seed，折叠）→ 参考图（**仅 i2i**：从素材库多选 1–3 张，缩略图 + 可删）；
3. 提交前校验：云端档位提示价格（后端 `models` 里若带价格就用，没有则不显示，**不伪造**）；PC 不可用时后端会失败 → 提交后立刻返回 task/run，进度页展示失败原因；
4. 提交后跳 `/generate/[id]`（已有批次详情）轮询；候选可入库（已实现）。

**边界**：手机端不做「多姿态一次多批」（`group_id` 逻辑复杂，留 Web）；不做参数预设管理；`i2i` 的 `pose_id`（姿势图库）不做，仅参考素材。

**改动面**：`app/generate/new.tsx`、`app/generate.tsx`、`services/api.ts`（`createGenerateRun`、`fetchGenerateModels`、`fetchPromptPreview`）、`components/ui/NumberStepper`？尽量复用现有 Chip/Button/BottomSheet。

**测试**：表单参数拼装与校验（越界值、必填）、模型弹层与云端字段、参考图选择（0/超过上限）、提交失败提示。

### 4.6 H：本地通知（1.0 人日，第二批，需重建 APK）

**要做的事**
- 依赖：`expo-notifications`（SDK 52 对应 ~0.29），`app.json` 加插件与 Android 通知权限；
- 场景：**前台/短后台**时任务完成或出图批次完成 → 本地通知（标题「任务完成：向量回填」/「出图完成：4 张候选」）；
- 触发：复用任务中心的 3 秒轮询，检测到本次会话内出现的新终态（`done`/`failed`）→ 发通知；App 被杀后不做（轮询已停）。

**边界 / 风险**：不做推送、不做后台任务（`expo-background-fetch` 在国产 ROM 上极不可靠）；通知权限被拒时降级为应用内 Snackbar；**只在 App 前台或刚退到后台的几分钟内可靠**，文档与 UI 文案都不要承诺「后台也会通知」。

**测试**：终态检测纯函数（避免重复通知，按 task id + status 去重）。

### 4.7 I：平板/宽屏双栏（1.5–2 人日，第二批）

**方案（推荐：详情页内嵌左栏，不动路由）**
- 断点沿用 `utils/layout.ts` 的 `LARGE_SCREEN_BREAKPOINT = 600`，≥900dp 视为宽屏双栏（`>= 900` 才上双栏，600–900 仍是 3 列单栏，避免平板竖屏过挤）；
- 宽屏时：[`app/detail/[id].tsx`](../../mobile/app/detail/[id].tsx) 左侧加一列「同来源/同筛选」缩略图（复用素材库 store 的 items，滚动同步选中项），右侧是详情；从列表点图 → 详情在右栏切换，不整页跳转；
- 素材库/搜索在宽屏维持 3–4 列网格（已实现），不改成双栏。

**备选（不推荐）**：改造路由为 master-detail（`expo-router` 的 slot 或自建），改动面大、易与现有返回栈冲突。

## 7. 风险与回退

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| f2 Cookie 失效 / 抖音风控 | E 无法取到清单或下载 | 错误分类引导（去电脑重新登录 / 稍后重试）；不做「换 IP 硬刷」 |

| 新原生模块导致旧 APK 崩页 | H（expo-notifications） | 按 `require` 懒加载 + 缺失提示「请更新 App」（沿用 `mediaActions` 的做法） |
| 评分排序分页不稳定 | A 列表跳动 | 后端已保证；手机端沿用 `sort=rating` + 现有分页合并逻辑 |
| 双栏与返回栈冲突 | I 奇怪跳转 | 采用「详情页内嵌左栏」方案（不动路由），窄屏完全走旧路径 |
