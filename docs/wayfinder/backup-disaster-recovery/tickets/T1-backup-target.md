# [TICKET · grilling · HITL] T1 备份目标位置与异盘策略

- **Map**：[MAP](../MAP.md)
- **类型**：grilling（需与用户 live 访谈，不能替用户回答）
- **状态**：✅ resolved
- **Blockers**：无
- **Blocks**：T2 备份范围与分层、T6 自动调度与保留、T7 备份校验

## Question

备份放到哪里？这是所有后续决策的地基——它决定分层策略、保留份数、校验方式和自动化可行性。

需要从用户处 grill 出的事实：

1. **目标盘**：当前项目在 `C:\Users\Administrator\Desktop\...`（系统盘）。是否有第二块本地盘（D:/E:）？容量与可用空间各多少？
2. **网盘/可移动介质**：是否使用 OneDrive / 坚果云 / 其他同步盘？同步目录的真实路径？是否有外接 USB 硬盘？
3. **可接受的"异地"程度**：只要异盘即可，还是要求至少一份在网盘（防火灾/盗窃）？
4. **历史保留期望**：希望保留多少份 / 多长时间的备份（影响所需容量）。
5. **`.env` 含密钥**：备份若进网盘，密钥会随网盘上云——是否接受？还是要把敏感配置从文件备份中排除/单独加密？

## 验收（resolution 记录什么）

一段明确结论，例如："主备份到 `D:/fashion-inspo-backups/`（异盘，X GB 可用），另每周复制一份到 `OneDrive/.../backups/`；保留近 7 份日备 + 4 份周备；`.env` 纳入备份但网盘目录需加密/私密。" 结论写进本 ticket 的 resolution comment，并追加到 MAP 的 Decisions so far。

## Resolution

- ✅ **主备份目标**：`E:\fashion-inspo-backups\`（独立物理盘——一块 512GB SSD，实测可用 431GB，非 C 盘分区），可写。约 1GB/份 × 保留 7 日 + 4 周 ≈ 10GB+，容量充裕。
- ✅ **暂不使用网盘**：不做云端第二副本。因此 `.env` 等含密钥配置可直接纳入本地 E 盘备份，无密钥上云风险，无需单独加密/排除。
- ⏳ **保留份数**：交给 T6 决定具体 rotation（初拟：日备 7 份 + 周备 4 份）。
- ⏳ **调度触发**：交给 T6（每日定时 + 后端启动稳定后自动补备，由 T2 决议）。

**风险记录（影响 scope，非 blocker）**：E 盘是同机器内置 SSD，可防 C 盘/系统盘损坏，但**不能**防整机被盗、火灾、勒索病毒。这层"异地"保护明确推迟——未来需要时，把备份目录设为网盘客户端的同步文件夹即可获得自动云端副本（届时需重新评估 `.env` 密钥加密问题）。已同步写入 MAP 的 out-of-scope 边界说明。
