# 素材库首页与批量操作

> **状态**：现行（2026-11-22 按代码核对）。真源：`web/src/views/HomeView.vue`（582 行）、
> `components/home/`、`components/inspiration/{MasonryGrid,BatchActionBar,TrashReasonModal}.vue`、
> `composables/{useBatchSelection,useInspirationFilters,useHomeActions}.ts`、`utils/browseQuery.ts`。
> 检索参数的后端语义见 [搜索与向量检索](搜索与向量检索.md)；删除语义见
> [素材生命周期与垃圾桶](素材生命周期与垃圾桶.md)。

## 1. 一句话

首页是**唯一的浏览入口**：瀑布流 + 筛选栏 + 分页，URL 承载筛选与页码（可分享/刷新不丢），
批量模式把「收藏 / 移垃圾桶 / 加标签 / 关联博主 / 批量改字段」收敛到一条操作栏。

## 2. 页面组成

| 组件 | 职责 |
|---|---|
| `MasonryGrid` | 瀑布流：按密度与视口宽算列数，**行优先分列**（第 i 个素材进 `i % 列数` 列），保证视觉顺序与「最新在前」的扫视一致 |
| `HomeFilterBar` | 筛选栏：关键词、标签、来源、评分、主色调（仅当库里有主色数据时才出现）等维度 |
| `HomeActiveFilters` | 当前生效筛选的可清除标签（点 × 取消单个条件） |
| `BatchActionBar` | 批量操作栏（进入批量模式后才出现） |
| `TrashReasonModal` | 删除原因选择（与素材库/审核页复用同一个原因枚举） |
| `CollectionPickerModal` | 加入合集的选择弹窗 |

`HomeView` 自身只做编排：状态来自 `useInspirationFilters`（筛选域）+ `stores/inspirations`（列表与总数），
动作来自 `useHomeActions`（单条）+ `useBatchSelection`（批量）。

## 3. URL 与本地偏好的分工

| 状态 | 落在哪 | 键 / 参数 |
|---|---|---|
| 页码 | URL query | `page`（**只有 >1 时才写进 URL**，首页保持干净） |
| 排序 | localStorage | `masonry-sort`（默认 `newest`，见 `DEFAULT_BROWSE_SORT`） |
| 每页数量 | localStorage | `masonry-page-size`（`storedBrowsePageSize()` 读取） |
| 网格密度 | localStorage | `masonry-density`（`compact` 紧凑 / `standard` 标准 / `comfortable` 宽松） |
| 定位跳转 | URL query | `focus=id1,id2`（只显示指定素材，用于从后台/审核页跳回来） |

**为什么详情页要复用同一套参数**：`buildBrowseParams()` 被 `HomeView` 与 `DetailView` 共用，
保证「详情页的上一张/下一张」与「列表进入时的筛选+排序」完全一致——各写一份就会变成
在列表里筛「已评分」、翻进详情后上一张却是未评分的。

`focus` 模式有个副作用要留意：素材库里若少了其中几张（已在垃圾桶 / 文件缺失），页面会提示
「素材库中仅找到 N 张，其余可能已在垃圾桶或文件缺失」，而不是静默少显示。

## 4. 单条动作（`useHomeActions`）

| 动作 | 行为 |
|---|---|
| 收藏 / 取消收藏 | 直接改 `is_favorite`，卡片立即反映 |
| 评分 | 写 `rating`，与随机评分页、详情页共用同一字段 |
| 删除 | 弹 `TrashReasonModal` → 软删除（进垃圾桶，可恢复） |
| 加入合集 | 弹 `CollectionPickerModal`（合集是两级结构，见 [收藏合集两级结构](收藏合集两级结构.md)） |
| 审核通过 | 质量审核的翻案动作（`manual` 来源） |
| 批量质检 | 对当前筛选结果批量跑质量预检 |

## 5. 批量模式（`useBatchSelection`）

进入方式：筛选栏/工具栏的「批量」按钮 → `enterBatchMode()`；退出 `exitBatchMode()` 清空选择。
内部状态就两个：`batchMode`（布尔）+ `selectedIds`（`Set<string>`，素材 ID 是 UUID 字符串）。

| 能力 | 说明 |
|---|---|
| `toggleSelect` / `toggleSelectAll` | 单选、按当前页全选 |
| `batchFavorite(true/false)` | 批量收藏/取消 |
| `batchTrash(reason?)` | 批量移入垃圾桶（软删） |
| `batchAddTags(names)` | 批量加标签 |
| `batchLinkBloggers(personIds)` | 批量关联穿搭博主 |
| `batchUpdate(fields)` | 批量改字段（`undefined` = 不修改该字段） |

`BatchActionBar` 的能力与上表对应，另有批量评分。
一个性能细节值得记住：**批量关联博主曾每次进入批量模式就串行翻页拉完 611 个博主**
（约 4 次请求，即使这次只想批量收藏），现在改成模块级缓存 + 选择器虚拟列表，同一会话内只拉一次。

## 6. 分页与总数

- `pageSize` 由 `storedBrowsePageSize()` 决定，改动即写回 localStorage；
- `totalPages = ceil(store.total / pageSize)`；
- 页面右上角显示「共 N 条」（`store.total`）；
- 换筛选条件 → 页码重置为 1 并滚回顶部（`scrollPageToTop()`）。

## 7. 常见坑

1. **刷新后筛选没了**：筛选条件目前主要来自组件内存状态，只有页码与 `focus` 在 URL 里；
   想「可分享的筛选视图」需要把条件写进 query（尚未实现，别假定它已经在）。
2. **批量选择后换页，选择丢失**：`selectedIds` 是页面级状态，翻页/换筛选不保留跨页选择。
3. **主色调筛选时有时无**：`HomeFilterBar` 用 `v-if="dominantColors.length > 0"` 控制——库里还没有
   主色数据时这个筛选项根本不渲染，不是 bug。
4. **详情页上一张/下一张与列表不一致**：先确认两个页面都走了 `buildBrowseParams`，
   有人手工拼过 query 就会出现这种漂移。
5. **密度改了但列数没变**：列数同时受「密度」与「视口宽度」影响（`masonryColumnCount`），
   窄窗口下切密度可能仍是同一列数。
