# 提示词版本与多提示词分析

> **状态**：现行（2026-11-22 按代码核对）。真源：`backend/app/services/model_prompt.py`（当前 prompt + 版本读写）、
> `routers/ai_settings.py`（`/prompt*` 端点）、`services/ai_dashboard_service.py`（哈希口径与可读标签）、
> `routers/ai_analysis.py:158-183`（多提示词组合）、`web/src/components/model/SettingsPanel.vue`、
> `backend/prompt_versions.json`（版本历史文件，已入库）。

## 1. 一句话

打标 prompt 有两个文件：**`prompt_configs.json` 存当前生效的**，**`prompt_versions.json` 存历史版本**；
版本号不是递增序号而是**内容哈希前 8 位**，所以「改了 prompt 再打标」和「旧标签是哪版产出的」能对上账。

## 2. 三个关键事实

| 事实 | 说明 |
|---|---|
| 版本是**手动保存**的 | 改 prompt 只是改当前生效值；点「保存版本」才会往历史里追加一条。**没保存就没有历史** |
| 版本标识是**内容哈希** | `sha256(prompt)[:8]`（`ai_dashboard_service._prompt_hash`），写进 `ai_analysis_log.prompt_version` |
| 版本按**模型**分开 | `prompt_versions.json` 顶层键是模型名（如 `qwen3-vl:8b-instruct`），换模型 = 换一套版本历史 |

版本条目的形状：`{"prompt": 全文, "saved_at": ISO 时间, "length": 字数}`。

## 3. 端点

| 端点 | 作用 | 备注 |
|---|---|---|
| `GET /api/ai/prompt` | 取当前生效 prompt（含字数） | 取的是 `prompt_configs.json` 里该模型的值，没有就用全局默认 |
| `PUT /api/ai/prompt` | 改当前生效 prompt | **不写版本历史**，改完记得点保存版本 |
| `GET /api/ai/prompt/versions` | 版本列表（带 `saved_at` / `length`） | 前端版本列表就是它 |
| `POST /api/ai/prompt/save-version` | 把当前 prompt 追加进历史 | 由设置页「保存版本」按钮调用 |
| `POST /api/ai/prompt/rollback` | 回滚到某个历史版本 | 会**覆盖当前生效 prompt**，不是新建一条 |
| `GET /api/ai/person-bio-prompt` | 人物简介 prompt（与打标分开） | 博主简介生成走另一份文本 |

## 4. 哈希如何把「版本」和「结果」串起来

```
保存版本 ──→ prompt_versions.json[{prompt, saved_at}]
                     │
改当前 prompt → 打标时取 prompt → sha256[:8] ──→ ai_analysis_log.prompt_version
                     │
看板聚合：按 prompt_version 分组 → 用 prompt_versions.json 反查可读标签
```

反查规则（`ai_dashboard_service`）：

- 命中历史版本 → 显示 `版本 #N（模型名）`；
- 命中当前生效 prompt → 显示 `当前提示词（模型名）`；
- 都没命中（历史记录来自更早、已不在版本文件里的 prompt）→ 回退显示裸哈希，**不猜**。

## 5. 多提示词 / 多模型组合分析

`GET /api/ai/analysis` 支持一次跑多个组合，组合项来自：

1. 当前默认提示词（永远有，`prompt_id = 0`）；
2. 历史版本（`prompt_id >= 1`，标签带保存时间，如 `版本 #2（2026-09-05 22:23）`）。

搭配多模型选择，就是 `模型数 × 提示词数` 次分析；结果各存一条 `ai_analysis_log`，
**素材的正式标签只保留一份**（组合分析不自动叠加标签，避免同一素材被打三套矛盾标签）。
前端入口：`MultiModelAnalyzeCard`（发起组合）、`AnalysisHistoryCard`（按版本筛选/对比）、
`QualityPanel`（按版本看质量）。

## 6. 常见坑

1. **改了 prompt，历史记录还是旧版本**：正常——历史按当时的内容哈希记账；想看新版本效果就再打一批。
2. **「保存版本」点完没变化**：版本号是内容哈希，**内容没改就保存出同一条**（不会产生新版本）。
3. **回滚把改了一半的 prompt 冲掉了**：回滚是覆盖当前值，必要时先复制一份到本地再回滚。
4. **换模型后看不到之前的版本**：版本按模型存档，去对应模型下看。
5. **看板里出现裸哈希**：那条记录产生的 prompt 已不在 `prompt_versions.json` 里（文件被清理或换机未带过去），
   这属于正常降级，不是数据损坏。
6. **多人同时改 prompt**：写入有 `_write_lock`（进程内锁），但**只保证单进程**；API 与 worker 同机单进程场景够用。
