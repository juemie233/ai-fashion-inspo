# 收藏功能代码审查（2026-11-12）

> 状态：审查报告（未改代码）
> 范围：`inspirations.is_favorite`（素材卡片/详情页的心形收藏）、批量收藏、收藏筛选、移动端收藏、「系统入库手动收藏」智能合集；不含 `generation_runs.favorite`（出图批次收藏，属于另一套数据）
> 方法：对后端 service/router/query、Web store/组件/composable、移动端 store/页面逐文件走查；对照现有测试与文档。未运行写操作，未改业务代码。
> 结论：**后端收藏写入本身是正确的**（单条/批量、软删除过滤、去重、`updated_at` 都没问题）；用户感知到的「收藏有问题」主要集中在三处：**收藏筛选下取消收藏不移除条目、系统收藏合集可被编辑/固化/删除、跨页面收藏状态不同步**。

## 1. 结论摘要

### 1.1 做得对的部分

- 单条收藏走 `PATCH /api/inspirations/{id}`，`is_favorite` 与评分、质量状态互不干扰（`backend/tests/test_inspirations.py` 有独立更新用例）。
- 批量收藏 `POST /api/inspirations/batch-favorite` 会去重 ID、只更新未删除素材、返回真实 `updated` 行数（`inspiration_update.py:59-78`）。
- 收藏作为「人工投入」参与重复保留评分 +50，避免自动去重删掉用户收藏的副本（`deduplicate.py`）。
- 垃圾桶软删除保留 `is_favorite`，恢复后不丢；F2 回滚也会保护「打标/收藏/评分」的素材。
- Web 卡片和详情、移动端卡片和详情都有收藏按钮；移动端触控区 44pt；卡片按钮 `@click.stop` 不打开详情。
- 系统合集「系统入库手动收藏」用 `{"is_favorite": true}` 动态求值，设计上能做到「收藏按钮即合集成员」。

### 1.2 主要问题

## 2. 问题详解

### P1-1 「仅收藏」筛选下取消收藏，列表不收敛

**复现路径（Web）**：

1. 素材库选择状态「仅收藏」；
2. 列表只剩 `is_favorite=true` 的素材；
3. 点卡片心形取消收藏；
4. 心形变空，但**卡片仍留在列表里**，顶部总数不变；
5. 继续滚动/翻页时，后端第 2 页已经按新的收藏集合计算 offset，可能出现重复或漏图。

**代码链**：

```text
useInspirationFilters.statusFilter = 'favorites'
  → buildBrowseParams: is_favorite: true   (utils/browseQuery.ts:59)
  → store.load({is_favorite:true})
  → InspirationCard @toggleFavorite
  → useHomeActions.handleToggleFavorite
  → store.toggleFavorite(id)
      newState = !item.is_favorite
      await api
      item.is_favorite = newState          ← 只改字段
      （不删除 item、不更新 total、不重新 load）
```

`useHomeActions.ts:242-250` 的批量取消收藏也一样：只把选中项 `is_favorite` 改成 false，然后 `exitBatchMode()`，列表和 `total` 都没变。

**移动端**：

`mobile/hooks/useInspirations.ts:173-182` 的 `toggleFavorite` 只 map `items`；`(tabs)/index.tsx` 的收藏按钮直接调用它。筛选 `filter.is_favorite` 时，取消收藏后条目仍在。

**影响**：用户会直接认为「收藏按钮没用/取消不掉」，而且 `loadMore` 的分页分母与当前列表不一致。

**建议修复**：

- `store.toggleFavorite` 感知当前 `_lastParams.is_favorite`：当筛选是 `true` 且目标为 `false` 时，从 `items` 移除该条并 `total--`；或直接 `load(currentPage)`。
- `useHomeActions.handleBatchFavorite`：如果当前 `statusFilter === 'favorites'` 且 `isFavorite === false`，刷新当前页（或移除选中项并修正 total）。
- 移动端 store 同样处理：`filter.is_favorite && !desiredState` 时移除 + `total--`；批量取消收藏后重拉或移除。
- 补用例：收藏筛选下取消收藏→列表消失、总数减一；批量取消→全部消失；翻页不重复。

### P1-2 「系统入库手动收藏」可以被改坏

设计文档明确：

```text
一级①：系统入库手动收藏  ← 智能合集 {is_favorite: true}，随收藏按钮自动同步
```

`backend/app/models/collection.py:39-40`：

```python
MANUAL_ROOT_COLLECTION_NAME = "系统入库手动收藏"
MANUAL_ROOT_QUERY = {"is_favorite": True}
```

但当前：

- `CollectionContentHeader.vue:44-49` 对所有 `kind === 'smart'` 显示「编辑条件」「转手动」；
- 同一组件 `:65-67` 对所有合集显示「删除合集」；
- `useCollectionMutations.ts:91-156` 没有系统合集判断，直接调 `deleteCollection` / `solidifyCollection`；
- 后端 `update_collection`（`collection_service.py:571-621`）允许改 `query_json`；
- `solidify_collection`（`:833-859`）允许任意智能合集转手动；
- `delete_collection`（`:624-638`）允许删除；
- `ensure_root_collections`（`:431-455`）只保证「名字存在」，如果用户把 query 改成 `{}` 或转成手动，启动时也不会修复。

**后果**：

- 点「编辑条件」把 `is_favorite` 关掉 → 「系统入库手动收藏」不再跟随收藏；
- 点「转手动」→ 当前收藏被固化成静态成员，之后新收藏不会进来；
- 点「删除」→ 当前会话里一级收藏直接消失，要等下次启动才由 `ensure_root_collections` 重建；
- 通过 API 改名 → 启动时按原名再建一个，出现重复一级节点。

**建议修复**：

1. 后端先加保护（不能只靠前端隐藏按钮）：
   - `update_collection`：如果目标是 `MANUAL_ROOT_COLLECTION_NAME`，禁止改 `query_json` / 改名；
   - `solidify_collection`：目标是系统收藏根 → 400；
   - `delete_collection`：目标是系统收藏根 → 400（或只允许重建，不允许删）；
   - `ensure_root_collections`：不仅查名字，还要校验 `query_json == {"is_favorite": true}`；不一致时修复并记审计/日志。
2. 前端 `CollectionContentHeader`：系统收藏根不显示「编辑条件/转手动/删除」，或显示为只读说明。
3. 补测试：对根合集调用 update/solidify/delete 均返回 400；`ensure` 在 query 被改坏后能修复。

### P1-3 跨页面收藏状态不同步

#### Web 详情页

`DetailView.vue:189-198`：

```ts
const newState = !detail.value.is_favorite
await toggleFavorite(detail.value.id, newState)   // 直接 API
detail.value.is_favorite = newState
```

`stores/inspirations.ts:149-166` 才是「同步列表项与 currentDetail」的实现。详情页没有调用它，所以：

- 从素材库进详情取消收藏 → store 里的列表项仍是旧值；
- 如果 HomeView 没有重新加载（例如某些路由缓存/新标签页场景），返回后心形还是实的。

**建议**：详情页统一走 `inspirationsStore.toggleFavorite(id)`，或至少在 API 成功后更新 store 中同 ID 的项。

#### 移动端搜索/合集 → 详情

`detail/[id].tsx:143-153` 调全局 store `toggleFavorite`，它只更新 `state.items`（素材库列表）。但：

- 搜索页结果在本地 `results`（`search.tsx:308-317`），不在 store；
- 合集详情在本地 `items`（`collection/[id].tsx` 的 fetch），不在 store；
- 从这些页进详情改收藏，返回后来源列表不会更新。

**建议**：统一由 store/事件总线广播收藏变更，或在 `useFocusEffect` 回到页面时刷新；至少详情页把变更同步到来源页可感知的全局状态。

### P2-1 批量收藏忽略真实更新数

Web：

```ts
// useHomeActions.ts:242-250
const updated = await batchFavorite(isFavorite)
if (updated > 0) {
  for (const item of store.items) {
    if (selectedIds.value.has(item.id)) item.is_favorite = isFavorite
  }
  exitBatchMode()
}
```

如果后端因为「部分 ID 已删除/不存在」只更新了 2/5，前端仍把 5 个都改成目标值。移动端 `batchFavorite` 更直接：完全不看返回值，把所有传入 ID 都改掉。

**建议**：用返回的 `updated` 与选中数对比；不一致时重新拉列表，避免 UI 与后端分叉。

### P2-2 快速连点/双击

收藏按钮没有 pending 态。`newState = !item.is_favorite` 在 await 前计算；用户快速点两次：

- 第一次：`false → true`，请求在途；
- 第二次：仍读到 `false`，又发一次 `true`；
- 结果只收藏了一次，但用户以为「收藏又取消」。

详情/卡片/移动端都存在。建议按 ID 维护 `pendingFavoriteIds`，请求中禁用按钮，或使用乐观更新 + 请求去重。

### P2-3 `is_favorite` 没有索引

`Inspiration.is_favorite` 在模型里没有 `index=True`；素材库「仅收藏」筛选会 `WHERE is_favorite=1 AND deleted_at IS NULL`。当前 3 万级数据可接受，但收藏是高频入口，建议加部分索引：

```sql
CREATE INDEX ix_inspirations_favorite_active
ON inspirations (is_favorite, deleted_at)
WHERE is_favorite = 1;
```

（或用复合 `(is_favorite, created_at)`；先实测查询计划。）

### P2-4 有些视图看不到收藏按钮

- 博主详情「全部」网格：`PersonItemsSection.vue:312-322` 传 `show-actions=false`；
- 合集详情：`CollectionsView.vue:319-327` 传 `show-actions=false`。

`InspirationCard` 的悬浮层被整体隐藏，收藏按钮也一起没了。用户如果期望「在博主详情/合集里直接收藏」，会认为功能缺失。建议把 `show-actions` 拆成 `showFavorite` / `showDelete` 等独立开关，或在详情页提供收藏入口。

### P2-5 搜索页没有收藏筛选

素材库有「仅收藏」，搜索结果没有；相同的素材在两处筛选能力不一致。若产品希望搜索里也能只看收藏，需要在 `SearchFilterPanel` / `useSearch` 增加 `is_favorite` 参数。

### P2-6 收藏垃圾桶素材

`PATCH /api/inspirations/{id}` 不检查 `NOT_DELETED`，垃圾桶里的素材仍可被 API 收藏；而「系统入库手动收藏」查询排除垃圾桶，所以收藏后不会出现在合集里，恢复后才出现。UI 详情页对垃圾桶素材仍显示收藏按钮。这不是数据损坏，但语义不清晰；建议要么禁止（400），要么在 UI 上说明「恢复后才进入收藏合集」。

## 5. 需要产品确认的点

1. **「仅收藏」筛选下取消收藏，条目应该立即消失，还是保留到下次刷新？** 推荐立即消失（符合筛选语义）。
2. **「系统入库手动收藏」是否允许用户编辑条件/转手动/删除？** 推荐全部禁止；如果确实要允许，必须同时去掉「自动同步」承诺，并改文档/UI 文案。
3. **博主详情/合集详情要不要直接给收藏入口？** 推荐至少给「收藏」一个独立开关，不要和删除/审核共用 `show-actions`。
4. **搜索页是否增加「仅收藏」筛选？** 推荐加，保持和素材库一致。
5. **「我的喜欢」f2 导入是否应自动标记 `is_favorite`？** 当前不标记（它属于「抖音入库自动收藏」合集，不是手动收藏）；如果产品希望导入即收藏，需要明确。
6. **垃圾桶素材能否收藏？** 推荐禁止或在 UI 注明「恢复后才进入收藏合集」。

## 7. 总体评价

后端写入语义、软删除保留、去重保护都做得不错；问题主要是**前端列表状态没有跟随筛选条件收敛**，以及**系统收藏合集缺少「不可编辑」约束**。这两类问题都会让用户产生「收藏了但没生效 / 取消了还在」的直觉，优先级应排在收藏功能的新增能力之前。

建议先修 P1-1、P1-2、P1-3，再补测试；P2 的索引/入口/搜索筛选可以随后做。
