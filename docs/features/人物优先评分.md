# 人物优先评分（`/person-rating`）

> **状态**：现行（2026-11-18 实施）
> **一句话**：像首页随机评分一样逐张打星，但**按人物排队**：哪个博主的图片素材「已评占比」最低，就先评他的未评分图片；当前博主的未评分图片评完，自动切下一位。

## 1. 目的

素材库的评分入口是分散的（首页随机评分无目标地刷、详情页单张评、素材库网格顺手评）。
当目标是「给人物页的博主们补评分」时，需要有导向的队列：**优先补最缺评分的博主**，
让「博主列表按作品均分排序」尽快具备足够样本（门槛 `MIN_RATING_SAMPLE = 5`）。

本功能只做**手动逐张评分**（评分仍写 `inspirations.rating`），不批量写分。

## 2. 队列口径（`GET /api/bloggers/rating-priority`）

`GET /api/bloggers/rating-priority?limit=1000`（`limit` 1~2000，默认 1000）

```json
{
  "items": [
    {
      "blogger_id": 12,
      "name": "博主昵称",
      "platform": "xiaohongshu",
      "avatar_path": "avatars/avatar_12.jpg",
      "image_count": 42,
      "rated_count": 3,
      "unrated_count": 39,
      "rating_average": 4.33,
      "coverage": 0.0714
    }
  ],
  "total": 137
}
```

| 字段 | 说明 |
| --- | --- |
| `blogger_id` / `name` / `platform` / `avatar_path` | 博主基础信息（头像用于页面展示，可为空） |
| `image_count` | 图片素材数（`media_type=image` 且未删除） |
| `rated_count` / `unrated_count` | 已评（`rating>0`）/ 未评（`rating` 为空或 0）图片数 |
| `rating_average` | 已评图片均分（2 位小数）；没有已评时 `null` |
| `coverage` | 已评占比 `rated_count / image_count`（4 位小数，0~1） |
| `total` | 符合条件（还有未评分图片）的博主总数，**不受 `limit` 影响** |

**纳入**：所有还有未评分图片素材的穿搭博主（不设素材数门槛）。
**排序（全部升序）**：`coverage` → `rated_count` → `image_count` → `blogger_id`。
即：已评占比最低的先评；同占比时已评数少的先；再同则素材少的先（小博主先评完，尽快清空队列）；最后以 id 稳定排序。

只统计图片：视频素材、垃圾桶素材（`deleted_at` 非空）都不进入任何计数。

## 3. 逐张抽未评分图片（`GET /api/bloggers/{id}/random`）

在现有「随机浏览」接口上新增可选参数 `unrated: bool = false`（与其它筛选可组合）：

```
GET /api/bloggers/12/random?unrated=true&media_type=image&size=1
→ {"person": {...}, "items": [{...}], "total": 39}
```

- `unrated=true`：只抽 `rating` 为空或 0 的素材；
- 评分页固定同时传 `media_type=image`（与首页随机评分一致，只评图片）；
- `total` 是**满足筛选条件**的素材总数（页面据此显示「当前博主还剩 N 张」）；
- 响应结构不变（`{person, items, total}`）；博主不存在仍返回 404。

## 4. 前端交互（页面 `/person-rating`）

1. 进入页面加载队列（`limit=1000`，覆盖当前全部有未评分图片的博主），取队首博主；
2. 用 `random?unrated=true&media_type=image&size=1` 抽一张未评分图片，展示大图 + 星级；
3. 点星级（1~5）或键盘 `1`~`5` 评分后**自动换下一张**；清除评分（0 星）不自动跳（避免误清后翻页）；
4. 空格/`→` 换下一张不评分，`Esc` 返回；删除走既有垃圾桶原因弹窗（软删除）；
5. 当前博主的未评分图片评完（`total` 归零）→ 自动切下一位博主，直到队列为空显示空态；
6. 队列数据与本地计数同步更新（已评/未评、覆盖率）；重新进入页面会重新拉队列——已被别人/其它入口评过的会自然前移或移出队列。

页面入口：人物管理页「穿搭博主」tab 的工具栏「优先评分」按钮；与首页随机评分（无目标地刷）互补，互不改变对方行为。

## 5. 边界与已知取舍

- **只统计图片**：视频不参与评分页（评分页看原图，视频无法用同一交互打星）；
- **占比会变化**：`coverage` 是查询时刻的快照；评分/删除/新入库都会改变队列，页面加载时以当时结果为准；
- `limit` 只限制单次返回的博主数量，方便前端一次拿完常见规模（当前博主量级 < 500）；队列更长时前端可按需再请求（后续若需要可分页扩展）；
- 已评口径与「评分功能方案」一致：`rating > 0` 才算已评（0 = 未评分）；均分只算已评图片；
- 该接口是**只读**，不写库、不产生任务；评分本身仍走既有 `PATCH /api/inspirations/{id}` 类接口；
- 前端页面由并行任务实现（`web/src/views/PersonRatingView.vue`、`usePriorityRating.ts`），本文只描述后端契约与页面行为约定。
