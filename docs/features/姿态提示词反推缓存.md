# 姿态提示词反推缓存（`pose_prompts` 表 + 全量回填脚本）

> **状态**：现行（2026-11-01 首次全量回填完成）。**用途**：把图库全部 1,439 条姿态线稿（含 275 条双人）用 thinking 模式反推出的图生图提示词、thinking 原文与调用成本存进本地库，供后续生成/分析直接查询，避免重复调用接口。
> 数据来源：`ai-pose-gallery-zh` 中文图库；脚本：`scripts/data/backfill_pose_prompts.py`；表：`pose_prompts`（迁移 `s8t9u0v1w2x3`）。

## 1. 表结构（`pose_prompts`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增 |
| `pose_id` | VARCHAR(64) UNIQUE | 图库姿态 ID（如 `full_sexy_P037_diag`、`pair60_P026_front`） |
| `name` / `angle` / `system` / `category` | 字符串 | 反推时的姿态元数据快照（图库目录后续变化也能对上） |
| `prompt` | TEXT | 反推出的图生图提示词正文（80~150 字） |
| `thinking` | TEXT NULL | thinking 原文（少数请求无 thinking 块时为空） |
| `model` | VARCHAR(64) | 固定 `deepseek-flash[1m]`（Anthropic 兼容接口） |
| `thinking_enabled` | BOOLEAN | 本表全为 1（本次全量用 thinking 开启） |
| `input_tokens` / `output_tokens` | INTEGER | 单次调用 token（用于成本核算） |
| `elapsed_s` | FLOAT | 单次调用耗时（秒） |
| `image_bytes` | INTEGER | 本次送图的线稿字节数 |
| `created_at` / `updated_at` | DATETIME | UTC（naive，按项目时间约定） |

索引：`ix_pose_prompts_pose_id`（唯一）。

> 本表是**缓存/分析表**，不参与线上业务读写；没有对应 API 路由。需要时直接 SQL 查询，或在后续任务中按 `pose_id` 读取。

## 1.1 已接入图生图

- 后端 `generation_service.create_run`：`kind=i2i` + `pose_id` 时，读取本表 `prompt` 并拼在用户描述前（缺失时回退旧模板），生成用的是数据库里的提示词；
- API：`GET /api/pose-gallery/{pose_id}/prompt` 返回 `{pose_id, prompt}`；
- 前端：选姿势/一键出图时自动拉取并填入描述框（保留用户已写内容），用户仍可手改；
- 相关说明见 [姿势图库换姿势（路径一）实现说明](../pose/姿势图库换姿势（路径一）实现说明.md)。

## 2. 全量回填脚本

```bash
# 前置：迁移建表（只跑一次）
cd backend && python -m alembic upgrade head

# 设置接口 key（不要写进文件）
export DEEPSEEK_API_KEY=sk-...

# 预览待处理（不调用接口）
python scripts/data/backfill_pose_prompts.py --dry-run

# 全量（默认跳过已有记录，可断点续跑）
python scripts/data/backfill_pose_prompts.py --workers 4

# 强制重刷 / 小批量
python scripts/data/backfill_pose_prompts.py --force --workers 4
python scripts/data/backfill_pose_prompts.py --limit 3 --workers 2
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--workers` | 4 | 并发请求数（含图片下载） |
| `--limit` | 0（全部） | 本次最多处理多少条 |
| `--force` | 关 | 已有 `pose_id` 也重刷；默认跳过 |
| `--dry-run` | 关 | 只打印待处理列表 |
| `--budget-tokens` | 2048 | thinking 预算 |
| `--max-tokens` | 4096 | 单条最大输出 |
| `--timeout` | 180s | 单次 HTTP 超时 |
| `--db` | app 配置 | 可指定其他 SQLite 文件 |

实现要点：

- 接口：`https://api.deepseek.com/anthropic/v1/messages`、模型 `deepseek-flash[1m]`、`thinking: enabled`；
- 逐条：下载/复用姿态线稿缓存 → base64 送图 → 解析 `thinking` / 文本 / `usage` → `INSERT ... ON CONFLICT(pose_id) DO UPDATE`；
- 失败不中断全量：单条最多重试 3 次（429/5xx/超时），仍失败记录后继续；结束时打印失败列表，重跑即续；
- 断点续跑：默认按已有 `pose_id` 跳过，插入/更新各一条即 commit（WAL + `busy_timeout`）。

## 4. 常用查询

```sql
-- 某条姿态
select pose_id, name, prompt from pose_prompts where pose_id = 'full_sexy_P037_diag';

-- 按体系抽样
select pose_id, name, prompt from pose_prompts where system like '%双人%' order by id limit 5;

-- 平均提示词长度 / token 成本
select system, count(*) n, round(avg(length(prompt)),1) avg_chars,
       sum(output_tokens) out_tokens
from pose_prompts group by system;
```

## 5. 边界与注意事项

- 反推只针对**姿态线稿**，与具体素材无关；提示词描述姿势（朝向/重心/四肢/手/头/镜头/景别），不含服装/场景；
- 提示词质量与 thinking 提示词实验结论一致：thinking 不是必须，但本表按用户要求统一用 thinking 生成；
- 图库图片缓存位于 `G:/fashion-inspo-storage/pose_gallery/images/<pose_id>.png`（按需下载，不随仓库分发）；
- 表不暴露 API；若后续要在出图页展示，可在生成参数选择姿势时按 `pose_id` 读取并预填提示词；
- 重刷全部用 `--force`；只补缺失直接重跑（默认跳过已有）。
