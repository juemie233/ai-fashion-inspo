# 人物组：跨平台账号绑定

> **状态**：现行（2026-11-15 按代码校对）。真源：`backend/app/models/person.py`（`PersonGroup` / `Blogger.person_group_id`）、
> `services/person/person_groups.py`、`routers/bloggers.py` 的 `/groups/*` 端点、`web/src/components/person/`。

## 1. 一句话

同一现实人物在抖音和小红书各有一个账号时，把两条**博主记录绑定成一个人物组**：
列表折叠成一条（显示主账号）、带多平台徽标，展开可见组内各账号及其素材。
**账号记录一条都不合并、一个字段都不丢**——这是方案 B（账号关联），不是"合并成一条主记录"。

## 2. 为什么不做"账号合并"

账号合并看起来更"干净"，但要面对：两个平台的字段集不同（小红书号 vs `sec_user_id`、IP 属地、主页 URL），
合并必然丢一半；历史素材的归属会指向一个"复合 id"；解绑等于数据回滚，做不到。

所以选了**关联**：`bloggers.person_group_id` 为空 = 独立账号；非空 = 与组内其它账号声明为同一人。
组内每个账号仍可正常采集、被搜到、绑定素材，行为与未分组时完全一致。

**只有穿搭博主参与分组，职业模特（`models`）不分组。**

## 3. 数据模型

| 表 / 字段 | 作用 |
| --- | --- |
| `person_groups.id` | 组 ID |
| `person_groups.name` | 组名，初始取主账号名，可改 |
| `person_groups.primary_blogger_id` | **可选**：手动指定的主账号（`ON DELETE SET NULL`） |
| `bloggers.person_group_id` | 归属组；`NULL` = 独立账号。组删除时账号回退独立 |

## 4. 主账号怎么定（列表折叠展示位）

1. 若组上设了 `primary_blogger_id` → 用它；
2. 否则**自动取组内素材数最多者**（素材数变化时会自动换人）；
3. 手动设过之后就不再随素材数漂移，直到手动改回或解绑。

组名为空或主账号被删时，回落自动规则；组内一个账号都没有的异常态会报错
（`人物组内没有博主，无法确定主账号`），不会静默给空名。

## 5. 四个端点

| 端点 | 语义 | 关键约束 |
| --- | --- | --- |
| `POST /api/bloggers/groups/link` | 两种模式：`{blogger_id, target_blogger_id}` 两账号**新建组**；`{blogger_id, group_id}` **并入已有组** | 两个参数**必须且只能给一个**；不能绑自己；不能重复绑；两账号已同组会报冲突 |
| `POST /api/bloggers/groups/unlink` | 把账号移出组，变回独立账号 | **组里只剩 1 个账号时自动删组**；不在组内会报冲突 |
| `POST /api/bloggers/groups/{id}/set-primary` | 手动指定主账号 | 目标博主必须在该组内 |
| `GET /api/bloggers/groups/{id}` | 组详情（成员 + 主账号） | — |

绑定/解绑/改主账号都写审计（`audit_logs`，含成员 id 列表与是否删组），出问题可追溯。

## 6. 冲突与校验

| 情况 | 结果 |
| --- | --- |
| `{blogger_id, target_blogger_id}` 与 `group_id` 同时给 / 都不给 | 409 `必须且只能提供 target_blogger_id 或 group_id 之一` |
| `blogger_id == target_blogger_id` | 409 `不能把博主绑定到自身` |
| 该博主已在目标组内 | 409 `该博主已在目标组内` |
| 两个账号已在同一组 | 409 `两个博主已在同一组` |
| 解绑一个不在组内的账号 | 409 `该博主不在任何人物组内` |
| 目标博主 / 组不存在 | 404 |

## 7. 对其它功能的影响

| 场景 | 行为 |
| --- | --- |
| 素材归属 | **仍按账号**（`inspiration_bloggers` 不变），组只是展示层的聚合 |
| 列表 | 同组折叠为一条（主账号 + 多平台徽标），可展开看组内各账号 |
| 素材数 / 评分均分 | 组内是否有"按组合并计算"的口径，见 [评分功能方案与博主详情应用](评分功能方案与博主详情应用.md)（评分对人物组按账号合并计算） |
| 采集 | 完全不受影响：按平台 + 账号采集，组不参与 |
| 人脸注册 | 按账号注册特征；同组不会自动共享人脸特征（否则等于跨平台合并身份） |
| 删除账号 | 需先无关联素材；删主账号会把 `primary_blogger_id` 置空并回落自动规则 |

## 8. 前端入口

- 博主列表：同组折叠 + 平台徽标 + 「展开」看组内账号；
- 博主详情：绑定/解绑/设主账号；
- 同名建议（`PersonDuplicateModal`）：归一化昵称相同的记录聚成一组，**只给建议不自动合并**
  （同名未必是同一人）；用户点「合并为同一人」时才调 `groups/link`，或选择「删掉空壳」。

## 9. 常见坑

1. **以为绑了组，素材就并到一个人名下了**：不会。素材仍属于各自账号；要汇总看的是组的展示聚合口径。
2. **解绑后组"消失"了**：组内只剩 1 个账号时按设计自动删组，账号本身还在。
3. **主账号自动变成别人**：没手动设过 `primary_blogger_id` 时会按素材数自动选；想固定就点「设为主账号」。
4. **想给模特也分组**：当前不支持（`models` 不参与），需要先改模型与服务层，不是前端开关。
5. **绑定后又想撤销**：用 `unlink`，账号回退独立，历史素材归属不受影响。
