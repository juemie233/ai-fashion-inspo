> **上游**：[收藏增强 P0：收藏时间与收藏中心](收藏增强-P0-收藏时间与收藏中心.md)
> **范围**：后端 P1 三项（用户确认仅做这三项）：①合集批量移动/复制/合并；②收藏智能视图；

## 1. 合集批量移动 / 复制 / 合并

### 1.1 移动 / 复制

`POST /api/collections/{source_id}/inspirations/transfer`

```json
{ "ids": ["uuid1", "uuid2"], "target_ids": [3, 5], "mode": "move" }
```

| 参数 | 约束 | 说明 |
| --- | --- | --- |
| `ids` | 1~500 | 要操作的素材 ID，**必须全部属于源合集**（move/copy 一致，避免误操作） |
| `target_ids` | 1~20 | 目标合集；请求内去重，可多个 |
| `mode` | `move` / `copy` | move 从源合集移除；copy 源合集不动 |

规则：

- 源与所有目标都必须是**普通手动合集**：手动（`query_json IS NULL`）、非自动维护
  （`auto_source IS NULL`，抖音收藏夹由 f2 维护）、非系统收藏根、非分类节点（无子收藏夹）；
- 目标不能包含源合集本身；目标已存在该素材则跳过，其余按目标当前最大 position
  **追加到末尾**；
- **整单事务**：任何校验失败都不写库（源/目标保持原状）。

返回（`added`/`skipped` 为跨目标合计；同一素材复制到两个目标会各计一次）：

```json
{
  "source_id": 7,
  "mode": "move",
  "target_ids": [3, 5],
  "added": 3,
  "skipped": 1,
  "removed_from_source": 2
}
```

### 1.2 合并（合并后删除源）

`POST /api/collections/{target_id}/merge`

```json
{ "source_ids": [7, 8] }
```

规则：

- 目标与所有源都必须是普通手动合集（同上：手动 / 非自动维护 / 非系统收藏根 / 非分类节点）；
- 源不能等于目标；`source_ids` 请求内去重；
- 源成员按源内 `position, added_at` 顺序 append 到目标末尾；目标已有跳过；
- **成功后删除源合集（含成员关系），目标保留**；整单事务，任何源非法/不存在都不产生部分写入。

返回：

```json
{
  "target_id": 3,
  "merged_collections": 2,
  "added": 4,
  "skipped": 2,
  "deleted_sources": [7, 8]
}
```

- `merged_collections`：成功合并的源合集**数量**；
- `deleted_sources`：被删除的源合集 **ID 列表**（按请求顺序）；
- `added` / `skipped`：目标新增成员数 / 因已存在跳过的成员数。

## 2. 收藏智能视图

`GET /api/favorites/views` → 四个固定视图 + 实时计数：

```json
{
  "views": [
    {"key": "unrated", "label": "未评分", "description": "…", "count": 35},
    {"key": "unfiled", "label": "未整理", "description": "…", "count": 20},
    {"key": "high_rating", "label": "高分收藏", "description": "…", "count": 12},
    {"key": "stale", "label": "久未回顾", "description": "…", "count": 8}
  ]
}
```

`GET /api/favorites/views/{key}?page=1&size=50` → 该视图素材列表：

```json
{"key": "unrated", "items": [/* InspirationOut */], "total": 35, "page": 1, "size": 50}
```

| key | 口径（均只算未删除收藏） |
| --- | --- |
| `unrated` | 收藏且评分空 / 0（还没打分） |
| `unfiled` | 不在任何**手动合集**的收藏（智能合集动态求值，不算整理） |
| `high_rating` | 评分 ≥ 4 |
| `stale` | `favorited_at` 早于 90 天前，**或历史收藏无收藏时间**（NULL 也计入） |

- 排序统一 `favorited_at DESC`（NULL 最后）、`id DESC` 兜底；
- 未知 `key` 返回 404；`size` 上限 200（全局分页约定）。

## 3. 收藏整理工作台数据

`GET /api/favorites/cleanup`

```json
{
  "counts": {
    "unrated": 35,
    "unfiled": 20,
    "missing_files": 3,
    "duplicate_groups": 2,
    "duplicate_items": 4
  },
  "missing_files": [/* 最多 20 条 InspirationOut */],
  "duplicate_groups": [
    {"content_hash": "sha256…", "items": [/* 组内 InspirationOut */]}
  ]
}
```

口径：

- 全部只统计**未删除收藏**；垃圾桶素材不参与；
- `missing_files`：收藏素材的 `file_path` 在 `storage_root` 下不存在。路径解析是**安全**的：
  绝对路径 / `..` 越界 / 解析异常一律按「缺失」处理（不读 storage_root 之外的文件）；
- `duplicate_groups` / `duplicate_items`：按 `content_hash` 分组且组内 >1 的**总数**，
  不受展示上限影响；`duplicate_items` 是组内素材总数（不是「多出来的数量」）；
- 展示上限：`missing_files` 最多 20 条（按收藏时间倒序），`duplicate_groups` 最多 20 组
  （按组内条数降序、hash 升序）；组内按收藏时间倒序；
- 不做缓存：30k 级收藏的 exists 检查 + 一次分组查询在可接受范围（任务口径）。

## 5. 已知取舍

- **只接受普通手动合集**：抖音自动维护的收藏夹、系统收藏根、有子收藏夹的分类节点都不能作为
  移动/复制/合并的源或目标；智能合集需先固化（solidify）为手动合集。
- **合并不可撤销**：源合集被删除（素材本身不删）；前端二次确认文案应写明「合并后删除源合集」。
- `transfer` 的 `added`/`skipped` 是跨目标合计，不返回逐目标明细；如需逐目标展示可后续扩展。
- **重复判定只看 `content_hash`**（文件内容 SHA-256），不看 `phash`：感知哈希相近但内容不同的
  素材不算重复，避免误合并。
- **缺失文件判定依赖本地磁盘**：若 storage 位于可移动盘/网络盘，离线时会把全部收藏判为缺失；
  工作台只展示数据，不做删除。
- 工作台为实时查询，未做缓存/分页（缺失与重复都是全量扫描后截断展示）；后续如成为热点可加缓存。
