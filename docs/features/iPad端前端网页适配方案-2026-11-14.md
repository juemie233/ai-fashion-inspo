# iPad 端前端网页适配方案（2026-11-14）

> 状态：已按本文完成阶段 1–4 实施（2026-11-14），实现记录见 §12。
> 范围：Web 前端（Vue 3 + Vite + TypeScript + Arco Design）在 iPadOS Safari / 主屏幕 PWA 下的布局、触控、弹层、表格与拖拽；移动端 App 不在本文范围。
> 方法：检查 viewport/布局 CSS、响应式断点、固定宽度弹层、hover 交互、拖拽实现、触控尺寸、安全区与现有 e2e 配置；重点页面人工走查。
> 结论：**项目已经有一层 iPad 适配（侧栏 ≤1024px 收成 64px、100dvh、safe-area、部分页面 900/767 断点、卡片 hover:none 常显）**，但仍是「桌面端 + 若干补丁」的状态。真正阻塞 iPad 使用的主要是：**固定宽度弹层溢出、图片灯箱没有触摸缩放/平移、拖拽排序没有触控替代、触控目标过小、部分页面固定 100vh/固定侧栏**。

## 2. 目标与判定标准

### 2.1 目标

1. iPad 竖屏（768–834）、横屏（1024–1366）都能完成核心链路：浏览 / 搜索 / 详情 / 收藏 / 上传 / 出图记录 / 任务查看；
2. 不出现横向溢出、按钮被裁、弹层超出屏幕；
3. 纯触控可用，不依赖 hover、右键、拖拽或键盘；
4. 触控目标 ≥ 44×44 CSS px（Apple HIG 44pt；最低不低 36px）；
5. Safari 地址栏收放、主屏幕 PWA、分屏/Slide Over 下不破版。

### 2.2 非目标

- 不把 Web 改造成移动端底部 Tab 布局；
- 不追求 iPad 与桌面完全一致的密度；允许减少列数/隐藏次要列；
- 不为 Apple Pencil/手写做专门能力；
- 不重做 Arco 组件库。

## 4. 主要问题

### P1-1 固定宽度弹层在 iPad 竖屏溢出

Arco Modal 默认 CSS 只有 `width: 520px`，**没有全局 max-width**；项目里大量 `:width` 超过 iPad 竖屏内容宽度：

| 组件 | 宽度 |
| --- | ---: |
| `GenerateCompareModal.vue` | 1140 |
| `GenerateRunCompareModal.vue` | 1080 |
| `AnalysisCompareBatchModal.vue` | 1080 |
| `PersonFaceCandidatesModal.vue` | 980 |
| `AnalysisCompareModal.vue` / `ScraperFunnelModal.vue` / `TaskRunHistoryModal.vue` | 960 |
| `GenerateImportDialog.vue` / `PosePickerModal.vue` | 900 |
| `ReferenceGalleryModal.vue` / `ReferencePickerModal.vue` / `TagDuplicateCompareModal.vue` | 880 |
| `PersonRandomBrowseModal.vue` | 860 |

iPad 竖屏 768px、内容区约 672px；900/960/1140 的弹层会超出视口，右侧按钮/内容被裁，Safari 可能整页横向滚动。

**建议**：

- 全局兜底：

```css
@media (max-width: 1024px) {
  .arco-modal {
    max-width: calc(100vw - 32px);
  }
  .arco-drawer {
    max-width: 100vw;
  }
}
```

- 组件内如需要更精确：`:modal-style="{ maxWidth: 'calc(100vw - 32px)' }"`；
- 弹层内部用 `max-height: calc(100dvh - 32px)` + 内容区 `overflow-y:auto`，避免竖屏高度不够；
- 逐个验证上表弹层，而不是只依赖全局 CSS。

### P1-2 图片灯箱没有触摸缩放/平移

`ImageLightbox.vue` 当前：

- `@mousedown` 拖拽平移；
- `@wheel` 滚轮缩放；
- `@dblclick` 双击缩放；
- 键盘 `+/-/Esc/方向键`。

**没有 `pointerdown/pointermove`、`touchstart/touchmove` 或双指 pinch**。iPad 上只能点按钮缩放，不能拖动放大后的图片；双击还可能触发 Safari 页面缩放而不是组件缩放。

**建议**：

- 统一改用 Pointer Events（同时覆盖鼠标/触控/笔）；
- 增加双指 pinch 缩放（可用 `touchstart/touchmove` 计算两指距离）；
- 放大后单指拖动平移；
- `touch-action: none` 仅作用于图片容器，避免页面滚动冲突；
- 保留 +/- 按钮与键盘操作；
- 真机验证「双指缩放 → 单指平移 → 点击背景关闭」不误触。

### P1-3 拖拽排序没有触控替代

当前拖拽实现：

| 功能 | 实现 | iPad 风险 |
| --- | --- | --- |
| 合集一级排序 | `CollectionSidebar.vue` HTML5 `draggable` | 触屏无法稳定拖拽 |
| 合集成员排序 | `CollectionOrderingStrip.vue` draggable | 同上 |
| 标签分类/标签排序 | `TagGroupList.vue` draggable | 同上 |
| 标签树拖拽 | `TagTreePanel.vue` draggable | 同上 |
| 标签管理左右分栏 | `useSplitResize.ts` 只监听 `mousemove` | 触屏不能拖分栏 |
| 上传 | `UploadView` drag/drop | 有「选择文件」按钮兜底，文字仍写「拖拽/Ctrl+V」 |

**建议**：

- 排序统一提供「上移/下移」按钮或「排序」弹层（触屏友好），拖拽保留给鼠标；
- `useSplitResize` 改用 Pointer Events，或提供「重置/收起左栏」按钮；
- 触屏设备隐藏「拖动排序」提示，改成「使用上移/下移排序」；
- 上传页在 `(hover:none)` 下把提示改成「点选择文件或拍照上传」。

### P1-4 触控目标偏小

统计：全仓 **233 处 `size="mini"`**。Arco mini 按钮约 24px 高；卡片悬浮操作按钮也偏小（`ThumbCard` 的 `IconButton` 44px 是好的，但 `InspirationCard` 的 `a-button size="mini"` 仍小）。`InspirationCard` 在 `hover:none` 下把「浏览详情」从 26px 提到 32px，但仍低于 44px。

**建议**：

- 触屏媒体查询下统一把操作按钮的命中区扩到 44×44（可用 padding/hit area，不必把图标变大）；
- 表格行内操作优先收进「更多」菜单，减少一排 mini 按钮；
- 卡片悬浮操作在触屏下用 44px 圆形按钮或底部 Action Sheet；
- 评分星、收藏、删除这类高频/高风险按钮优先处理。

### P1-5 固定 `100vh` 与动态工具栏

`TagManageView.vue`、`TagAdvancedManageView.vue` 使用：

```css
height: calc(100vh - 120px);
```

iPad Safari 地址栏收放时 `100vh` 是「最大视口」，页面会比可视区高，底部被裁；分屏/Stage Manager 下更明显。

**建议**：

- 改用 `calc(100dvh - 120px)`，保留 `100vh` 回退；
- 或 `height: 100%; min-height:0` 由 AppLayout 的固定高度承担；
- 同类 `max-height: 72vh/88vh/92vh` 的弹层/预览，优先 `dvh` 或 `min(...)`，并在 iPad 上验证。

### P1-6 AppLayout 的滚动容器不完整（需实测确认）

当前：

```css
.app-shell { min-height: 100vh; min-height: 100dvh; }
.main-content { flex:1; min-width:0; overflow-y:auto; }
```

`app-shell` 只有 `min-height` 没有 `height`；在长页面里容器会随内容增高，`main-content` 的 `overflow-y:auto` 不会形成独立滚动区，实际滚动多半落在 `body`，侧栏会随页面一起滚走（导航不可见）。

**建议二选一**：

- **方案 A（固定外壳，推荐）**：

```css
.app-shell { height: 100vh; height: 100dvh; }
.main-content { min-height: 0; overflow-y: auto; }
.sidebar { height: 100%; overflow-y: auto; }
```

- **方案 B（整页滚动）**：去掉 `main-content` 的 `overflow-y:auto`，接受侧栏随页面滚动，但要用 `position: sticky` 让侧栏在长页面中保持可见。

需要在 iPad Safari（地址栏展开/收起）、PWA 全屏、分屏三种模式下实测，再定方案。

### P2-1 hover-only 预览与操作

- `HoverImagePreview.vue` 用 `mouseenter/mouseleave`；iPad 没有 hover，预览完全不可用。
- `ImageHoverPreview.vue` 用 Arco `a-popover trigger="hover"`；iPad 上首次点按可能触发「模拟 hover」弹出浮层，产生「点一下先弹预览、再点才进详情」的意外。
- 全仓约 47 个 `:hover` 选择器，但只有 2 个 `@media (hover:none)` 覆盖。

**建议**：

- 触屏下禁用 hover 预览，改为「长按预览」或详情页查看；
- 或保留一个明确的「查看大图」按钮；
- 统一用 `@media (hover: none)` / `(pointer: coarse)` 做能力判断，而不是按宽度猜设备。

### P2-2 收藏合集左右分栏在窄宽下拥挤

`CollectionSidebar` 固定 `width/min-width: 260px`，`CollectionsView` 没有媒体查询。iPad 竖屏内容约 672px，左侧 260 后右侧仅约 396px；分屏 507px 时右侧只剩约 215px，基本不可用。

**建议**：

- `≤900px` 把合集列表收成顶部横向滚动/抽屉；
- 或折叠为「合集」按钮 + 抽屉，内容区占满；
- 保留 `position: sticky` 但不要固定 260px。

### P2-3 表格横向滚动与操作列

大量表格使用固定 `scroll.x`：

- `PersonListSection` x=1180；
- `GenerateHistoryTable` x=1480；
- `AdminPromptQuality` x=1080；
- `ScraperRoiPanel` 900/1020。

iPad 竖屏必须横向滚动才能看到右侧操作列；触屏滚动可用，但「先横滑再点操作」成本高。

**建议**：

- 高频操作列做 sticky（Arco 支持 `fixed: 'right'`）；
- 或 `≤768px` 切换为卡片列表，次要列收进「详情」；
- 至少给横向滚动区域加可视提示（阴影/滚动条），避免用户不知道右边还有列。

### P2-4 安全区只覆盖了 AppLayout 底部

`viewport-fit=cover` 已开启，但只有 `AppLayout` 有 `env(safe-area-inset-bottom)`；`ImageLightbox` 的关闭按钮 `top:16px`、底部控制条 `bottom:20px` 没有安全区补偿。主屏幕 PWA / 横屏时可能贴近 Home 指示条或屏幕边缘。

**建议**：

- 全屏灯箱/全屏预览的顶部/底部控制条使用 `env(safe-area-inset-top/bottom)`；
- 抽屉/弹层底部按钮同理；
- 在 iPad 主屏幕 PWA 与 Safari 两种模式下各验一次。

### P2-5 字体缩放与页面缩放

Web 没有 `-webkit-text-size-adjust` / `text-size-adjust` 的显式设置；iPad 横竖屏切换、Safari 页面缩放 125%/150% 时，部分固定宽度布局可能被挤压。

**建议**：

- 全局 `html { -webkit-text-size-adjust: 100%; text-size-adjust: 100%; }`；
- 关键页面在 Safari 125%/150% 缩放下走查一次；
- 避免用固定 `px` 宽度承载长中文按钮/标签。

### P2-6 缺少 iPad 的自动化回归

`web/playwright.config.ts` 当前只有 Desktop Chrome 1600×1100，`workers:1`；没有 iPad viewport 项目，也没有触控模拟/视觉快照。

**建议**：

- 新增 `ipad-portrait`（768×1024）与 `ipad-landscape`（1024×768）两个 Playwright project；
- 加 `hasTouch: true`、`isMobile` 仅用于触控模拟（注意 Safari 内核仍是 Chromium，只能覆盖布局/交互，不覆盖 Safari 特有问题）；
- 至少覆盖：首页、详情、搜索、收藏合集、标签管理、出图、任务、一个表格页；
- 加关键页截图基线（可选）。

## 5. 设计规则（建议写入前端规范）

1. **布局按容器宽度，不按设备名**：优先 CSS 媒体查询；组件内用 `ResizeObserver` 而不是只看 `window.innerWidth`。
2. **禁止无上限固定宽度**：弹层/抽屉/侧栏用 `min(px, calc(100vw - 32px))` 或全局 `max-width`。
3. **触控目标 ≥44×44**：图标按钮用 44px 命中区，视觉图标可 20–24px。
4. **所有 hover 交互必须有触控替代**：长按、点按、按钮或详情页。
5. **所有拖拽必须有按钮替代**：上移/下移、排序弹层、分栏收起。
6. **全屏容器用动态视口高度**：`100dvh`，保留 `100vh` 回退；不要 `calc(100vh - 固定值)`。
7. **全屏/贴边控件用 safe-area**：顶部/底部都要。
8. **表格先保证操作列可见**：sticky 操作列或窄屏卡片化。
9. **文字不依赖悬停显示**：title 只能作为补充，不能是唯一信息源。
10. **iPad 验收至少包含竖屏、横屏、分屏三种宽度**。

## 7. 实施顺序

### 阶段 1：基础兜底（1–2 天）

1. 全局 `.arco-modal` / `.arco-drawer` max-width；
2. `app-shell` 高度/滚动方案二选一并在 iPad 实测；
3. `TagManageView` / `TagAdvancedManageView` 100vh → 100dvh；
4. 全屏灯箱/抽屉 safe-area；
5. 触屏下隐藏 hover 预览或改为长按；
6. 全局 `text-size-adjust:100%`。

### 阶段 2：核心交互（3–5 天）

1. `ImageLightbox` Pointer Events + pinch + 平移；
2. 合集/标签排序的上移/下移按钮；
3. `useSplitResize` 改 Pointer Events 或提供收起；
4. 触控目标 ≥44（卡片操作、表格行操作、评分）；
5. 收藏合集侧栏 ≤900 折叠。

### 阶段 3：表格与页面（3–5 天）

1. 人物/出图/采集/模型表格 sticky 操作列或窄屏卡片化；
2. 900+ 弹层逐个验证；
3. 上传页触屏文案；
4. 首页筛选栏换行/密度按钮触控；
5. 随机评分等新页面补查。

## 9. 需要确认的产品/技术点

1. **iPad 是否只支持 Safari，还要不要支持主屏幕 PWA？** 两者 safe-area/视口行为不同，验收要分开。
2. **最低 iPadOS 版本？** `100dvh` 需要 Safari 15.4+；如果要支持更老版本，必须保留 100vh 回退并避免依赖 dvh 的新特性。
3. **是否要求支持分屏/Slide Over？** 如果只要求全屏 iPad，收藏合集/表格的极窄布局可以降级；如果要求，需要按 320–507px 单独设计。
4. **拖拽排序是否接受改成上移/下移？** 推荐接受；否则需要专门实现触摸拖拽（成本高、误触多）。
5. **表格窄屏是横向滚动还是卡片化？** 推荐高频页卡片化、低频管理页 sticky + 横向滚动。
6. **触控目标做到 44 还是 36 折中？** 推荐 44；36 只用于低频次要操作。

## 11. 结论

iPad 适配不是从零开始：侧栏、部分断点、hover:none、100dvh 已经打了底。但要让 iPad 真正可用，优先级应是：

1. **弹层不溢出 + 外壳滚动正确**（否则很多页面直接不可操作）；
2. **灯箱触摸手势 + 排序/分栏的触控替代**（触屏核心交互）；
3. **触控目标与 100dvh/safe-area**（手感与 Safari 兼容）；
4. **表格/合集窄屏策略 + Playwright iPad 回归**（持续保障）。

建议按 §7 分四阶段实施，先做阶段 1 的全局兜底，再做灯箱与排序，最后补表格和自动化。

### 12.1 已拍板的前提
