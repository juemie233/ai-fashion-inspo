# 采集与 f2 通道说明

> **状态**：现行｜编写日期 2026-11-01｜依据 `backend/app/scrapers/`、`services/scraper/`、`task_runners/f2_*`、`routers/scraper.py`
> **一句话**：采集有三条入口——Playwright 网页采集、f2 抖音下载、浏览器插件；三条最终都汇入同一套「判重 → 入库 → 打标」链路。
> **合规前提**：只采集公开内容、串行 + 随机延时、遇限流/验证码即停并留审计，不做换 IP 硬刷（见 CLAUDE.md「安全与数据合规」）。

---

## 1. 三条采集通道

| 通道 | 适用 | 实现 | 产物 |
| --- | --- | --- | --- |
| **Playwright 网页采集** | 小红书 / 抖音按关键词、话题、博主搜索结果 | `scrapers/xiaohongshu.py`、`scrapers/douyin.py`，经 CDP 连接采集专用 Chrome | 下载图片 / 视频 → 入库 |
| **f2 抖音下载** | 自己账号的点赞、收藏夹、关注作者的作品批量回捞 | 上游开源项目 f2（子进程 `python -m f2 ...`） | 下载到本地目录 → 扫描 → 入库 |
| **浏览器插件** | 单个笔记页 / 单张图 | `browser-extension/`，只转交 URL | 后端 `from-url` 下载 → 入库 |

三条通道**共用**后端的去重、缩略图、入库与打标登记；插件与 Playwright 走 `create_inspiration_from_file/url`，f2 走批量导入计划。

## 2. Playwright 网页采集

### 2.1 浏览器与登录态

- 采集专用 Chrome 由后端通过 CDP 启动 / 停止，用户数据目录由 `CHROME_USER_DATA_DIR` 指定（`.env`），登录态保存在该 profile；
- 相关接口：`GET /api/scraper/chrome/status`、`POST /chrome/start`、`POST /chrome/stop`、`GET /cdp-check/{port}`；
- **Cookie 通道**：`GET /cookie-status`、`POST /cookie-verify/{platform}`、`POST /cookie-import`、`DELETE /cookie/{platform}`；只允许 `xiaohongshu` / `douyin` 两个平台（白名单在 `services/scraper/cookies.py`）；
- 浏览器插件导出的 Cookie 可直接导入（`sameSite` 取值会映射成 Playwright 期望值）。

### 2.2 任务与定时

| 能力 | 入口 |
| --- | --- |
| 创建采集任务 | 采集管理页 → `services/scraper/tasks.py` |
| 查看日志 / 取消 / 重试 | `GET /tasks/{id}/log`、`POST /tasks/{id}/cancel`、`POST /tasks/{id}/retry`、`POST /tasks/retry-failed` |
| 定时计划 | `GET/POST/PATCH/DELETE /schedules`、`POST /schedules/{id}/run` |
| 统计 / ROI | `GET /stats`、`GET /collection-roi`、`GET /hashtags` |

采集任务与 `task_queue` 是两套记录：`scraper_tasks` 记录「去平台抓取」的过程，抓取完成后才产生素材，不占任务队列 worker。

### 2.3 限流参数（`.env`）

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `SCRAPER_REQUEST_DELAY` | 2.0 秒 | 请求间隔 |
| `SCRAPER_MAX_CONCURRENT` | 3 | 并发上限 |
| `SCRAPER_DEFAULT_MAX_COUNT` | 20 | 单次默认采集量（控制规模规避风控） |
| `SCRAPER_BROWSER_HEADLESS` | true | 是否无头 |
| `SCRAPER_TASK_AUTO_RETRY` | 2 | 崩溃自动续采次数 |

> `playwright-stealth` 只用于降低误判，不用于绕过登录与风控；遇到验证码或限流应停止并留审计，而不是重试硬刷。

## 3. f2 通道（抖音批量回捞）

### 3.1 f2 是什么、边界在哪

f2（[Johnserf-Seed/f2](https://github.com/Johnserf-Seed/f2)）负责**下载**；本仓库只做「调度 → 判重 → 入库 → 打标」。抖音侧的作品下载完全交给上游，不在本仓库重写解析逻辑。

f2 以子进程运行：`python -m f2 ...`，产物根目录由 `F2_DOWNLOAD_ROOT` 指定（默认为 f2 工作目录下的 `Download`）。结构为：

```text
<F2_DOWNLOAD_ROOT>/douyin/{post|like|collection}/{昵称}/
```

### 3.2 三种取数模式

| 模式 | 语义 | 关键要求 |
| --- | --- | --- |
| `post`（发布模式，默认） | 下载指定作者（关注列表 / 点名博主）的作品 | 作者清单见 `services/scraper/f2_authors.py` |
| `like`（我的喜欢） | 下载**当前登录账号**的点赞列表 | 必须填自己的主页链接（`F2_LIKE_USER`）；点赞列表只有本人可见 |
| `collects`（我的收藏） | 按抖音收藏夹下载 | 先 `GET /f2-collects` 列出夹，默认全选；`-M collects` 是交互式的，worker 里跑不了，改用分页接口自建 |

**「我的喜欢」注意**：f2 的点赞分页没有「遇到已下载就停」，会从 cursor=0 一路翻到底；`F2_LIKE_MAX_COUNTS`（默认 0 = 全量）可限制单次翻页数。

### 3.3 下载前预览与批次回滚

- **预览**：`GET /api/scraper/f2-preview` 跑同一条「扫描 → 五层判重」链路（`build_plan_with_cache`），只返回「新增 N 个文件 / M 个作品 + 跳过明细（含原因）」，不写库。15,350 个文件的哈希缓存首次约 81 秒，之后 1~2 秒；
- **回滚**：`GET /f2-tasks/{id}/rollback/preview` + `POST /f2-tasks/{id}/rollback`，复用 CLI 的 `plan_rollback` / `apply_rollback`；
  - 默认只撤销「本批导入且之后没被人动过」的素材（打标 / 收藏 / 评分 / 改过质量状态的保留并说明原因）；
  - `force` 才连它们一起删；
  - **物理删除而非进垃圾桶**：撤销误导入的素材若进垃圾桶，会被当作负样本污染学习；
  - 写 `f2_rollback` 审计。
- **清理源文件**：`--prune-downloads`（默认关），入库 commit 成功后才删本批成功导入的源文件，先保库再删盘。

### 3.4 五层判重

导入计划由 `build_import_plan` 产出，五层判据（顺序即成本从低到高）：

1. **内容 SHA-256**：同文件重复（跨批次、跨目录）；
2. **垃圾桶**：已在垃圾桶的素材不重复导入（软删除释放平台 ID）；
3. **批次内**：本批扫描结果内部去重（同一作品多份文件 / 硬链接）；
4. **合成平台 ID**：库内已有 `f2:<19 位作品 ID>#<类型><序号>` 的跳过；
5. **参数过滤**：按日期窗口（`F2_FETCH_SINCE_DAYS`，默认 14 天）、类型、作者等条件过滤。

> 旧素材的 `source_platform_id` 是文件名算出的合成哈希，与作品 ID 无法互推——这部分只能靠内容哈希判重，代码里不假装知道。

### 3.5 执行阶段（A~F 分片）

`f2_import` 任务由 `f2_import.py` 编排，拆分如下：

| 阶段 | 模块 | 内容 |
| --- | --- | --- |
| 取数 | `f2_fetch_stages.py` | 下载（我的列表 / 逐作者）、收藏夹归位、发布模式选人、主页链接解析 |
| 进度 | `f2_progress.py` | 子进程执行、软进度、每 2 秒把已落盘文件数写回任务 |
| 判重 | `f2_library_ids.py`、`f2_plan_apply.py` | 库内作品 ID 索引、扫描 + 五层判重、生成导入计划 |
| 入库 | `f2_plan_apply.py` | 线程内同步入库，watcher 每 2 秒落库并把取消/暂停转成停止标记 |
| 归位 | `f2_finalize.py` | 收藏夹归位（两级）、批次结算、`result.notices` |
| 助手 | `f2_personal.py` | 点赞 / 收藏模式常量、按名字 + 父级幂等建合集 |

**两条硬性约定**：

1. **导入不做标签分析**：不调用 `analyze_image`、不建向量，素材以未打标状态入库，打标交给「批量分析任务」；
2. **必须去重**：上面五层判重是导入的前提，缺一层就会出现重复素材。

### 3.6 自动获取

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `F2_IMPORT_AUTO_ENABLED` | false | 是否开启每日自动获取 |
| `F2_IMPORT_INTERVAL_HOURS` | 24 | 间隔；f2 按 `last_aweme_id` 只下新作品，重复触发无额外收益 |
| `F2_IMPORT_AUTO_MODE` | `post` | 自动模式（post / like / collects） |
| `F2_IMPORT_AUTO_SKIP_LIVE` | false | 是否跳过直播 |
| `F2_FETCH_SINCE_DAYS` | 14 | 只翻最近 N 天；0 = 全历史 |
| `F2_LIKE_USER` | 空 | 我的喜欢模式必填（自己的主页链接） |
| `F2_LIKE_MAX_COUNTS` | 0 | 点赞单次最多翻多少条；0 = 全量 |

自动获取通过 `create_f2_import_task_if_idle` 保证同一时间只有一个 f2 任务在跑。

### 3.7 批次结果与审查

| 接口 | 用途 |
| --- | --- |
| `GET /f2-tasks/{id}/results` | 按批次清单浏览本批素材 |
| `POST /f2-tasks/{id}/results/trash` / `restore` / `delete` | 批量移入垃圾桶 / 恢复 / 物理删除 |
| `POST /f2-tasks/{id}/results/register-bloggers` | 把来源作者补建成博主（不进下载白名单） |
| `GET /f2-authors` | 下载白名单里有哪些作者、各自入库多少 |
| `GET /f2-status` | 当前 f2 任务 / 自动调度状态 |

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 采集任务立刻失败，提示找不到浏览器 | 采集专用 Chrome 未启动 / CDP 端口不通 | 先 `POST /chrome/start`，再 `GET /cdp-check/{port}` |
| 登录态失效、页面跳登录 | Cookie 过期 / profile 被清 | 重新登录采集 profile，或导入新 Cookie 并 `cookie-verify` |
| f2 报 `ModuleNotFoundError: f2` | 当前 Python 环境没装 f2 | 按 f2 上游文档安装；CI 无 f2 时相关用例应跳过 |
| 「我的喜欢 / 我的收藏」提示 **F2 抖音登录 Cookie 已过期** | f2 配置 `douyin.cookie` 的 `sid_guard` 已过期（任务会在启动 f2 子进程前预检并直接失败，不再静默成功 0） | 关闭浏览器后执行 `python -m f2 dy --auto-cookie chrome` 更新 `f2/conf/app.yaml`，或手动替换 Cookie 后重新提交；只登录浏览器不会自动更新 f2 配置 |
| f2 下载 0 个作品 | 点赞/收藏必须本人可见；作者清单为空；日期窗口太窄；Cookie 过期（旧版本会静默成功） | 检查 `F2_LIKE_USER`、作者白名单、`F2_FETCH_SINCE_DAYS`；「我的列表」模式先看任务是否报 Cookie 过期 |
| 预览数字与执行不一致 | 预览与执行之间目录/数据库变了 | 正常；预览只是快照，执行时会重新跑计划 |
| 重复素材 | 判重被跳过 / 旧素材无真实作品 ID | 不要跳过五层判重；旧素材只能靠内容哈希 |
| 误导入想撤销 | — | 用批次回滚（默认只撤回没被动过的，物理删除） |
| 磁盘越来越大 | f2 产物 19 GB 级且持续增长 | 设 `F2_DOWNLOAD_ROOT` 到非系统盘；需要时开 `--prune-downloads` |
