# 手机截图自动裁剪

> **状态**：现行（2026-11-22 按代码核对）。真源：`backend/app/services/crop_service.py`（编排）+
> `crop_scan.py` / `crop_candidates.py` / `crop_common.py` / `crop_vlm.py`、
> `routers/admin.py` 的 `/crop-phone-screenshots/*`、`schemas/admin.py` 的请求模型、
> `web/src/components/admin/{AdminPhoneCrop,AdminCropResultsPanel}.vue`、
> CLI 入口 `scripts/data/crop_screenshots.py`（与服务共用同一份实现）。

## 1. 解决什么问题

手动上传的图里有一部分是**手机全屏截图**：画面上下混进状态栏、底部导航/进度条，
既影响看图也影响 CLIP 向量（向量算的是整张图）。这个功能把这类素材**就地裁掉上下多余区域**，
并同步更新缩略图、内容哈希、主色调与向量。

**不是通用裁剪**：它有硬性准入条件，且默认只处理黑边截图。

## 2. 准入条件（不满足直接跳过）

| 条件 | 值 | 说明 |
|---|---|---|
| 来源 | `source_type = manual_upload` | 采集/生成/插件入库的图不处理 |
| 删除状态 | 未删除 | 垃圾桶里的素材跳过 |
| 媒体类型 | 图片 | 视频不参与 |
| 比例 | 竖屏，高/宽 ≥ **1.75** | 手机截图特征；横屏/方图不处理 |
| 文件 | 可解码 | 文件缺失/无法解码→跳过并注明原因 |

即使满足条件，**裁剪后若与库中其它素材内容重复，该条也会自动跳过并保留原图**——
裁剪把两张不同的截图变成同一张时，不应该制造一份新重复。

## 3. 三种模式

| 模式 | 做法 | 适用 |
|---|---|---|
| `auto`（默认） | 检测**黑边**（深色/黑色背景的状态栏区域） | 深色背景截图；浅色背景会检测不到 → 白跑一趟 |
| `ratio` | 按固定比例裁：顶部 `crop_top`、底部 `crop_bottom` | 浅色背景截图；默认 3% / 5% |
| `content` | 内容边界检测 | 截图主体四周留白不规则的场景 |

## 4. 两步流程：先扫描（只读）→ 人工勾选 → 执行

```
POST /api/admin/crop-phone-screenshots/scan   只读，返回候选 + 跳过明细
        ↓ 人工在页面上勾选（可以只勾一部分）
POST /api/admin/crop-phone-screenshots/apply  按 ids 执行，写库 + 入队向量回填
```

### 4.1 扫描参数与语义

| 参数 | 默认 | 说明 |
|---|---|---|
| `mode` | `auto` | 见上 |
| `crop_top` / `crop_bottom` | 0.03 / 0.05 | 仅在 `ratio` 模式生效（0 ≤ x < 0.5） |
| `limit` | 200（上限 1000） | 单次返回候选数 |
| `cursor` | 空 | 分页游标，传上一批的 `next_cursor` 继续扫剩余素材 |
| `time_budget` | 60（5~300 秒） | 单次扫描时间预算，耗尽即返回已找到的候选（不报错） |
| `vlm_review` | `true` | AI 复核：VLM 判断顶部状态栏/底部进度条是否残留，**约 1.3 秒/候选**，阳性候选置顶并标注 |

扫描是**只读**的（不写库、不改文件），失败或超时也不会影响素材本身。

### 4.2 执行做了什么

`apply` 收到勾选的 `ids`（必填，空列表直接 400）后逐张：

1. **备份原图**到 `storage/_crop_backup/{时间戳}/`；
2. 裁剪并替换原文件；
3. 重建**缩略图**、**内容哈希**、**主色调**；
4. 向量重建以**任务队列**方式入队，由 worker 消费（不阻塞接口）；
5. **标签、收藏、来源等字段完全不动**。

重复对比预览会写进本批次的 `_crop_dups` 目录（带目录锁，自动清理历史批次），方便人工看
「裁完以后和哪张撞了」。

## 5. 代码分层（为什么要拆 5 个文件）

| 文件 | 职责 | 特点 |
|---|---|---|
| `crop_service.py` | 编排：扫描/执行/落库/入队 | 只做流程，不实现判定细节 |
| `crop_scan.py` | 扫描主体（找候选、分页、时间预算） | 触库 + 触文件 |
| `crop_candidates.py` | **候选裁决 + 游标解析**纯函数 | 不碰库、不读文件，最好测 |
| `crop_common.py` | 共用的图像/比例工具 | 纯工具 |
| `crop_vlm.py` | VLM 复核（状态栏/进度条） | 只依赖 httpx/PIL/settings，独立「模型问询」层 |

`crop_vlm.py` 用**三态**表达结果：`True` 明确检出、`False` 明确未检出、`None` 无法判断——
不要把它简化成布尔值，`None` 混进 `False` 会让「模型没答上来」被当成「确认没有」。

**前端**：`AdminPhoneCrop`（扫描/勾选/执行）+ `AdminCropResultsPanel`（结果区，从主组件提取式重构）；
结果里带素材缩略图与「定位跳转到素材库」链接（构造 `?focus=id1,id2`，见
[素材库首页与批量操作](素材库首页与批量操作.md) §3）。

## 6. 常用坑

1. **浅色截图一张都没扫到**：`auto` 模式只认黑边；换 `ratio`（或 `content`）。
2. **裁剪后想还原**：原图在 `storage/_crop_backup/{时间戳}/`，手动拷回即可。但注意
   **`_crop_backup` 不在常规备份范围内**（见 [数据备份与恢复](../ops/数据备份与恢复.md) 的排除项）——
   它不是可撤销的撤销栈，别把批量裁剪当可回滚操作。
3. **扫描到一半没了**：`time_budget`（默认 60 秒）用尽会返回已有结果；用 `next_cursor` 继续扫。
4. **开了 AI 复核后很慢**：约 1.3 秒/候选，几百张候选就是几分钟；只需要粗筛时先关 `vlm_review`。
5. **勾了一堆但只有部分被裁**：被跳过的一定会在结果的「跳过明细」里给原因（比例不符/重复/文件缺失）；
   别只看成功数以为自己少勾了。
6. **裁完搜索不到原图**：内容哈希变了，按哈希/精确重复查不到旧图——向量已入队重建，等任务跑完再搜语义相似。
