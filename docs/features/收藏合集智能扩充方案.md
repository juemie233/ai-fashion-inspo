# 收藏合集智能扩充（按此合集扩充）

> 日期：2026-11-22
> 状态：已实施（候选生成 + 人工勾选 + 批次撤销；智能合集可先转「半智能」再扩充）
> 范围：用户自建手动合集与半智能合集；只做一次性候选，不做自动/持续扩充

## 1. 背景与目标

收藏夹（尤其是从抖音同步来的）已经有了一批「典型的」素材，但素材库里还有大量
风格相近、却因为采集时不在同一个收藏夹而没被收进来的内容。人工逐张翻找成本高。

目标：在合集详情页提供「按此合集扩充」：以合集现有成员为种子，在素材库中找出
相似但尚未入夹的素材 → 人工勾选 → 批量加入 → 可一键撤销。

## 2. 口径（用户已确认 2026-11-22）

1. **只写用户自建合集**：允许手动合集与**半智能合集**；抖音同步收藏夹
   （`collections.auto_source` 非空）、纯智能合集、分类节点一律拒绝（400）。
   需要扩充抖音收藏夹时，先「复制为手动合集」——f2 同步只增不删，手工写进去会让
   本地夹与抖音侧长期不一致。
2. **一次性候选 + 人工勾选**：打开弹窗只生成候选（只读接口），写入必须人工确认。
3. **可溯源、可撤销**：`collection_items` 新增 `added_by`（manual / ai_suggest /
   sync）与 `added_batch`；「撤销本次扩充」按批次只删 `ai_suggest` 成员。
4. **半智能合集**（2026-11-22 追加）：智能合集可一键「转为半智能」——保留
   `query_json` 动态匹配，同时允许在 `collection_items` 里补充素材；内容口径变为
    **规则匹配 ∪ 实体成员**。手动加入/移出/扩充都可用，之后仍可固化为纯手动合集
   （固化会保留已补充的成员）。

## 3. 匹配算法

复用现有向量与标签能力，不引入新模型：

1. **种子**：合集前 200 个成员（手动按 `position`；半智能取「规则匹配 ∪ 成员」的最新
   200 条，排除垃圾桶）；候选排除集合同样用这个并集，避免规则已命中的素材重复推荐。
2. **画像**：
   - 图像向量：`vector_store.get_vectors_batch("image", seeds)` 求均值并 L2 归一化
     （有效向量少于 5 条视为不可用）；
   - 标签：种子素材标签频次 Top 8；`category='outfit'` 的**穿搭大标签**单独作为
     「大标签画像」，这是大标签与收藏夹联动的第一层。
3. **召回**：向量质心 `search_vectors(..., 200)`；再补「含 Top 标签」的素材（SQL，≤300）。
4. **打分**：`0.6 × 视觉相似 + 0.4 × min(共同标签数, 3)/3`（权重取自
   `settings.vector_similarity_weight / vector_tag_weight`）；向量不可用时降级为纯标签分。
5. **过滤**：已在合集内、垃圾桶、阈值以下；可选「只保留共享大标签」「排除已属于
   其它抖音自动合集的素材」。
6. 结果附「命中理由」（视觉相似度 / 同大标签 / 共同标签），供人工复核。

**不做 AI 调用**：本地 8B 模型慢且输出不稳定，预览式扩充更适合可解释的向量 + 标签；
`collection_ai_service` 的摘要能力后续可作为「AI 生成匹配画像」的可选增强。

## 4. 数据与接口

### 4.1 数据模型

`collection_items` 新增：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `added_by` | `VARCHAR(16) NOT NULL DEFAULT 'manual'` | manual / ai_suggest / sync |
| `added_batch` | `VARCHAR(32) NULL`（索引） | 扩充批次号；手工/同步为空 |

迁移 `e3f4a5b6c7d8_合集成员来源与扩充批次.py`：新增列 + 索引，并把
`auto_source` 非空合集的既有成员回填为 `added_by='sync'`。

`collections` 新增（半智能）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `semi_manual` | `BOOLEAN NOT NULL DEFAULT 0` | 智能合集允许实体成员（规则匹配 ∪ 成员）；手动合集恒为 0 |

迁移 `e4f5a6b7c8d9_智能合集支持半智能扩充.py`。半智能的内容求值：把
`query_json` 条件与 `collection_items.inspiration_id IN (...)` 取并集（两侧都排除垃圾桶），
再叠加内容页的筛选/排序；`item_count` 也按并集计算（不再是 null）。固化为手动合集时
**保留**已补充的成员，只补进尚未成为成员的规则命中。

### 4.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/collections/{id}/to-semi` | 智能 → 半智能（幂等）；手动合集 / 系统收藏根 400 |
| POST | `/api/collections/{id}/suggest-items` | 生成候选（只读）；body：`limit`(1~100，默认 40)、`min_similarity`(0~1，默认 0.5)、`outfit_only`、`exclude_other_auto`(默认 true) |
| POST | `/api/collections/{id}/expansions` | 按批次写入；body：`{inspiration_ids}`；返回 `{batch_id, added, skipped, not_found, added_ids}`；`added=0` 时 `batch_id` 为 null |
| DELETE | `/api/collections/{id}/expansions/{batch_id}` | 撤销该批次（只删 `ai_suggest` 成员）；无记录 404 |

`suggest-items` 响应：`{items: [{inspiration, similarity, shared_tags, outfit_tags,
match_source, reason}], total, profile: {top_tags, outfit_tags, seeds_used,
vector_available}}`。

扩充/撤销都会写 `audit_logs`（`collection_expand` / `collection_expand_undo`，detail 含批次与 ID 列表）。

### 4.3 前端

- `CollectionExpandModal.vue`：阈值滑杆、大标签/排除抖音夹开关、候选网格
  （`MasonryGrid` 的 `badges` 显示「88% · 2 标签」）、全选/清除、加入合集；
- `CollectionContentHeader` 增加「按此扩充」（手动/智能合集显示；抖音同步、系统收藏根、
  分类节点隐藏），半智能合集显示「半智能合集」标签；
- 纯智能合集点「按此扩充」先弹确认「转为半智能」→ 调 `to-semi` → 打开弹窗；
- `CollectionsView` 在扩充成功后显示「本次扩充已加入 N 个素材 · 撤销本次扩充」提示条。

```bash
cd backend

pytest -q            # 全量
cd ../web
npx vitest run src/components/collection/__tests__/CollectionExpandModal.test.ts

```

手工验收：

1. 手动合集 → 「按此扩充」→ 调整阈值/开关 → 勾选 → 加入合集；
2. 纯智能合集 → 「按此扩充」→ 确认转半智能 → 生成候选 → 加入；内容 = 规则匹配 ∪ 补充成员；
3. 顶部提示条「撤销本次扩充」→ 内容与计数恢复；
4. 抖音同步收藏夹 / 系统收藏根 / 有子夹的分类节点：不显示按钮，直接调接口返回 400；
5. 撤销后再次撤销同一批次返回 404。

## 6. 边界与后续

- **不做**：自动/定期扩充；智能合集新增「与某合集相似」规则；AI 生成匹配画像；
  向抖音同步收藏夹写入。
- 想做「新素材入库时提示加入某收藏夹」时，可复用本模块的画像（大标签 + 标签频次）
  做反向建议，但必须保持人工确认。

## 7. 已知风险

- 视觉相似会召回「同色不同类」的素材：默认阈值 0.5 + 人工勾选，`outfit_only`
  可进一步收敛；建议用真实收藏夹回测 Top20 准确率（目标 ≥ 70%）。
- 向量库不可用/素材未向量化时只剩标签召回，召回率下降但不会报错；
  前端会显示「仅标签（向量不可用）」。
- 大批量合集的种子只取前 200 条，画像可能偏向最新/最前的成员；如需更稳的画像，
  后续可改成按成员均匀采样。
