# 抖音收藏夹 → 穿搭大标签映射

> 日期：2026-11-24
> 状态：已实施（首次获取前可配置、同步自动打标、待确认与冲突三选一、重命名影响确认）
> 范围：抖音「获取我的收藏」归位的收藏夹；不影响 AI 打标与手动标签

## 1. 背景与目标

「获取我的收藏」把作品按抖音收藏夹归位到两级合集（`f2_finalize`），但夹名只存在于合集结构里：
搜索筛选、相似推荐、「按此扩充」的画像都用不上。本功能把每个收藏夹映射成一个**穿搭大标签**
（`tags.category='outfit'`），同步时自动给该夹全部素材（含视频）打上，让收藏夹主题变成可检索的标签。

## 2. 口径（用户已确认 2026-11-24）

1. **映射按收藏夹名存**：首次「获取我的收藏」前就能在管理页预配置（不依赖尚未建立的合集行）。
2. **未配置的夹**：首次同步按同名建标签并打上，同时 `needs_confirm=True` 进入「待确认」；
   用户在管理页确认/改名/改指/跳过后落定。
3. **快照语义**：作品从收藏夹移出后标签保留，不自动摘除。
4. **可更改**：默认改映射目标；必要时可重命名全局标签，但必须显示影响面并二次确认。
5. 任何模糊点都**给选项**，不静默决定：待确认列表、名称冲突三选一、改名影响确认。

## 3. 数据模型

新表 `douyin_folder_tag_map`（迁移 `e5f6a7b8c9d1`）：

| 列 | 说明 |
| --- | --- |
| `folder_name` | 抖音收藏夹名，唯一（映射主键；同步前就存在） |
| `tag_id` | 目标大标签；标签被删时 `SET NULL`，映射降级为待处理 |
| `mode` | `tag` 已指定 / `skip` 明确不打 / `pending` 待处理 |
| `needs_confirm` | 首次同步自动建标签后为 true（管理页高亮「待确认」） |
| `created_at` / `updated_at` | UTC |

关联来源写入 `inspiration_tags.source='collection'`：重新分析只清 `ai_generated`，不会误删收藏夹打标。

## 4. 同步流程（`task_runners/f2_finalize.py`）

每个收藏夹归位（`add_inspirations`）后：

1. 按收藏夹名查映射：
   - `tag` → 对该夹**全部当前成员**打标（`batch_add_tags`，幂等 `INSERT OR IGNORE`，500/批）；
   - `skip` → 跳过；
   - 无映射 → 同名建穿搭大标签 + 打标 + `needs_confirm=True`；同名已被其它类别占用时
     不建关联，行置 `pending`（返回 conflict，写入同步 notice）。
2. 「未分类收藏」兜底夹不自动映射（避免给大批素材打上无意义大标签）。
3. 打标失败只记 warning，不影响入库与合集归位（`folder_stats[].tag` 记录结果）。

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/douyin-folder-tags` | 映射总览（含本地抖音夹与 f2 已扫描到的夹名，可预配置） |
| POST | `/api/admin/douyin-folder-tags` | 新建/更新映射；同名类别冲突返回 409 |
| DELETE | `/api/admin/douyin-folder-tags/{folder_name}` | 删除映射（回到待处理；已打标签保留） |
| POST | `/api/admin/douyin-folder-tags/{folder_name}/apply` | 按当前成员重打单个夹 |
| POST | `/api/admin/douyin-folder-tags/apply-all` | 全量重打已映射的夹 |
| GET | `/api/admin/douyin-folder-tags/tag-impact/{tag_id}` | 改名/改类别前的影响面（引用素材数 + 映射夹） |

POST body：`{folder_name, mode, tag_id?, new_tag_name?, reuse_existing_category?}`。

## 6. 管理页交互（数据治理 → 抖音收藏夹标签）

- 列表三态：已映射 / 待确认 / 已跳过；顶部提示待确认数量；
- 「设置标签」四选一：按同名新建 / 新建一个大标签 / 选择已有大标签 / 暂不映射；
- 名称冲突弹三选一：**复用并改为穿搭大标签** / **另起一个名称** / **跳过此收藏夹**；
- 「改名」：先调影响面接口，展示引用素材数与映射夹，勾选「我确认会影响所有引用此标签的素材」
  后才可提交（走既有 `PATCH /api/tags/{id}`）；
- 「重打」「立即重打全部」：带二次确认，幂等。

## 7. 边界与已知风险

- 标签名全局唯一且类别只在创建时写：同名标签已属其它类别**不自动复用**（409 → 三选一）。
- 建标签会走别名归一化（如「纯白」→「白色」），冲突提示展示最终生效名。
- 快照语义：移出收藏夹不摘标签；需要反映当前成员时用「重打」（只补不删）。
- 打标会登记文本向量回填（标签影响语义检索），大批量时由攒批任务统一执行。
- 抖音侧改收藏夹名：旧名映射保留，新名首次同步进入待确认，可手动继承旧映射。
- **已知取舍（2026-11-24 决定，保持现状）**：`routers/folder_tags.py` 的 6 个端点
  `db` 参数未加 `AsyncSession` 注解，与 CLAUDE.md「类型注解必须」不一致。原因是
  架构棘轮 `test_router_db_coupling_ratchet` 的基线固定为 23 个「router 直接 import
  数据层」的文件、不允许新增；补注解会让该门禁变红。所有 SQL/ORM 逻辑都在
  `folder_tag_service`，router 只做参数校验与 HTTP 转译。后续若要补注解，需先评审
  并调整棘轮基线，而不是单点绕过。
