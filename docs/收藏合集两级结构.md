# 收藏合集两级结构（系统入库 / 抖音入库）

> 2026-09 改造。起因：任务 `#370` 把 4970 件抖音收藏全量导入，结果 **0 件入库**
> （`no such table: inspirations`），而唯一的扁平合集「抖音收藏」里只有 31 条——
> 那 31 条恰好是「本来就在库里、无需重新入库」的素材。用户口径：收藏夹只该有两类，
> 一级是系统入库手动收藏 / 抖音入库自动收藏，二级才是抖音上那些真正的收藏夹。

## 一、结构

```
一级：系统入库手动收藏          ← 智能合集 {is_favorite: true}，随「收藏」按钮自动同步
一级：抖音入库自动收藏          ← 自动合集（auto_source=douyin），同时汇总收藏全集
   └─ 二级：穿搭 / 秘书OL / 股票 …  ← 名字与抖音侧收藏夹一一对应，随同步自动建立
```

- **一级①「系统入库手动收藏」**：智能合集，成员按 `inspirations.is_favorite`
  动态求值。选它是因为「手动收藏」在本项目里早就是「素材卡片上的收藏按钮」，
  再建一个手动合集等于让人维护两份状态。不需要同步逻辑，永不落伍。
- **一级②「抖音入库自动收藏」**：`auto_source='douyin'` 的自动合集。它**同时汇总
  全部收藏作品**（点进去就是收藏全集），二级只是同批作品的细分归属——分了二级反而
  看不到总数，是这次要避免的另一种坏体验。
- **二级**：`parent_id` 指向一级②，名字取自抖音收藏夹名。

约束：

| 规则 | 落点 |
| --- | --- |
| 最多两级（二级不能当父） | `collection_service._validate_parent` |
| 重名按**同层**判定（二级「穿搭」可与用户自建「穿搭」并存） | 两个部分唯一索引 `uq_collections_root_name` / `uq_collections_child_name` |
| 自动合集禁止改名（改名会让下次同步按原名再建一个） | `collection_service.update_collection` |
| 删父合集连带删二级 | `collection_service.delete_collection`（显式删，不依赖 DB 级联） |
| 两个一级节点必然存在 | 迁移 + 启动钩子 `ensure_root_collections` |

## 二、二级归属从哪来

按夹下载时 `folderize=False`，文件**平铺**在 `{我的昵称}/` 下，路径里**不带收藏夹名**
（这是既有约定：扫描/入库/跨模式合并都只认这一层）。所以归属必须额外记录：

- 下载阶段（`scripts/f2_collects.py`）边枚举边把 `作品 ID` 记到当前收藏夹名下，
  收尾写 `{我的昵称}/_collect_folders.json`（多次运行取**并集**，中断/限量/只勾部分夹
  都不会抹掉已有归属）；
- 入库阶段（`task_runners/f2_import.py` 的 `load_collect_folder_map`）读这份清单，
  把「作品 ID → 收藏夹名」还原成库内素材 ID，逐个建二级并归位。

没有归属信息的作品（平铺 `-M collection` 下载、清单缺失、清单里没记到的）**只进一级
节点**——宁可少一层细分，也不猜一个收藏夹名。

## 三、去重口径（为什么不会越跑越大）

判重始终在**素材库**侧完成，共五层（见 `scripts/f2_plan.py`）：内容 SHA-256、
垃圾桶、批次内重复、合成平台 ID（`f2:<作品 ID>#<类型><序号>`）、参数过滤。
按夹下载还额外做两道「下载前就知道不用下」的过滤：库内已有作品整件跳过、
like/collection 之间同名分段硬链接。

⚠ **这套判重曾整体失效**：`library_db_path()` 原先是
`settings.storage_root.parent / "fashion_inspo.db"`，只在「库文件恰好在 storage 上一级」
时成立。本项目 `STORAGE_ROOT=G:/fashion-inspo-storage`，于是算出 `G:\fashion_inspo.db`
——一个空库：判重读空库（全部作品都「库里没有」）、入库写空库（整批报
`no such table: inspirations`）。现在库路径只有**一个口径**：
`Settings.db_file_path`（由 `DATABASE_URL` 推导），并有用例锁死。

实测（修复后，对真实库）：`E:\f2-downloads\douyin\collection` 里 4988 个文件 /
1518 个作品，其中 **8 个已在库、1510 个是新作品**——判重已经看得见素材库。

| 模块 | 职责 |

| `backend/app/models/collection.py` | `parent_id` / `auto_source`、同层唯一索引、一级名字常量 |
| `backend/app/services/collection_service.py` | 两级 CRUD、同层重名、自动合集只读名、`ensure_root_collections` |
| `backend/alembic/versions/a7b8c9d0e1f2_*.py` | 加列/换索引/建两个一级/删旧扁平自动合集（可重入） |

| `backend/app/services/task_runners/f2_import.py` | 读清单 → 两级归位（阶段 3c） |
| `web/src/views/CollectionsView.vue` | 两级列表（可折叠）、面包屑、二级新建入口 |
