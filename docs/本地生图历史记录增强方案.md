# 本地生图历史记录增强方案

> 目标：把「生成历史」从**参数台账**变成**可回看的作品集**——看得见图、找得到、记得住、
> 知道哪批入过库。本文只做方案，不动代码。
>
> 数据基线：2026-10-27 实测本库（80 个批次 / 188 张候选），SQL 见附录 A。

## 0. 一句话结论

现在历史能重跑、能删，但**看不到图**（7 天后图被清理、只留参数）、**只能看最近 20 条**
（攒到 80 条已有 60 条不可见）、**不知道哪批入过库**（10 批已入库但列表无标识）、
**没法标注**（好的一批 7 天后和记忆一起消失）。这四件事按顺序补齐，收益最大且都不动生成主链。

## 1. 现状盘点

### 1.1 数据模型（`generation_runs`）

| 字段 | 含义 | 现状 |
|---|---|---|
| `kind` | t2i / i2i | 实测 80/80 都是 i2i |
| `status` | queued/running/waiting_vram/done/failed/cancelled | 实测 80/80 都是 done |
| `prompt` / `negative` | 描述与负向词 | 完整保存 |
| `params_json` | 尺寸/步数/cfg/sampler 等原始参数快照 | 平均 315 字节 |
| `model_key` / `workflow_name` / `workflow_hash` | 档位与模板指纹 | 79/80 是 `qwen_2_1_uc_i2i` |
| `reference_ids` | i2i 参考素材 id（JSON 数组） | 80/80 非空 |
| `batch_dir` | 候选图目录（相对 storage_root） | 80/80 非空 |
| `total` / `done` / `failed` | 本批张数与进度 | 合计 188 张，失败 0 |
| `error` | 失败原因 | 当前 0 条 |
| `created_at` / `updated_at` | 创建 / 最后更新 | 2026-10-23 → 10-27 |

**没有**的字段：收藏、命名、备注、耗时、入库张数（需 join 算）。

### 1.2 落盘与保留策略

- 候选图落 `storage/generated/<run_id>/NN_seed-XXXXXX.png`，**文件名编码 seed**，
  因此「单张复现」不需要 per-image 表。
- 保留期 `settings.image_gen_keep_candidates_days = 7`：**启动时**（`main.py` 生命周期）
  调 `cleanup_expired_runs` 删过期目录，**但保留 DB 行**——历史仍在，图不在地上了。
- 实测：80/80 目录仍在（都创建于最近 4 天）；共 **188 张 / 302 MB**（约 1.6 MB/张）。
- 按当前节奏（4 天 188 张 ≈ 47 张/天）推算，7 天保留期的稳态占用 ≈ **0.5 GB**。

### 1.3 现有接口

| 接口 | 用途 | 现状限制 |
|---|---|---|
| `GET /generate/runs?limit=` | 历史列表 | **只有上限 20、无分页/筛选/搜索**；prompt 全量返回 |
| `GET /generate/runs/{id}` | 候选详情 + 是否已入库 | 判定入库要**逐文件算 SHA-256**（实测 8 ms/张、1.74 MB/张） |
| `POST /runs/{id}/confirm` | 勾选入库 | 载荷是 `filenames`，天然支持「从历史入库」 |
| `POST /runs/{id}/retry` | 同参重跑（可指定 seed） | 只能整批复制，改参数要回左侧面板重填 |
| `POST /runs/{id}/regenerate` | 单张重生成 | 仅候选区可用 |
| `POST /runs/cleanup` | 手动清理过期目录 | 只按天数，不能排除某些批次 |
| `DELETE /runs/{id}` | 删批次（清目录、删行、不删已入库素材） | 运行中会 400 拒绝 |

### 1.4 前端结构

- `GenerateView` 的历史区**默认收起**（懒加载 + 脏标记，收起时不发请求）——这是刻意的，
  出图页主线是「填参数 → 生成 → 入库」，历史只是偶发需求。
- `GenerateHistoryTable` 列：`# / 描述（省略号+tooltip）/ 模型 / 状态 / 时间 / 操作（同参重跑、删除）`。
- 展开行：完整描述、负面词、参数 chips（尺寸/步数/CFG/采样器/调度器/seed/张数/参考张数）、
  失败原因、meta（工作流、创建与更新时间）、复制描述。
- **没有缩略图列、没有入库标识、没有筛选与分页**。

### 1.5 数据家底（实测）

| 指标 | 实测值 |
|---|---|
| 批次数 | 80（全部 done、全部 i2i） |
| 候选图 | 188 张（2.35 张/批） |
| 已入库 | **10 张 / 10 个批次（5.3%）** |
| 批次耗时 | 中位 **49.1 s**、均值 56.8 s、最大 405.3 s |
| prompt 去重 | 69 独特 / 80 条（最多一条重复 3 次） |
| 参考素材 | 独立 28 张、被引用 80 次（有 3 张各被用 7 次） |
| 磁盘占用 | 302 MB（7 天稳态 ≈ 0.5 GB） |

## 2. 四个真问题（用户视角）

1. **看不到图**：清理后历史只剩参数。想核对「上次那种袖子的效果」时，连是不是这一批都无法确认。
2. **找不到**：只有最近 20 条、无筛选搜索。已积 80 条 → **60 条在列表外**；「上周那个改了领口的」只能靠翻。
3. **不知道哪批用过**：10 个批次已入库，但列表里没有任何标识 → 容易重复入库，或找不到「入库的是哪张」。
4. **记不住**：不能命名/收藏/备注。好的一批 7 天后图被清、评论也没地方写；
   而「同参重跑」只能整批复制，想只改 seed 或多给一张参考图得重填整个表单。

## 3. 增强项

### P0（1 周内，收益最大）

#### A1 列表带缩略图 + 已入库张数

- **关键约束（实测）**：候选图是 **1.6 MB 的 1024² PNG**，直接把原图塞进列表
  （20 行 × 2.35 张）≈ 75 MB，不可接受；而且**不能**在列表里复用 `GET /runs/{id}`——
  它为了判「是否已入库」会逐文件算 SHA-256，实测 **8 ms/张**，20 条列表会多 300+ ms。
- **方案**：
  1. 后端新增 **缩略图生成**（Pillow 已有依赖）：首次请求时把 256px JPEG 落到
     `generated/<run_id>/.thumbs/<filename>.jpg` 并缓存——**实测首张 148 ms / 6 KB**，
     命中缓存后 0.1 ms（预估的 8~15 ms 太乐观：1024² PNG 解码本身就要 100 ms 量级）；
     接口 `GET /runs/{id}/candidates/{filename}?w=256`（默认返回原图，保持兼容）。
  2. `recent_runs` 多返回两个字段：
     - `candidates: [{filename, thumb_url}]`（最多前 4 张，**不算哈希**）；
     - `imported_count`：一条聚合 SQL 按 `inspirations.generation_run_id` 统计（实测 10 行，毫秒级）。
     - `files_missing: bool`：**终态且目录不存在**才算「图已清理」——排队/生成中的批次目录还没建，
       不能显示成已清理（复审时发现原判据 `not candidates` 会冤枉它们，已修）。
- **前端**：表格加一列 96px 缩略图（`loading="lazy"`）；目录已清显示灰块 +「图已清理」；
  「已入库 N 张」做成可点 chip（见 B5）。
- **成本**：**S**（后端缩略图 + 两个字段；前端一列）。
- **验收**：目录存在时首屏每行有图；`GET /runs?size=20` **实测 p95 30.8 ms**（门槛 150 ms；
  含 20 次目录列举与一条聚合 SQL，均在线程池里）；
  已清理的批次显示占位而不是破图。

#### A2 分页 + 筛选 + 搜索

- **接口**：`GET /generate/runs` 扩展查询参数
  `page`（默认 1）、`size`（默认 20，上限 100）、`kind`、`model_key`、`status`、
  `has_imported`（true/false）、`q`（prompt 关键字，`LIKE`）、`reference_id`（精确匹配 JSON 内含）、
  `since` / `until`（日期）。返回 `{items, total, page, size}`。
- **前端**：历史区顶部工具栏——档位下拉、状态下拉、「只看已入库」开关、日期范围、
  关键字输入（**300 ms 防抖**，与参考图缩略图同一套 `useReferenceItems` 思路）；
  表格改为服务端分页（`total` 来自接口，不再 `history.length`）。
- **成本**：**M**（接口 + 工具栏 + 分页状态；注意「收起时脏标记」逻辑要兼容筛选变更）。
- **验收**：80 条可翻完；三组筛选结果与附录 A 的 SQL 完全一致（档位 / 已入库 / 关键字）。

#### A3 展开看全部候选 + 从历史入库

- **接口**：复用 `GET /runs/{id}`（已返回 filename/seed/imported/url），**不改**。
- **交互**：展开行内渲染候选网格（缩略图 + seed + 已入库角标），勾选后走
  `POST /runs/{id}/confirm`（载荷就是 `filenames`，接口天生支持）→ 入库成功后刷新该行。
- **成本**：**M**（展开行组件 + 勾选态 + 入库后的行内刷新）。
- **验收**：从历史入库张数与 `inspirations` 增量一致；已入库的图不能重复入库（后端已按哈希去重）。

### P1（2~3 天）

#### B1 收藏 / 命名 / 备注（含清理豁免）

- **迁移**：`generation_runs` 加 `favorite BOOLEAN NOT NULL DEFAULT 0`、
  `title VARCHAR(64) NULL`、`note TEXT NULL`。
- **清理**：`cleanup_expired_runs` 增加 `favorite == False` 条件；UI 在历史区显示
  「收藏占用 N MB」，并给「收藏的批次不自动清理」提示（不做硬上限，避免误伤）。
- **成本**：**M**（迁移 + 接口 patch + 行内编辑）。
- **风险**：收藏滥用导致磁盘只增不减 → 用「占用可视化 + 可手动删除」兜底，不加限制。

#### B2 保留期可视化

- 列表行显示「图还剩 N 天」（`created_at + keep_days - now`）或「图已清理」；
  设置页可改 `image_gen_keep_candidates_days`（已有配置，只需前端入口）。
- **成本**：**S**。

#### B3 统计卡（近 30 天）

- **接口**：`GET /generate/runs/stats?days=30` → `{runs, images, imported_images, import_rate,
  avg_duration_s, failure_rate, by_model: [{model_key, runs, images}]}`。
  耗时取 `updated_at - created_at`（已够用，实测中位 49 s；精确耗时需 task 表 join，见风险）。
- **前端**：历史区顶部一行 4 个数字 + 档位分布条。
- **成本**：**M**。

#### B4 一键复现到表单（与「同参重跑」并存）

- **交互**：行内新增「带入表单」：把 prompt / negative / params / 参考图 id 填进左侧面板，
  **不直接生成**——用户可以先改 seed、加一张参考图，再点生成。
- 现成的「同参重跑」保留（一键直接跑）。
- **成本**：**S/M**（复用面板的 `initialRefIds` / `initialModelKey` 通道，需新增「带入参数」入口）。

#### B5 已入库反查

- 行内「已入库 N 张」点击 → 跳素材库并带上 `generation_run_id` 筛选。
- 需要素材列表接口加一个 `generation_run_id` 参数（当前没有）。
- **成本**：**S**。

### P2（可选，价值更长期）

| 编号 | 内容 | 成本 | 说明 |
|---|---|---|---|
| C1 | 两批并排对比 | M | 复用对比弹窗，左批 vs 右批 |
| C2 | 导出历史（CSV / JSON） | S | 参数台账导出给外部复盘 |
| C3 | 自动命名（LLM 概括 prompt → 标题） | M | 需兜底：模型不可用时退回截断 prompt |
| C4 | 按参考素材聚合（「这张参考图生成过哪些」） | M | 实测 3 张参考图各被用 7 次，确有需求 |

## 4. 明确不做 / 暂缓（附理由）

| 不做 | 理由 |
|---|---|
| per-image 数据表 | 文件名已编码 seed，`imported` 用内容哈希判定；加表是重复存储 |
| 候选图全部入素材库 | 「确认入库」就是质量闸门；自动全入会把未筛选的图污染素材库 |
| 历史图永久保留 | 302 MB → 1.6 MB/张线性增长；7 天保留是克制设计，改由「收藏」显式延期 |
| 云端同步 / 多端历史 | 本地单机工具，素材与模型都在本机 |
| 删批次时连带删已入库素材 | 素材已独立（`generation_run_id` 是 SET NULL）——删历史不该动作品 |

## 5. 分期与验收

| 阶段 | 范围 | 验收口径 |
|---|---|---|
| P0 | A1 + A2 + A3 | ① 目录存在时首屏每行有图，接口 p95 < 150 ms；② 80 条可翻完，三组筛选结果与附录 A SQL 一致；③ 展开行能看全部候选并入库，入库张数与 `inspirations` 增量一致 |
| P1 | B1 + B2 + B3 + B4 + B5 | ① 收藏的批次过了保留期图仍在、且不参与自动清理；② 行内显示剩余天数/已清理；③ 统计卡 4 个数字与 SQL 一致（附对照）；④「带入表单」后左侧面板字段与历史一致；⑤「已入库 N 张」跳转后素材数为 N |
| P2 | C1~C4 | 按需立项，各自单条验收 |

## 6. 依赖与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 缩略图请求数 | 20 行 × 4 张 = 80 个请求 | `.thumbs` 缓存 + `loading="lazy"` + 256px JPEG（实测 **6 KB/张**） |
| 缩略图生成阻塞 | 首次每张约 **148 ms**（解码 1024² PNG） | 放 `asyncio.to_thread` + `loading="lazy"`（浏览器只并发几个）+ 缓存命中 0.1 ms；单批最多 4 张 |
| 入库判定成本 | 列表若算哈希会 +300 ms | 列表只给 `imported_count`（聚合 SQL），逐张 `imported` 只在详情里算 |
| 收藏有效期失控 | 磁盘只增不减 | 显示收藏占用、支持手动删、不设硬上限（避免误伤） |
| 耗时口径 | `updated_at - created_at` 含排队等待 | 文案写「批次耗时（含排队）」，精确耗时需 join `task_queue`（暂不做） |
| 老数据 | 新字段为空 | `favorite` 默认 0；`title`/`note` 为空即按 prompt 前 40 字展示 |

## 附录 A：可复现 SQL

```sql
-- 批次总览与耗时（中位/均值在代码里算）
select count(*) as runs, sum(total) as images, sum(done) as done, sum(failed) as failed
from generation_runs;

-- 已入库张数（按批次）—— A1 的 imported_count 就这一条聚合
select generation_run_id, count(*) as imported
from inspirations
where generation_run_id is not null
group by generation_run_id;

-- 入库率
select
  (select count(*) from inspirations where generation_run_id is not null) * 1.0
  / (select sum(total) from generation_runs) as import_rate;   -- 实测 10/188 = 5.3%

-- 档位分布
select model_key, count(*) from generation_runs group by 1 order by 2 desc;

-- 磁盘占用（需在 Python/脚本里读文件大小；这里只给目录来源）
select id, batch_dir from generation_runs where batch_dir <> '';

-- 筛选对照（A2 验收用）
select count(*) from generation_runs where model_key = 'qwen_2_1_uc_i2i';      -- 79
select count(distinct r.id) from generation_runs r
  join inspirations i on i.generation_run_id = r.id;                            -- 10
select count(*) from generation_runs where prompt like '%领口%';                -- 关键字示例
```
