## 前端：死代码（ts-prune + 基线，已接入）

```bash
node scripts/check-web-dead-code.mjs   # 只拦新增：出现基线里没有的条目才以 1 退出
```

- **为什么不用 knip**：本仓库 `npm i -D knip` 后运行即报 `Cannot find native binding`（npm 可选依赖
  的已知 bug），修复需删除 `node_modules` + `package-lock.json` 重装，破坏性太大，故放弃。
- **为什么用 ts-prune**：单文件脚本、无原生依赖，覆盖「未使用导出」；报告里 `(used in module)`
  与 `shared/types/*`（与 mobile 的 React Native 侧共用）属已知误报。
- **基线**：`scripts/tsprune-baseline.txt`（268 条，2026-10 快照）。门禁语义是**只拦新增**。
- 路径归一化按**仓库目录名截断**（ts-prune 混用绝对路径与「相对 web/」，按目录名切最稳）。
- 自检：临时加 `export function __deadCodeProbe()` 应被拦下，删除后应恢复通过（已验证）。

`eslint src` 的 73 条均为 **warning**（0 error），已用 `--max-warnings 73` 上棘轮：数量只能降不能升。
逐类原因与处理计划：

| 规则 | 数量 | 原因 / 计划 |
| ------ | ------ | ------ |
| `@typescript-eslint/no-unused-vars` | 39 | **可安全修**：多为遗留未使用导入。计划按文件逐个删（需 `vue-tsc` 兜底，避免误删类型导入）；本轮未做，列为本文件记录的第一优先项 |

## 结构性欠账：两个巨型文件的拆分进度（2026-10-20）

| 文件 | 原始 | 当前 | 已拆出的模块 |
| ------ | ------ | ------ | ------ |
| `app/services/crop_service.py` | 1238 | 1059 | `crop_candidates.py`（候选裁决 + 分页游标）、`crop_vlm.py`（VLM 复核层） |
| `app/services/task_runners/f2_import.py` | 2005 | 1932 | `f2_library_ids.py`（库内作品 ID 索引） |

拆分方法（每一步都不能省）：

1. 函数体**原样搬移**（含注释与文档字符串，只改归属模块）；
2. 原文件以**同名再导出**（`# noqa: E402, F401` 并注明理由），既有调用方与测试无需改动；
3. 跑全量 `pytest` + `ruff check app` + 漂移门禁；
4. 独立提交（一个切片一条历史，便于 bisect）。

只选**自包含**切片：若新模块与原模块互相 import 会成环，必须**先**抽共享助手（路径解析、VLM 调用等）
再抽主体。这也是 `crop_scan.py` 排在最后的原因。

剩余切片（边界已定，按自包含度从高到低）：

- `f2_import.py` **B**：任务创建/调度（`create_f2_import_task` … `get_f2_auto_status`，约 460 行）
  连同 `_append_notice`/`_brief_reason` 一起搬 → `f2_task.py`
- `f2_import.py` **D**：取数阶段（`_fetch_personal_stage` … `_resolve_named_profile_keys`，约 530 行）→ `f2_fetch_stages.py`
- `f2_import.py` **E**：规划与入库（`_scan_and_plan_stage` / `_apply_import_stage` /
  `_register_personal_bloggers_stage`，约 200 行）→ `f2_plan_apply.py`
- `f2_import.py` **F**：聚合与收尾（`_aggregate_collect_stage` / `_finalize_import`，约 170 行）→ `f2_finalize.py`
- `crop_service.py`：候选扫描（`scan_candidates` / `_scan_one_candidate`，约 340 行）→ `crop_scan.py`
  （该片**需先**抽共享助手，否则成环）

验收标准：每次拆分后 `f2_import.py` / `crop_service.py` 的行数应单调下降，且
`pytest`、`ruff`、漂移门禁三者全绿。
