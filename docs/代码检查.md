# 代码检查（死代码 / 静态分析）

## 后端：死代码（vulture）

```bash
cd backend
pip install -r requirements-dev.txt        # 含 vulture
python -m vulture app --min-confidence 80  # 必须 0 条
```

- **门禁口径**：`--min-confidence 80` 下必须 **0 条**（2026-10 已清零）。
- 确实需要保留但被误报的符号（FastAPI 装饰器注册、Pydantic 回调、框架约定参数等），
  用 `python -m vulture app --min-confidence 80 --make-whitelist > vulture_whitelist.py`
  生成基线，然后跑 `python -m vulture app vulture_whitelist.py --min-confidence 80`。
  **只往白名单里加「确认要保留」的项**，不要为了过门禁而整批加进去。
- 本轮清理掉的 4 条真实死代码：`database.py` 未用的回调参数、`inspiration_create.py` 两个
  未用 import、`tag_batch_edit.py::_format_preview` 未使用的 `tags_by_id` 参数。

## 前端：死代码（ts-prune + 基线，已接入）

```bash
node scripts/check-web-dead-code.mjs   # 只拦新增：出现基线里没有的条目才以 1 退出
```

- **为什么不用 knip**：本仓库 `npm i -D knip` 后运行即报 `Cannot find native binding`（npm 可选依赖
  的已知 bug），修复需删除 `node_modules` + `package-lock.json` 重装，破坏性太大，故放弃。
- **为什么用 ts-prune**：单文件脚本、无原生依赖，覆盖「未使用导出」；报告里 `(used in module)`
  与 `shared/types/*`（与 mobile 的 React Native 侧共用）属已知误报。
- **基线**：`scripts/tsprune-baseline.txt`（268 条，2026-10 快照）。门禁语义是**只拦新增**。
- 路径归一化按**仓库目录名截断**（ts-prune 混用绝对路径与「相对 web/」，按目录名切最稳）。
- 自检：临时加 `export function __deadCodeProbe()` 应被拦下，删除后应恢复通过（已验证）。
