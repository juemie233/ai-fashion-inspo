# SQLite 数据库容量评估

> 评估日期：2026-08-13
> 数据库：`backend/fashion_inspo.db`（SQLite + SQLAlchemy async + aiosqlite）

## 一、当前状态

| 指标 | 数值 |
|------|------|
| 数据库文件 | 3.69 MB（945 页 × 4KB） |
| 素材 `inspirations` | 993 行 |
| 标签 `tags` | 1,687 行 |
| 标签关联 `inspiration_tags` | 14,028 行（平均每素材 14.1 个标签） |
| 分析日志 `ai_analysis_log` | 1,039 行（`raw_response` 平均 599 字节，最大 3.2KB） |
| 已抓取 URL `scraper_seen_urls` | 814 行 |
| journal 模式 | `delete`（回滚日志，非 WAL） |

各表数据体积估算：

| 表 | 数据字节 | 说明 |
|----|---------|------|
| `ai_analysis_log` | ≈ 665 KB | 每次分析/重试各写一条，含完整模型输出 |
| `inspiration_tags` | ≈ 571 KB | 多对多关联，比素材本身增长快约 14 倍 |
| `inspirations` | ≈ 268 KB | 素材主表 |
| `scraper_seen_urls` | ≈ 129 KB | 采集去重集合 |
| `tags` | ≈ 74 KB | 标签字典 |

数据集中在近 2 天（08-11 ~ 08-13），增速约 **500 素材/天**。

## 二、每条素材的边际成本

约 **3–4 KB/素材**（含索引），大头是两个线性增长的关联表：

- `ai_analysis_log`：每次分析各写一条，重试会叠加；
- `inspiration_tags`：14.1 条关联/素材，增长快于素材主表。

## 三、三个独立的「撑不住」阈值

SQLite 的瓶颈**不是文件大小**，而是下面三项，按先后顺序：

### 1. 存储容量 —— 最不用担心

SQLite 硬上限 281 TB，实际几十 GB 内都流畅。

| 素材量 | 预计文件 |
|--------|---------|
| 1 万 | ~37 MB |
| 10 万 | ~370 MB |
| 100 万 | ~3.7 GB（开始偏重，备份/VACUUM 变慢）|
| 1000 万 | ~37 GB（不推荐）|

存储层面，**100 万素材以内 SQLite 都扛得住**。

### 2. 并发写入 —— 真正的天花板，且比大小先到 ⚠️

SQLite 是**单写者**：同一时刻只允许一个写事务。当前配置：

- `journal_mode = delete`：写事务期间连读都全部阻塞；
- 后台有并发写者：AI 分析（信号量 ~16 并发，每条写日志 + 标签）、采集器批量插入、用户上传/打标签，都在抢同一把写锁；
- `timeout=30` 秒，抢不到锁直接报 `database is locked`。

**这一项随「并发写负载」而非「数据量」退化。** 提高分析并发、或加快采集速度，现在就可能触发。

### 3. 查询性能 —— 随数据量退化

- **按标签筛选**：`inspiration_tags` 只有复合主键索引 `(inspiration_id, tag_id)`，缺少单独的 `tag_id` 索引 → 「查找包含某标签的所有素材」走全索引扫描，关联表到 ~50 万行时明显变慢（当前 1.4 万）；
- **分页** `ORDER BY created_at DESC LIMIT/OFFSET`：深分页在 10 万+ 行后变慢；
- **`LIKE '%关键词%'`**：全表扫描，10 万行后变慢，且未启用 FTS5 全文索引。

## 四、结论

| 阶段 | 素材量 | 状态 |
|------|--------|------|
| 现在 | ~1000 | ✅ 毫无压力 |
| 个人长期使用 | 1 万 ~ 10 万 | ✅ 舒适，但建议先开 WAL |
| 临界区 | 50 万 ~ 100 万 | ⚠️ 查询/并发开始有感知，需补索引 + WAL |
| 该换 PostgreSQL | 100 万+ 或多用户/高并发写 | ❌ 换库 |

**最先咬人的不是「素材数量」，而是「并发写」。**

## 五、建议（按优先级）

1. **立即（零成本）**：切到 WAL 模式，让读不阻塞写、提升写并发能力。
   在 `backend/app/database.py` 的 connect 事件中加一行：

   ```python
   cursor.execute("PRAGMA journal_mode=WAL")
   ```

2. **素材到几十万量级前**：给 `inspiration_tags.tag_id` 加独立索引，优化「按标签筛选」查询。
3. **素材到 100 万或出现多用户/高并发写**：迁移 PostgreSQL。
