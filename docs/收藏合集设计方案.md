# 收藏合集（Lookbook / Board）设计方案

> 状态：已评审定稿（2026-08-29 与用户确认四项决策：独立新表 / 星标共存 / 自定义拖拽 / 智能合集本期实现）。
> 本文档是实现的唯一依据；TODO 中「收藏合集」条目引用本文档。

## 一、数据模型

```
collections                        合集
├─ id            整型自增主键
├─ name          1~50 字，唯一（重名返回 409）
├─ description   可空
├─ cover_inspiration_id    封面素材 ID（可空；未手动指定时取「加入最早」的一张）
├─ position      合集列表排序（整型，越大越靠后；列表页支持拖拽排序）
├─ query_json    智能合集筛选条件 JSON；手动合集恒为 NULL（智能合集演进预留列）
├─ created_at / updated_at

collection_items                   素材 ↔ 合集（多对多，仅手动合集有行）
├─ collection_id   FK → collections (ON DELETE CASCADE)
├─ inspiration_id  FK → inspirations (ON DELETE CASCADE)  ← 素材物理删除自动出合集
├─ position        合集内自定义顺序（拖拽编排展示顺序）
├─ added_at        加入时间
└─ UNIQUE(collection_id, inspiration_id)
```

**两类合集同表区分**：`query_json IS NULL` = 手动合集（实体成员关系）；`query_json IS NOT NULL` = 智能合集（动态成员，items 表不存它的行）。删除合集：手动 → 级联删 items、素材无损；智能 → 仅删自身，素材无损。

**与 is_favorite 的关系**：共存。星标 = 快速标记（轻量无组织），合集 = 策划整理；列表筛选两者并列。

## 二、智能合集

- **条件模型**：`query_json` 复用素材库现有筛选条件的参数结构（不发明新筛选语言）：

```json
{
  "keyword": "白色衬衫",          // 关键词，可 null
  "tag_ids": [12, 34],           // 标签 ID 列表，可 []
  "tag_mode": "and",             // "and" | "or"
  "source_types": ["xiaohongshu"], // 来源类型列表，可 null（全部）
  "media_type": "image",         // "image" | "video" | null（全部）
  "is_favorite": true,           // true/false/null
  "min_rating": 3,               // 0~5 整数或 null
  "start_date": "2026-08-01",    // 可 null（YYYY-MM-DD）
  "end_date": "2026-08-31"       // 可 null
}
```

- 后端用与素材库同一套查询逻辑动态求值（复用 `inspiration_query` 的筛选构建），保证「素材库怎么筛、合集就怎么算」口径一致；未知键忽略（向前兼容）。
- **标签以 tag_id 存储**：标签被删除后相关条件自动失效（该标签不再匹配），不做级联改写（simplicity 优先，文档明示）。
- **垃圾桶素材一律不在合集内容中出现**（手动/智能均排除 `deleted_at IS NOT NULL`），恢复后自动重现。
- **固化（solidify）**：一键把当前匹配素材按当前位置写入 `collection_items` 并清空 `query_json`，之后可手动增删排序。
- 计数：列表接口对智能合集 `item_count` 返回 null（懒计算），进入合集页才查询精确数——避免每次进列表页全量求值。
- 封面：智能合集默认取动态结果第一张，允许手动指定。

## 三、API 契约

```
GET    /api/collections
       → [{id, name, description, kind: "manual"|"smart", position,
           cover_inspiration_id, cover_thumbnail_path,
           item_count(手动=成员数；智能=null),
           query_json(仅智能), created_at, updated_at}]

POST   /api/collections          {name, description?, query_json?}      重名 409；name 越界 422
PATCH  /api/collections/{id}     {name?, description?, cover_inspiration_id?}
DELETE /api/collections/{id}     删除合集（不动素材）
GET    /api/collections/{id}/inspirations?page=&page_size=
       → {items: [InspirationOut], total}
       手动按 position 升序；智能按 query_json 动态求值（均排除垃圾桶）
POST   /api/collections/{id}/inspirations    {inspiration_ids: [...]}   批量加入；智能合集 400
DELETE /api/collections/{id}/inspirations    {inspiration_ids: [...]}   批量移出；智能合集 400
PATCH  /api/collections/{id}/items/order     {ordered_ids: [...]}       合集内拖拽排序；智能 400
PATCH  /api/collections/order                {ordered_ids: [...]}       合集列表拖拽排序
POST   /api/collections/{id}/solidify        智能转手动（按当前位置固化成员、清 query_json）；手动 400
```

错误约定沿用项目现状：资源不存在 404、重名 409、类型/状态不符 400、参数越界 422。

## 四、前端

- **`/collections` 新路由**（侧边栏「浏览」分组，素材库下方）：左侧合集列表（📁/⚡ 徽标、计数、拖拽排序、新建按钮），右侧瀑布流（复用素材库瀑布流组件）。手动合集支持页内多选移出与拖拽排序；智能合集显示条件摘要 + 「更新为当前筛选条件」+ 「转手动」。
- **加入入口**：素材库批量操作栏「加入合集」（选择器内可现场新建）；详情页「加入合集」下拉。
- **保存为合集入口**：素材库筛选状态下「保存为合集」按钮（创建智能合集，序列化当前筛选为 query_json）。
- 移动端 / 插件本期不动。

## 五、验收标准

1. 素材可同时属于多个手动合集；素材物理删除自动出合集；删除合集不影响素材；
2. 合集内可拖拽编排展示顺序，合集列表可拖拽排序；
3. 素材库任意筛选状态可「保存为合集」生成智能合集，内容随素材库动态变化，可更新条件、可一键转手动；
4. 垃圾桶素材在合集中隐藏，恢复后重现；
5. 导出暂缓。
