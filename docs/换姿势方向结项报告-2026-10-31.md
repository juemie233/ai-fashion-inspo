# 「换姿势 / R2」方向结项报告（失败实验总结 + 收尾方案）

> 决定：**暂停并结束这一轮「换姿势 / R2」的测试与实验**，不再继续投入下载/调参。
> 本文档做三件事：① 把失败实验的结论固化下来（避免以后重复踩坑）；② 列出已投入的资产与可复用部分；
> ③ 给出 Git / 磁盘 / 分支的收尾方案（**推送仍暂停，仅 commit**）。
> 结项时间：2026-10-31。

---

## 1. 一句话结论

**「素材里的人换个姿势、还是她/她那身衣服」这个目标，在 16 GB 显存 + 现有本地模型栈下没有做出可交付方案。**

- 姿势可以准（R2-A lineart 5/5、depth 路线 3.7/5），但代价是**关节圆→护具/服装装饰**、**身份/服装丢失**；
- 身份可以救（换脸 0.81 余弦），但**服装/发型/场景**仍是模型自由生成（通用紧身衣/黑裙）；
- 唯一在社区 2 例里同时保住的组合（Qwen2.1 + Pose Studio LoRA）需要 **BF16 全量权重（20B 级 / 约 40 GB）**，
  我们 int8 权重上 LoRA 会让画面/结构崩坏，**不可行**；
- 继续这个方向需要「分割/局部重绘服装」重工程或换更大显存，投入产出比低，**决定结项**。

## 2. 失败实验清单（按时间）

| 轮次 | 方案 | 结果 | 关键失败原因 |
| --- | --- | --- | --- |
| R1-A | Qwen2.1 多参考图（要素材 + 图库线稿），换姿势 | **姿势不跟随**；线稿关节圆被当内容融合到人物腿上 | Qwen 把线稿当"内容参考"而非控制信号 |
| R1-B | 同 R1-A，换提示词/参考顺序/重复线稿 | 全部更差或失败 | 换人/换装指令和参考图语义冲突 |
| R1-C | 只给文字姿势（不传线稿） | 姿势 **3/5**、身份/服装好、31 s/张 | 姿势只到大体姿态；已放弃（用户要求放弃文生图） |
| R2-A | SDXL + ControlNet-Union **lineart** | 姿势 **5/5**、17.8 s/张 | **关节圆→护具/机甲装饰**；身份丢失（txt2img 必然） |
| R2-A 变体 | img2img 0.7/0.85、hed 类型、强度 0.75、no-armor 提示词 | 均未解决护具；img2img 身份也差 | 控制图本身是素体线稿，模型忠实渲染 |
| R2-C | R2-A 出图 → Qwen 编辑清洗（姿势图在前） | 姿势保留、护具清除、画面干净 | **身份只有 2~3/5**（10 样本实测更差，用户判 0/5） |
| R2-C 10 样本 | 5 素材 × 5 姿势基线（实际 10 素材 × 1 姿势） | 姿势 3.5/5、身份 0.9/5、画面 1.9/5 | 「鬼图」+ 身份完全丢失 |
| A 方案 | R2-C 结果 + InsightFace 换脸 + GFPGAN 修复 | **身份余弦 0.47→0.87**、脸部可辨 | **服装/发型/身材仍不是主体**（只解决 1/3 identity）；s06 无脸素材失败 |
| 换装实验 | 提示词要求「保持第 2 张发型/服装」 | **服装 0/10 保持**；画质更差（颗粒/油彩） | Qwen 编辑把参考图当"长相参考"，服装先验压倒参考 |
| GitHub 调研 | 搜索社区「X + 图库」项目 | 多数 1+1<2；唯一 >2 的组合需 BF16 + Pose LoRA | 见 `docs/GitHub-姿势图库与AI出图结合项目调研.md` |
| P0 | Qwen 英文约束 prompt（无 LoRA / +LoRA） | **身份/服装 5/5 保留，但姿势 0/5**；加 LoRA 后姿势 2/5 + 结构崩坏 | 英文 prompt 解决"换人"，int8 + BF16 LoRA 不兼容；社区结果需 BF16 |
| E3 | **Depth Anything V2 → SDXL depth 控制 → 换脸** | **护具伪影 10/10 消失**、姿势 3.7/5、换脸 0.81、20~25 s/张 | **服装/发型仍是模型生成**；这是目前最好版本，仍差服装一致性 |

## 4. Git 收尾方案（**不推送远程**）

当前状态：

- 分支 `feat/pose-i2i`：比 `master` 多 **20 个提交**（含换姿势功能、一键出图、全部实验文档/脚本），
  落后 3 个 master 提交（README/CLAUDE.md 等文档更新），**已分叉**；
- 远端 `origin/feat/pose-i2i` 停在本地提交的 9 个之前（推送已暂停）；
- 工作区干净（无未提交改动）。

### 4.1 推荐方案（保留成果 → 合并 → 删本地分支）

```bash
# 1) 把功能分支合并进 master（保留换姿势功能 + 所有实验文档）
git checkout master
git merge --no-ff feat/pose-i2i -m "merge: 换姿势（路径一）+ R2 实验复盘文档"
#    若有冲突：以 master 的 CLAUDE.md/README 结构为准，保留本分支新增的 docs 与 scripts/oneoff 实验脚本
# 2) 验证
git status
git log --oneline -3
# 3) 删除本地功能分支（远端分支等用户允许 push 后再删）
git branch -d feat/pose-i2i
```

> 说明：`--no-ff` 保留一条可追溯的合并记录；`-d` 只在已合并时成功，避免误删未合并提交。
> 远端 `origin/feat/pose-i2i` 的删除命令是 `git push origin --delete feat/pose-i2i`，
> 但**推送已暂停，必须等用户明确允许后才能执行**。

### 4.2 备选方案

- **只保留分支、不合并**：以后想继续 R2 时直接切回 `feat/pose-i2i`；`master` 不含实验代码。
- **丢弃实验**：`git checkout master && git branch -D feat/pose-i2i`（会丢 20 个提交，需用户明确确认）。

## 7. 经验教训（下次别再花这些钱）

1. **Qwen-Image-Edit 的图序决定语义**：第 1 张是编辑底图，第 2 张才是"参考内容"；「换姿势」必须姿势图在前，
   但那样身份就会丢——这是模型机制，不是 prompt 能解决的。
2. **cfg=1.0 时负向提示词不生效**（社区与我们都验证），别在负向里堆"no armor"。
3. **DWPose/OpenPose 识别不了素体线稿**（社区 lnyuqian 明确记录），所以"线稿→骨架"路线不成立。
4. **线稿接 lineart ControlNet 必然把关节圆画成服装装饰**（Anima 8 组 + 我们 10 组双重验证），
   要么换深度控制，要么先处理控制图（我们试的 Hough/洪泛去圆不可靠）。
5. **身份与姿势是跷跷板**：img2img 保身份则姿势掉、纯 txt2img 保姿势则身份丢；
   换脸能补脸但补不了衣服/发型/场景。
6. **社区成功案例要核对完整环境**：BF16 vs int8、ComfyUI 版本、LoRA 训练基座，缺一个就复现不了。
7. **实验必须留可读报告 + 对比图 + 量化指标**（本轮已执行），否则下次又从零开始。
8. **先算成本再下载**：本轮模型下载约 10 GiB、GPU 时间数小时；如果先做 2 样本 pilot，可以少走一大半。
