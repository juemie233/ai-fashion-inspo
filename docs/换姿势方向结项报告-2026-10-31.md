# 「换姿势 / R2」方向结项报告（权威总结）

> **状态**：已结项（2026-10-31，权威总结）｜本文是该专题的最终结论，5 份实验报告只作为证据附录。
> **一句话**：在 16 GB 显存 + 现有本地模型栈下，「素材换姿势且保留本人/原服装」没有做出可交付方案，决定结项；
> 已验证的最好组合是 **Depth 姿势 + SDXL depth 控制 + 换脸**（姿势 3.7/5、脸 0.81、约 25 s/张，衣服不保）。

---

## 0. 一页速览

| 项 | 结论 |
| --- | --- |
| 目标 | 素材里的人换成图库里的姿势，同时保持她的脸、服装、发型、身材 |
| 结果 | **失败**（不可交付）；姿势可做准，但身份/服装/画质无法同时保住 |
| 主要原因 | ① 线稿控制信号会带出「关节圆→护具」；② Qwen 编辑的图序机制导致「保姿势就丢身份」；③ 身份与姿势是跷跷板；④ 社区唯一成功组合需要 BF16 全量权重（20B / ~40 GB），本机 int8 跑不动 |
| 最好版本 | **E3**：Depth Anything V2 → SDXL depth 控制（无护具伪影）→ 换脸；姿势 3.7/5、身份 0.81、20~25 s/张；**服装/发型仍是模型生成** |
| 可用定位 | 若产品接受「**换装 + 换姿势**」，E3 链路可交付；若要严格保留原穿搭，还需「分割/局部重绘服装」重工程 |
| 已停在哪 | P0（Qwen 英文 prompt + Pose Studio LoRA）与 F1（Depth 姿势图 → Qwen 编辑）两步未继续：前者 int8+LoRA 崩坏，后者未跑（零下载、最值得重启的一步） |

---

## 1. 结论

「素材里的人换个姿势、还是她/她那身衣服」这个目标，在 **16 GB 显存 + 现有本地模型栈**下没有做出可交付方案：

- **姿势可以准**：R2-A lineart 5/5、E3 depth 3.7/5；但 lineart 必然带出关节圆/护具，depth 则保不住衣服；
- **身份可以救**：换脸余弦 0.81（9/10），但只救脸——**服装、发型、身材、场景**仍是模型自由生成；
- **身份与姿势是跷跷板**：纯 txt2img 保姿势丢身份，img2img 保身份丢姿势；换脸补不了衣服；
- **社区唯一在 2 例里同时保住的组合**（Qwen2.1 + Pose Studio LoRA）需要 **BF16 全量权重（20B 级，约 40 GB）**；
  我们 int8 权重上 LoRA 会让画面/结构崩坏，**不可行**；
- 继续需要「分割/局部重绘服装」重工程或换 24 GB+ 显卡，投入产出比低，**结项**。

## 2. 失败实验时间线（11 轮）

| 轮次 | 方案 | 结果 | 关键失败原因 |
| --- | --- | --- | --- |
| R1-A | Qwen2.1 多参考图（素材 + 图库线稿）换姿势 | **姿势不跟随**；关节圆被当内容融合到人物腿上 | Qwen 把线稿当「内容参考」而非控制信号 |
| R1-B | R1-A 调提示词/参考顺序/重复线稿 | 全部更差或失败 | 「换人/换装」指令与参考图语义冲突 |
| R1-C | 只给文字姿势（不传线稿） | 姿势 3/5、身份/服装好、31 s/张 | 姿势只到大体姿态；用户要求放弃文生图 |
| R2-A | SDXL + ControlNet-Union **lineart** | 姿势 **5/5**、17.8 s/张 | **关节圆→护具/机甲装饰**；txt2img 身份必然丢失 |
| R2-A 变体 | img2img 0.7/0.85、hed、强度 0.75、no-armor 提示词 | 均未解决护具；img2img 身份也差 | 控制图本身是素体线稿，模型忠实渲染 |
| R2-C | R2-A 出图 → Qwen 编辑清洗（姿势图在前） | 姿势保留、护具清除、画面干净 | **身份只剩 2~3/5**（10 样本实测更差，用户判 0/5） |
| R2-C 10 样本 | 10 素材各 1 姿势的基线 | 姿势 3.5/5、身份 0.9/5、画面 1.9/5 | 「鬼图」+ 身份完全丢失 |
| A 方案 | R2-C 结果 + InsightFace 换脸 + GFPGAN 修复 | **身份余弦 0.47→0.87**、脸部可辨 | **服装/发型/身材仍不是主体**；s06 无脸素材失败 |
| 换装实验 | 提示词要求「保持第 2 张发型/服装」 | **服装 0/10 保持**；画质更差（颗粒/油彩） | Qwen 把参考图当「长相参考」，服装先验压倒参考 |
| P0 | Qwen 英文约束 prompt（无 LoRA / +LoRA） | 身份/服装 **5/5** 保留，但姿势 **0/5**；加 LoRA 后姿势 2/5 + 结构崩坏 | 英文 prompt 解决「换人」；int8 + BF16 LoRA 不兼容 |
| E3 | **Depth Anything V2 → SDXL depth 控制 → 换脸** | **护具伪影 10/10 消失**、姿势 3.7/5、换脸 0.81、20~25 s/张 | **服装/发型仍是模型生成**；目前最好版本 |

> 逐样本数据见 §9 证据索引中各实验报告。

## 3. 根因（为什么不是再调参能解决）

1. **控制信号问题**：素体线稿的关节圆是真实的黑色线条，lineart ControlNet 会忠实画成服装装饰；
   换成深度图能消掉线条，但深度只约束轮廓，衣服/细节回到模型自由生成。
2. **Qwen 编辑的图序机制**：第 1 张是编辑底图、第 2 张是内容参考；要它「跟随第 1 张姿势」就会
   把第 1 张的人/衣服/画风一起带过来，要「保留第 2 张的人」就会忽略第 1 张的姿势。这是模型机制，不是 prompt 能修的。
3. **身份与姿势的跷跷板**：txt2img 姿势准但身份随机；img2img 保身份但姿势跟随变弱；
   换脸只能补脸（0.81），补不了发型/服装/身材/场景。
4. **环境差距**：社区唯一成功案例用 Qwen-Image 2.1 **BF16**（20B 级、约 40 GB）+ ComfyUI 0.43；
   本机是 int8 convrot（7.2 GB），LoRA 效果被放大/失真，复现不了。

## 4. 目前最好的可用方案（E3，也是唯一可交付形态）

```text
图库姿势线稿 → Depth Anything V2（99 MB）→ 深度图
→ SDXL + ControlNet-Union depth（strength 0.75，0~50% 步）→ 姿势图
→ InsightFace 换脸（源=主体原图）→ 最终图
```

| 指标 | 数值 |
| --- | --- |
| 护具/关节圆伪影 | **10/10 消失**（对比 lineart 的 10/10 出现） |
| 姿势保真 | 3.7/5（站/跪/坐/扶墙跟随；桥式偏差、俯仰角不保证） |
| 身份余弦 | txt2img -0.081 → 换脸 **0.814**（9/10；无脸素材失败） |
| 服装/发型/场景 | **未保持**（模型生成通用紧身衣/黑裙） |
| 速度 | 深度图 ~1 s + SDXL 15~25 s + 换脸 ~3 s ≈ **20~25 s/张** |

**适用边界**：适合「同一个人的脸 + 新姿势 + 新穿搭」的批量出图；不适合「严格保留素材原穿搭」的换姿势。
若以后产品定位是前者，E3 已是可交付链路；若要后者，见 §7 的服装路线。

## 8. 经验教训（下次别再花这些钱）

1. **Qwen-Image-Edit 的图序决定语义**：第 1 张是编辑底图，第 2 张才是内容参考；换姿势必须姿势图在前，但那会丢身份。
2. **cfg=1.0 时负向提示词不生效**（社区与我们都验证），别在负向里堆 "no armor"。
3. **DWPose/OpenPose 识别不了素体线稿**（社区 lnyuqian 记录），「线稿→骨架」路线不成立。
4. **线稿接 lineart ControlNet 必然把关节圆画成服装装饰**（Anima 8 组 + 我们 10 组双重验证）；
   换深度能消除线条，但保不住衣服。
5. **身份与姿势是跷跷板**：img2img 保身份则姿势掉、纯 txt2img 保姿势则身份丢；换脸补不了衣服。
6. **社区成功案例要核对完整环境**：BF16 vs int8、ComfyUI 版本、LoRA 训练基座，缺一个就复现不了。
7. **实验必须留可读报告 + 对比图 + 量化指标**，否则下次从零开始。
8. **先算成本再下载**：本轮下载约 10 GiB、GPU 数小时；先跑 2 样本 pilot 可以少走一大半。
