# Web 端功能移植到手机：可行性判定与方案

> 编写时间：2026-10-24 ｜ 基线：Web 19 个页面 / 后端 24 个路由模块；手机端 4 个 tab（素材库 / 搜索 / 采集 / 设置）+ 详情页
> 手机端现状：浏览、下拉刷新、无限滚动、收藏、**多图上传（逐张进度）**、**详情可编辑（标签/垃圾桶）**、**任务中心**、搜索（关键词）、全屏看图、后端地址配置
> 执行进度：**M2–M5 全部完成**（2026-10-28，versionCode 28 / 0.5.0）

## 一、结论速览

| 判定 | 数量 | 页面 |
|---|---|---|
| ✅ 直接移植（改交互即可） | 4 | 素材库首页、素材详情、搜索、收藏合集 |
| 🟡 改造后移植（按手机场景裁剪） | 4 | 上传素材、标签管理（轻量）、人物浏览、任务中心（只读） |
| 🔴 不建议移植 | 8 | 采集管理、素材管理、数据治理、数据洞察、AI 模型管理、人脸库扫描、模特照片上传、标签高级管理 |
| ⚪ 待定（先只做只读） | 1 | 本地出图 |

一句话：**手机是"随手采集 + 随手浏览 + 轻编辑"的工具，不是"桌面工作台"。凡是需要表格批量操作、长时间跑任务、依赖 PC 环境（Playwright / ComfyUI）的功能，都留在电脑上。**

## 二、判定标准（四条，按顺序问）

1. **数据是否已在手机上可获得？** —— 只调用 `/api/*` 的功能天然可移植；依赖 PC 本地进程（ComfyUI、Playwright、Ollama）的功能，手机只能当"遥控器"。
2. **交互是否适合触屏？** —— 瀑布流、多列网格、滑动、长按、拍照、相册多选：适合。密集表格、右键菜单、拖拽排序、多选批量打标签、hover 预览：不适合。
3. **是否需要长时间驻留？** —— 采集/人脸扫描/批量出图属于"分钟级到小时级"任务，手机息屏即断（RN 无后台任务），只适合"发起 + 看进度 + 看结果"。
4. **使用频次与场景？** —— 通勤/买衣服时翻素材、拍下来存起来：高频。改标签规则、清数据、管模型：低频且危险。

判定公式（实践版）：**只要有一步需要"盯着多个字段做决策"，就不移植。**

## 三、逐功能矩阵

### 3.1 素材库首页（`/` HomeView，395 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 瀑布流 + 筛选（来源/标签/收藏）+ 排序 + 分页 + 批量选择 + 加入合集 | 两列等高网格 + 下拉刷新 + 无限滚动 + 收藏 | 🟡 改造移植 |

**方案**
- 保留两列网格（**不做真瀑布流**：RN 实现需测每张图高度、滚动抖动明显，收益低）
- 顶部加一条**筛选胶囊栏**（全部 / 收藏 / 已标注 / 未标注 / 来源），横向滚动，不占空间
- 批量选择：长按进入多选态（标题栏变成"已选 N 张 · 加入合集 · 删除"），底部操作条；后端有 `batch-favorite` / `batch-trash` / `batch-tags` 可直接用
- 排序先只做「最新 / 收藏优先」两种，其余不进手机
- 工作量：**M（1.5~2 天）**

### 3.2 素材详情（`/detail/:id` DetailView，604 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 大图、标签编辑、移动/删除、相似推荐、加入合集、来源跳转 | 大图 + 全屏看图 + 收藏 + 只读标签 | ✅ 直接移植（补齐 4 项） |

**方案**
- 标签编辑：点标签区 → 底部弹层（BottomSheet）→ 搜索已有标签 / 新建 → 保存（`PATCH /api/inspirations/{id}`）
- 删除：右上「更多」→ 移入垃圾桶（`POST /api/inspirations/{id}/trash`，软删除，可恢复），二次确认；垃圾桶里可 `POST .../restore` 恢复
- 相似推荐：详情页底部「相似素材」横向列表（`GET /api/search/similar/{id}`），点进另一个详情
- 加入合集：复用 3.4 的选择器
- 工作量：**M（1.5 天）**（软删除+恢复的 UI 只做"移入垃圾桶 + 提示可恢复"）

### 3.3 搜索（`/search` SearchView，153 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 关键词 + **语义检索**（`POST /api/search/vector`）+ **以图搜图** + 相似 + 标签筛选 + 结果分页 | 关键词搜索，一次性返回 | ✅ 直接移植 |

**方案**
- 搜索框右侧加「📷 以图搜图」：调相册选图 → 上传临时文件 → `POST /api/search/vector`（手机上比桌面更自然，是**手机端反而更强**的功能）
- 结果分页：`onEndReached` 翻页（后端已支持 page/size）
- 标签筛选：底部弹层多选（`GET /api/tags`）
- 工作量：**M（1.5 天）**

### 3.4 收藏合集（`/collections` CollectionsView，520 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 左侧合集栏 + 拖拽排序 + 批量增删 + 固化（solidify） | 无 | 🟡 改造移植 |

**方案**
- 不做左侧栏：改成「合集宫格页」（封面 + 名称 + 数量），点进去是该合集的两列网格
- 拖拽排序**不做**（触屏拖拽 + 滚动冲突，投入产出比差）；改成「长按 → 上移/下移」
- 批量增删：在多选态里「加入合集 / 移出合集」
- 工作量：**M（2 天）**（涉及 6 个接口：list/create/delete/加/删/solidify）

### 3.5 上传素材（`/upload` UploadView，560 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 拖拽 / 粘贴 / URL 导入 / 多选上传 / AI 分析状态 | 单图上传（相册或相机） | 🟡 改造移植 |

**方案**
- **相册多选**（`allowsMultipleSelection: true`）+ 拍照入口（手机独占优势：逛街拍了直接入库）
- **URL 导入**：保留（粘贴小红书/抖音链接 → `POST /api/inspirations/from-url`），比拖拽更适合手机
- **拖拽/粘贴不做**（桌面概念）
- 上传进度：逐张进度条 + 失败重试 + AI 分析状态轮询（`/api/tasks`）
- 工作量：**M（1.5 天）**

### 3.6 标签管理（`/tags` TagManageView，421 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 浏览分类树、改名、合并、删除、改颜色 | 无 | 🟡 极简移植 |

**方案**
- 只做「按分类浏览 + 搜索 + 改名」三件事（改名是手机上最常需要的小修）
- 合并/删除/颜色/排序全部留在 Web（破坏性 + 需要对比多个标签）
- 工作量：**S（0.5 天）**

### 3.7 人物（`/persons`、`/persons/:id` PersonView + PersonDetailView）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 穿搭博主/模特列表 + 详情（作品墙 + 简介 + 关注） | 无 | 🟡 只做浏览 |

**方案**
- 只做「人物列表 + 人物作品墙」，不做人物新建/编辑/合并（那是维护工作）
- 工作量：**M（1.5 天）**；优先级低于上面几项

### 3.8 任务中心（`/tasks` TaskManageView，121 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 聚合任务列表、详情、取消/暂停/恢复/删除 | 无（上传后没有任何进度反馈） | 🟡 只做只读 + 取消 |

**方案**
- 设置页下方加「后台任务」入口 → 列表（类型/状态/进度）→ 点击看失败原因 → 支持「取消」
- 暂停/恢复/删除留在 Web（状态机复杂，手机上误触代价高）
- 工作量：**S（1 天）**；**建议随 M2 一起做**，否则上传后用户不知道 AI 分析成功没有

### 3.9 本地出图（`/generate` GenerateView，260 行）

| 项 | Web 现状 | 手机现状 | 判定 |
|---|---|---|---|
| 能力 | 选模型（含未审查版）→ 填 prompt → 提交 → 轮询 → 候选图 | 无 | ⚪ 只做只读（可选） |

**方案**
- 出图依赖 PC 上的 ComfyUI（`/api/generate/runs` 异步 + 轮询），手机上"填参数 + 等 30~60 秒"体验差
- 若要做：只做「已生成候选图浏览 + 一键收藏」，或「用已有素材做 i2i 的极简版」
- **不建议**把完整参数面板搬过来
- 工作量：只读版 **S（0.5 天）**；完整版 **L（3 天+）且体验不会好**

## 四、明确不移植的清单（附理由）

| 页面 | 不移植的理由 |
|---|---|
| **采集管理** `/scraper` | 依赖电脑上的 Playwright + 浏览器环境，手机上没有这个能力；只能是"遥控别人电脑"，价值低 |
| **素材管理** `/admin` | 密集表格 + 批量勾选 + 批量移动/删除，是典型桌面工作流；手机上误触成本极高 |
| **数据治理** `/admin/governance` | 批量清理、批量软删除、不可逆操作；**危险操作不该放在随手可点的设备上** |
| **数据洞察** `/admin/insights` | 图表 + 向量库状态，分析场景只在桌面；手机屏幕也装不下 |
| **AI 模型管理** `/models` | 运维配置（模型文件、显存、ComfyUI 参数），属于"一年改一次"，且改坏了手机上看不出来 |
| **人脸库扫描** `/face-scan` | 分钟级批处理 + 逐条确认簇结果，属于"盯着屏幕做决策"的典型；手机只适合看最终人物列表 |
| **模特照片上传** `/model-photos` | 565 行重度上传流程（多角度、裁剪、绑定人物），手机上做完也不会用第二次 |
| **标签高级管理** `/tags/advanced` | 分类树维护、规则配置，纯配置型工作 |

补充几条"看起来能移植但其实不该"的判断：

- **瀑布流布局**：Web 用等高列错落排布很好看，RN 里要实现需异步量测每张图高度，滚动会抖，且两列网格在 423dp 宽度下信息密度已经够 → 不做
- **拖拽排序**：触屏拖拽与列表滚动冲突，需要 gesture-handler 长按 + 自动滚动，投入 3 天换一个低频功能 → 改「上移/下移」按钮
- **右键/hover 交互**：手机没有，全部改成长按菜单
- **批量打标签**：看起来方便，但手机上选完标签就没法看画面确认，容易打错 → 只做单张编辑

## 五、移动端"反向优势"（Web 做不到的，优先做）

这几件事**只有手机能做**，是移植工作的真正价值点，建议优先级排在"搬运 Web 功能"之前：

1. **拍照即入库**：相机 → 上传 → 自动 AI 打标，替代"存相册再手动传电脑"
2. **相册多选批量上传**：一次选 20 张，逐张进度
3. **以图搜图**：逛街看到同款，拍一张找相似单品（Web 只能上传文件，手机是自然入口）
4. **分享到 App**（Android Share Intent）：小红书/抖音里点分享 → 直接进素材库（需配置 intent-filter，约 1 天）

## 七、跨端复用策略

**可以直接复用的**

- `shared/types/*`：`Inspiration` / `Tag` / `TagCategoryGroup` / 分页结构（mobile 已 `@shared/*` 引用）
- 接口契约与错误格式（`{detail: "..."}`）；mobile 的 axios 客户端已封装 baseURL 动态注入 + `normalizeBaseUrl`
- 纯函数：`sourceLabel`（两端各一份，需同步维护）、时间格式化

**不能复用的（别浪费时间）**

- Vue 组件 → React Native：模板语法、CSS、Arco 组件全不通用，只能照着交互重写
- 图表（Arco/自绘）→ RN：需要 victory-native/skia，且本就不移植洞察页
- 表格 → RN：所有表格类页面已判定不移植

**统一约定（新增功能时遵守）**

- 图标一律用 `mobile/components/Icon.tsx`，不要写 `<Ionicons>`（见 CLAUDE.md 的踩坑记录）
- 大图浏览用已封装的 `ImageViewer`，不要每个页面各写一个 Modal
- 列表一律 `FlatList`（两列 `numColumns={2}`），分页用 `onEndReached`
- 任何来自后端的字符串字段，渲染前做类型兜底（`sourceLabel` / `getFileUrl` 已加），否则脏数据会让整页崩

## 八、风险与注意事项

| 风险 | 说明 | 对策 |
|---|---|---|
| **后台任务中断** | RN 息屏后 JS 停跑，轮询会断 | 任务中心只在 App 前台轮询；文案明确"回到 App 自动刷新" |
| **局域网依赖** | 手机必须与电脑同网，换 WiFi 就失效 | 空态给"检查后端地址"入口 + 一键重试（设置页已具备） |
| **大数据量列表** | 后端 `total` 已达 3 万，翻页到底不现实 | 必须做筛选/搜索，不做"无限下滑到底" |
| **危险操作** | 删除/移入垃圾桶在手机上极易误触 | 一律二次确认；批量删除只给"移入垃圾桶"（可恢复），不给永久删除 |
| **图片流量** | 原图动辄 2~5MB | 列表用 `thumbnail_path`（已如此），详情/全屏才取原图 |
| **设备差异** | 只在 nova 7 Pro（1080×2340 / 423dp）验证过 | 布局用 flex + 百分比，不写死像素 |
