# 姿势图库换姿势（路径一）实现说明

> **状态**：现行（2026-11-02 增补选择器「随机 + 使用次数」；功能已合并 master）。如与代码不一致，以代码为准。
> **范围**：素材详情「换个姿势」→ 出图页打开姿势选择器 → 选姿势 → 生成候选图；**个人本地使用**，不做内容分级过滤。
> **生成方式（2026-10-31 修复）**：默认**线稿参考（图生图）**——姿势图作为最后一张参考图、走第三个**未审查**档位（`qwen_2_1_uc_i2i`）；仍支持切「文字描述（文生图）」把姿势名/角度写进 prompt（不需要参考图）。
> **效果边界**：线稿作参考图时姿势「像」但不保证逐关节一致；R2/E3 实验已证明「保留本人+原服装的换姿势」不可行，**方向已结项**（见 [结项报告](换姿势方向结项报告-2026-10-31.md)）。
> 评估背景见 [换姿势方案评估与调研合集 §2](换姿势方案评估与调研合集.md)。

## 1. 链路与数据流

```text
[素材详情页] 点「换个姿势」
   └─ 路由 /generate?ref=<素材id>&pose_lib=1
        └─ 出图页（GenerateView）读取 pose_lib → 参数面板挂载后自动打开姿势选择器
             ├─ 参考素材：ref 预填为第 1 张（主体：人物/服装）
             └─ 选姿势：GET /api/pose-gallery（后端代理 ai-pose-gallery-zh，目录缓存 12h）
                  ├─ 方式 A（默认）线稿参考/图生图：kind=i2i + reference_ids + pose_id
                  │     └─ 执行器把姿势图**追加为最后一张参考图**，走 Qwen-Image 2.1
                  │        「多参考图编辑」工作流（占 1 张参考额度，默认未审查第三档）
                  └─ 方式 B 文字描述/文生图：kind=t2i + pose_id
                        └─ 提交层把「人物姿势：名称（角度），构图词」拼进 prompt
                           → z_image_t2i 模板出图（无需参考图）
                            └─ 候选区 → 勾选入库（沿用现有两段式）
```

**参考图顺序约定**：第 1 张（及前面几张）是主体参考，**最后一张是姿势图**；参数面板的「插入姿势描述」会生成模板明确这个顺序。

---

> **提示词来源（2026-11-01 起）**：图生图 + 姿势的提示词不再由前端拼固定模板，而是优先使用 `pose_prompts` 表中 thinking 反推的提示词（全量 1,439 条，见 [姿态提示词反推缓存](../features/姿态提示词反推缓存.md)）；前端选姿势时自动填入，后端提交时再兜底补一次；库里没有该姿势记录时才回退旧模板。

## 2. 后端

| 模块 | 职责 |
| --- | --- |
| `app/services/pose_gallery.py` | 拉取源站 `data/pose-zh.json` → 归一化（id/名称/体系/分类/角度/缩略图/原图直链）；缓存到 `storage/pose_gallery/catalog.json`（默认 12 小时，过期回源，回源失败用旧缓存兜底）；按需下载原图到 `storage/pose_gallery/images/<id>.png`（生成时才下载，不随仓库分发图片） |
| `app/routers/pose_gallery.py` | `GET /api/pose-gallery`（筛选 + 分页，每项带 `usage_count`）、`GET /api/pose-gallery/random`（按同一套筛选随机取一个，支持 `exclude`）、`GET /api/pose-gallery/meta`（筛选项）、`GET /api/pose-gallery/{id}`、**`GET /api/pose-gallery/{id}/prompt`（取 `pose_prompts` 反推提示词）** |
| `app/schemas/generation.py` | `GenerationRunCreate.pose_id`（≤64 字符） |
| `app/services/generation_service.py` | 提交校验：两种方式都支持；姿势必须存在于目录；t2i 自动把姿势描述拼进 prompt（服务端兜底）；**i2i 自动读取 `pose_prompts` 表的反推提示词并拼在用户描述前**（无记录时回退旧模板）；i2i 校验姿势图占 1 张参考额度（主体参考 ≤9 张）；`pose_id` 写进 `params_json`；`retry_run` / `regenerate_candidate` 原样带上姿势；导出/历史显示姿势 id；**`pose_usage_counts()` 按 `params_json.pose_id` 聚合每个姿势的出图批次数**（选择器「已用 N 次」的数据源） |
| `app/services/task_runners/image_gen.py` | **t2i**：不下载/上传姿势图（只兜底补一次 prompt）；**i2i**：下载并上传姿势图（文件名 `gen_pose_<run_id>.png`），追加到 `reference_names` 末尾；下载失败按永久错误给出可读原因 |
| `app/config.py` | `pose_gallery_base_url`（默认 `https://ai-pose-gallery.anhao.app`）、`pose_gallery_cache_hours`（12） |

**为什么由后端代理**：源站是 GitHub Pages 静态站，`/data/pose-zh.json` **没有 CORS 头**，浏览器跨域 `fetch` 会被拦；后端缓存后前端只跟本机接口打交道，源站抖动也有旧缓存兜底。缩略图/原图地址仍是源站直链（`<img>` 展示不需要 CORS）。

**不做内容分级**：个人本地项目，源站 4 个体系（含成人向）都可选；只保留两条底线——不随仓库分发图片、生成结果仍走「AI 生成」标记。

### 3.1 选择器增强：随机 + 使用次数（2026-11-02）

**随机姿态（`GET /api/pose-gallery/random`）**

- 与列表**共用同一套筛选**（关键字/体系/分类/角度）——随机只在用户当前看到的那批里抽，不会突然跳回全部 1439 个；
- 单选模式：抽中即回抛并关闭弹窗；`exclude` 传当前已选姿势（筛选后只剩它时后端仍返回它自己，避免「点随机直接报没有匹配」）；
- 云端多选模式：抽中后加入已选、弹窗保持打开；若抽到已在已选列表里的姿势最多重试 3 次，避免重复占位；
- 目录走 `pose_gallery.load_catalog()` 内存/磁盘缓存，随机本身不产生额外回源请求。

**使用次数（`usage_count`）**

- 数据源：`generation_runs.params_json` 里的 `pose_id` 快照。建批次时无论本地 t2i / i2i 还是云端 Seedream，只要选了姿势就会写入；云端多姿态是「每个姿态各建一个批次」，所以同样只出现 `pose_id`；
- 口径：**每一次提交算一次使用**（含 queued/failed/cancelled）——用户问的是「这个姿势我用过几次」，不是「成功出图几次」；未选姿势的批次不参与统计；
- 实现：SQLite JSON1 `json_extract(params_json, '$.pose_id')` + `GROUP BY`（并用 `json_valid` 过滤脏行，避免一条坏 JSON 让整个选择器 500）；列表接口为当前页批量返回，卡片显示「已用 N 次」（0 次显示「未用」，用过的蓝字加粗）；
- 不做「选择器点击计数」：点击 ≠ 实际使用（用户可能点错/取消），以真实提交的出图批次为准，避免把一次浏览记成一次调用；
- 已知边界：`usage_count` 是本次打开选择器时的快照；刚提交的批次若在打开期间完成，需重新打开/翻页才刷新。

## 4. 一键出图（性感系 399 姿势轮播）

代码：`web/src/components/generate/QuickPoseBatchPanel.vue`（2026-10-30 审查后补说明）。

- **交互**：每次张数 1~4 / 步数 1~30 / 连续次数 1~剩余姿势数 + 主按钮；**默认文字描述（文生图，无需参考图）**，切线稿参考时才要求主体参考图；上限 = 剩余未出过的姿势数（可「设为剩余全部」）；运行中可停止；进度存 localStorage（按体系分开），可重置；
- **描述**：每轮自动写入带**姿势名·角度·构图词**的模板（用户已写的基础描述保留在前，模板在后）；
- **失败保护**：一轮「3 秒没启动」或「2 秒内就结束」判定本轮没起来（提交失败/被取消）→ 回滚该姿势、停止队列并提示，避免把剩余姿势快速标记成已用；
- **可追溯**：`pose_id` 进参数快照；生成历史展开行显示「姿势 <id>」；CSV/JSON 导出新增 `pose_id` 列；「带入表单」按 `pose_id` 取回完整姿势；
- **错误语义**：姿势图下载 4xx/格式错 → 永久失败（502）；网络/5xx → 可重试（503，执行器抛 `RecoverableTaskError` 交给任务队列重试一次，不依赖错误文案关键词）。

## 6. 已知问题与实测结论（2026-10-30~31）

**姿势线稿会被当「内容」融合**（`scripts/archive/pose_fidelity_ab.py`，12 张样张）：

- 主体姿势不跟着线稿变，反而把**素体关节圆圈画到人物腿上**（带姿势名也一样）；
- 提示词解释「线稿只作姿势参考」→ 模型在人物旁边**渲染一个素体雕塑**；
- 线稿放第 1 张 → 直接输出线稿本身；线稿放两遍 → 输出素体 3D 雕塑；
- **不传线稿、只用文字描述姿势** → 姿势大体能改、身份保持好、无伪影，且快 2.6~4 倍（32~34 s vs 85~137 s）。

后续实验（均见 [结项报告](换姿势方向结项报告-2026-10-31.md)）：

| 路线 | 结果 |
| --- | --- |
| R1 文字姿势（25 张） | 姿势 4.0/5、84% ≥4 分、身份 5.0/5、31 s/张；坐姿/相机角度/源图 UI 是失败模式 |
| R2-A SDXL + ControlNet lineart | 姿势 5/5，但**关节圆→护具/服装装饰**、身份丢失 |
| A 换脸 | 脸 0.47→0.87，服装/发型仍不保 |
| P0 Qwen 英文 prompt + LoRA | 身份/服装 5/5、姿势 0/5；int8+LoRA 崩坏 |
| E3 Depth 控制 + 换脸 | 护具消失、姿势 3.7/5、脸 0.81、20~25 s/张；**服装/发型仍不保** |

**结论**：路径一（选姿势 + 记录 `pose_id`）已可用，但「换姿势且保留本人/原服装」不可行，**方向已结项**。

## 7. 边界与后续

- **姿势一致性不保证**：复用 Qwen-Image 2.1 多参考图编辑；要更强控制已试 lineart（出护具）与 depth（保不住衣服），均不够；
- **源站依赖**：首次使用需能访问 `ai-pose-gallery.anhao.app`；离线时可手动放一份 `storage/pose_gallery/catalog.json` 兜底；
- **版权**：姿势图版权归原作者，仅本地个人使用，不随仓库分发、不对外提供公开生成服务；
- **若重启方向**：优先 F1（E3 的 depth 姿势图作 Qwen 编辑的姿势参考 + 英文 prompt，零新下载），见结项报告 §7。
