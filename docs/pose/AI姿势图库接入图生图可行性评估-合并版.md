# AI 姿势图库（ai-pose-gallery-zh）接入图生图能力可行性评估

> **状态**：现行（2026-10-31 精简合并版，唯一留存）。评估日期 2026-10-30；原 v1（上午）与 v2 复评（同日）两份源文件已删除，全部要点并入本文。
> **一句话结论**：**工程可行性高、合规可行性低**——图库是优质「输入侧」，但不适合做成公开在线生成；我们实际只把它当本地实验的姿势参考，该方向已结项（见 [换姿势方向结项报告](换姿势方向结项报告-2026-10-31.md)）。

---

## 0. 结论先行

| 问题 | 判断 |
| --- | --- |
| 技术上能否接入图生图？ | **能，但不能在它仓库内独立完成**。它是纯静态站（无后端/存储/推理/鉴权），i2i 需要新增一整套「推理 + 任务 + 存储 + 鉴权 + 审核」服务层；Pages/Workers 只能托管与轻量代理，跑不了 GPU |
| 个人 / 本地使用是否可行？ | **可行且推荐**：复用本机 ComfyUI + Qwen-Image-Edit，先做参考图/提示词导出（P0），需要站内生成再做受控服务（P1） |
| 值得在公开站点做在线生成吗？ | **当前不建议**：图片/数据授权（MIT 只覆盖代码）与 18+ 内容合规是 go/no-go，不是技术问题 |
| 推荐路线 | **P0 先做**：提示词模板 + 参考图导出，生成交给用户自己的工具（0.5~1 人日、0 算力、0 输出合规风险）<br>**P1 受控生成**：全年龄子集（765 条）+ 访问口令 + 每日硬限额，仅内部/自用（5~7 人日）<br>**P2 公开在线生成**：不做，除非先解决授权与内容分级 |
| 本项目的实际去向 | 未接入该图库做生成入口；仅用其姿势参考做本地「素材换姿势」实验（R2 / Depth / Qwen），**已结项** |

**一句话**：这个项目适合继续做「参考图库」，不适合直接变「公开生成站」；生成能力应放在用户自己的工具，或一个受控的独立服务里。

## 1. 图库现状（实测事实）

### 1.1 技术栈与运行形态

| 层面 | 事实 |
| --- | --- |
| 前端 | 单文件 `index.html`（922 行、约 58.6 KB，LF）；原生 HTML/CSS/JS，无框架、无构建、无 npm 依赖 |
| 交互 | 体系/分类/视角筛选、搜索、灯箱、键盘/触屏导航、原图下载；只有一次数据请求 `fetch('data/pose-zh.json')` |
| 图像处理 | 浏览器端**没有** canvas/WebGL/Worker/上传/解码/缩放；灯箱只是 `<img>` 切换 + 预加载 |
| 数据 | `data/pose-zh.json` 1439 条（中文版）；另有原始日文 `pose.json`、翻译 CSV；字段无 prompt/keypoints |
| 脚本 | 5 个，全部 Python 标准库：`download.py`、`verify.py`（魔数/大小校验）、`i18n.py`、`apply_translation.py`、`build.sh` |
| 运行时 | 无后端、无 API、无数据库、无对象存储、无鉴权；仅 1 个第三方统计脚本 |
| 部署 | Cloudflare Pages（构建 `bash scripts/build.sh` → `dist/`）；`_headers` 对图片做一年强缓存 |
| 安全头 | 中文版 `index.html` **没有 CSP**（原日文站有严格 CSP）；新增生成 API 需补 `connect-src`/`img-src` 与 CORS 白名单 |
| 内容属性 | 4 体系 / 26 分类 / 5 视角 / 288 个姿势名；18+ 体系合计 **674 / 1439 = 46.8%** |

### 1.2 数据与资产

| 项 | 数值 |
| --- | --- |
| 记录数 / 姿势组 | **1439 条 / 288 组** |
| 体系 | 全身单人·标准系 365；全身单人·性感系 399；上半身单人 400；双人缠绵 275 |
| 视角 | 正面/俯视/侧面/斜侧各 288，仰视 287（1 组缺仰视）；287 组具备全部 5 视角 |
| 字段 | `id、体系、姿势编号、分类、姿势名称、角度、缩略图、原图、检索`；无 prompt、无 keypoints、无骨架/控制图、无模型/seed |
| 原图 | 1439 张 **900×1200 RGB PNG（无 alpha）**，合计 **637.6 MB**；单张 73 KB~917 KB，中位 458 KB |
| 缩略图 | 1439 张 300×400 JPG，实测 **26 MB**（README 旧值 22 MB） |
| 画面特征 | 抽样左上角纯白 `(255,255,255)`；颜色数中位约 7,177——**白底灰阶素体线稿**，适合直接做 lineart/canny/depth |
| 仓库体积 | 工作树约 1.3 GB（含 `.git`）；GitHub 元数据约 662 MB |

**关键含义**：原图、多角度、筛选 UI 是现成的优质输入侧；缺的是生成侧全部基础设施；数据里没有骨架，要「骨架约束」必须离线补算控制图。

### 1.3 现有图像处理能力

全仓库**没有任何模型推理、图像编解码或像素级处理**，只有两处字节级校验：

1. `scripts/verify.py`：读前 8 字节判断 JPEG/PNG 魔数 + 大小阈值，校验 2878 个文件；
2. `scripts/download.py`：按实际字节数校验、原子替换落盘（urllib + 48 线程 + 断点续传）。

没有后端、Serverless、数据库、鉴权、任务队列；缩略图是预生成后入库的。**接入 i2i = 第一次给这个项目引入真正的图像 I/O 与推理链路。**

### 1.4 许可、内容属性与社区

| 项 | 事实 |
| --- | --- |
| 代码许可 | MIT，但 **Scope 明确只覆盖代码**（`index.html`、`scripts/`、`_headers` 等） |
| 图片/数据 | 著作权归原作者（ギア）；镜像不构成商业授权；`img/`、`thumbs/`、`data/` 不在 MIT 范围 |
| GitHub 许可识别 | `Other / NOASSERTION`（不是标准 MIT） |
| 内容属性 | 18+ 体系 = 性感系 399 + 双人缠绵 275 = **674 / 1439 = 46.8%**；全年龄子集 765 条（53.2%） |
| 仓库热度 | 2026-10-30 复评：**3,153★ / 812 fork / 3 个开放 PR**；2026-10-27 创建，增长很快 |
| 社区先例 | PR #2「姿势参考 Agent 技能」、#3「筛选/浏览优化」、#4「Codex 本地插件」；**没有任何 PR 实现生成功能**，社区方向是「检索/导出姿势图作为外部生图参考」 |
| 上游站点 | 原日文站也是纯静态 HTML，带严格 CSP，没有隐藏的生成 API |

**结论**：这是「参考图库」，不是「生成应用」。现有架构与数据非常适合做 i2i 输入侧，但生成所需的算力、状态、存储、密钥、审核全部不存在。

## 2. 接入 i2i 的能力缺口

| 环节 | 现状 | 缺口 |
| --- | --- | --- |
| 参考图输入 | ✅ 900×1200 PNG、每姿势 5 视角、可按分类/视角筛选 | 基本无需改造；最多加裁剪/缩放/白底处理 |
| 提示词 | ⚠️ 只有体系/分类/姿势名/角度（中文），可程序化拼模板 | 缺服装/场景/风格描述，需用户输入或 LLM 补全 |
| 模型推理 | ❌ 完全没有 | **核心缺口**：云端 API / 自建 GPU / 浏览器 WebGPU 三选一 |
| 结果存储 | ❌ 无 | 生成图 1~2 MB/张，不能塞进 `dist/`，需 R2/外部存储 |
| 任务状态 | ❌ 无 | i2i 通常 5~45 s，需要异步任务 + 轮询/SSE + 取消 |
| 鉴权/配额 | ❌ 无（纯静态公开站） | 必须新增，否则密钥与成本裸奔 |
| 内容审核 | ❌ 无 | 18+ 条目占 46.8%，必须分级与过滤 |
| 观测/日志 | ❌ 仅第三方统计 | 失败率、耗时、成本、滥用需要记录 |

## 3. 技术路线与我们的实验验证

原评估（v1/v2）比较了三条路线；后续本机实验补上了关键结论，**这是评估与最终选型之间最重要的修正**：

| 路线 | 原判断 | 本机实测（见结项报告） |
| --- | --- | --- |
| **A. 线稿 → 直接参考图编辑**（Qwen-Image-Edit / FLUX.2 multi-reference） | 链路最短、与现有后端最匹配；姿势不保证一致 | **姿势不跟随**：线稿作参考图时，模型把线稿当「内容」而非控制信号（R1-A/P0）；英文约束 prompt 能保身份/服装（5/5）但姿势 0/5 |
| **B. ControlNet lineart / canny** | 更贴合图库（本身就是线稿），保留构图/轮廓 | **姿势 5/5，但关节圆被画成护具/服装装饰**（R2-A）；加 Qwen 清洗仍丢身份 |
| **C. ControlNet depth** | 原评估未展开 | **消掉关节圆伪影（10/10）**，姿势 3.7/5；但保不住服装/发型（E3） |
| **D. 骨架 OpenPose/DWPose** | 姿势一致性最好，但线稿跨域、双人/俯仰视角风险 | **不可行**：社区记录 DWPose/OpenPose 识别不了素体线稿；我们的尝试也未成立 |
| **E. 普通 img2img 重绘** | 易改姿势，价值有限 | 不推荐；身份与姿势跷跷板 |

**结论**：图库线稿适合做 **lineart / depth 控制图**，不适合直接当「编辑参考图」；「图库 + 生成」的 1+1<2 根因在此（社区证据见 [社区姿势图库与出图结合项目调研](社区姿势图库与出图结合项目调研.md)）。

## 4. 架构方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A 浏览器直连**第三方 API | 前端直接 `fetch` 服务商接口 | 改造最小 | API Key 必然暴露；跨域/限流不可控 | ❌ 不可行 |
| **B Pages Functions 代理 + 云端 i2i** | 新增 `functions/api/i2i/*` 做代理、鉴权、配额、审核；结果存 R2 | 最贴合现状；密钥只在服务端；免费额度够内部用 | 成本转给上游；需内容审核；需新增 R2/KV/Secrets | ✅ **P1 推荐（限受控/内部）** |
| **C 自建 GPU + ComfyUI** | 独立机器跑 ComfyUI + 反代 + 队列 | 姿势控制最准、模型最自由、可复用现有栈 | 需常驻 GPU、运维、公网鉴权、带宽 | ⚠️ **仅本地/内网** |
| **D 纯浏览器本地推理** | WebGPU + onnxruntime-web / WebSD | 零后端、零密钥、零运营成本 | 首次下载数百 MB~GB；移动端/集显差；画质与可控性弱 | ⚠️ 实验性，不作主路径 |
| **E 不做生成，只做提示词/参考图辅助** | 按体系/分类/角度生成 prompt 模板，一键复制 + 导出 | 0 算力、0 成本、0 输出风险；最贴合定位；与社区方向一致 | 不是「在线生成」体验 | ✅ **P0 首选** |

**Cloudflare Workers AI 核对**：模型目录有 SDXL、FLUX.1 schnell、FLUX.2 dev/klein（标注支持 multi-reference），**未检索到 ControlNet/OpenPose 姿态条件模型**——可用于方案 A 的原型，不能替代 ControlNet 做精确姿势迁移；内容政策也不适合本站素材。

**与本机 `fashion-inspo` 的关系**：已有 Qwen-Image-Edit i2i 链路（参考图 1~10 张、最大 1024²、任务队列 + 生成历史）。本地/内网做姿势生成，方案 C 最省事；公开站不能依赖本机 GPU。

## 5. 若确定公开接入：改造点（精简）

| 模块 | 改动内容 | 量级 |
| --- | --- | --- |
| 前端 `index.html` | 新增创作模式（选图 → 参数 → 进度 → 结果对比 → 下载/删除）；现 922 行单文件再塞 600~900 行难维护，建议拆原生 ES Module；灯箱加「用这个姿势生成」入口 | 2~3 人日 |
| `functions/api/i2i/` | 提交/查询/取消/删除；配额、Turnstile、内容过滤、上游错误翻译 | 1.5~2 人日 |
| `functions/_middleware.js` | CORS/CSP/安全头、请求体大小限制、限流 | 0.5 人日 |
| 数据 | `pose-zh.json` 加派生字段（`i2i_prompt`/`age_rating`/`control`），同步 `apply_translation.py` 白名单；离线预生成 lineart/canny（CPU 分钟级），控制图不入静态仓库 | 0.5~1 人日 |
| 存储/部署 | R2 存结果（7~30 天 TTL）；KV/D1 存任务与配额；`wrangler` 绑定 Secrets；`.assetsignore` 增补 | 0.5 人日 |
| 文档/合规 | README、使用指南、免责声明、图片版权与「不得商用」、18+ 分级 | 0.5 人日 |

**接口草案（P1）**：`POST /api/i2i`（pose_id、prompt、strength、尺寸、seed、mode）→ 202 `{job_id, eta_s, quota}`；`GET /api/i2i/{job_id}` 轮询状态；`POST /api/i2i/upload` 可选自定义参考图（≤10 MB、PNG/JPG、尺寸校验）；错误统一 400/413/422/429。

**平台限制**：Pages 20,000 文件（免费）/25 MiB 单文件；Workers 100,000 请求/天（免费）；CPU 10 ms 免费、5 min 付费（默认 30 s）；子请求 50/10,000；HTTP 触发无硬 wall time（客户端保持连接）；`waitUntil` 最多 30 s。

## 6. 风险与 Go/No-Go

| # | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| 1 | **图片授权/版权**：MIT 不覆盖图片/数据；i2i 输出属演绎，公开传播/商用有侵权风险 | **极高（公开/商用）** | 仅本地自用；公开前取得原作者许可或替换自有/CC0 资产；保留署名与删除通道 |
| 2 | **成人内容合规**：18+ 占 46.8%，主流云端 API 普遍禁止；参考图可能被拒 | **高** | 生成入口只开全年龄子集（765 条）；关键词 + 图像审核；年龄分级；优先本地/内网 |
| 3 | **AIGC 标识与生成式服务合规**：显式/隐式标识、安全评估/备案义务 | **高（公开）** | 输出加水印/元数据；服务条款与隐私政策；公开前完成合规评估 |
| 4 | **肖像/同意/深伪**（若开放用户照片） | **高** | 默认不做用户照片；若做需明示同意、年龄门禁、人脸/NSFW 审核、短 TTL |
| 5 | **密钥与滥用**：静态站无鉴权，3.1k★ 会放大流量与恶意刷量 | **高（公开）** | 只走服务端代理；Turnstile/Access；每 IP/每日硬限额；预算告警 |
| 6 | **成本不可控**：上游按张计费、GPU 常驻贵 | 中高 | 每日总张数硬上限；BYOK；队列与并发限制；优先本地 |
| 7 | **姿势保真与质量**：线稿对姿态模型是跨域输入；双人、俯仰、遮挡、手脚易失败 | 中 | 先做 10~20 样本对比；lineart/depth 回退；人工 QA |
| 8 | **架构漂移**：从零依赖静态站变「静态 + Functions + R2 + 上游」 | 中 | 做成可选模块（配置了才启用，默认关闭）；主干保持纯静态 |
| 9 | **模型许可证**：SDXL/Qwen/ControlNet/IP-Adapter/InsightFace 条款不同，人脸模型常限非商用 | 中 | 商用前逐个核对；优先 Apache/可商用；避免 InsightFace 非商用依赖 |
| 10 | **安全**：上传攻击、SSRF、公开 ComfyUI 8188、CORS 过宽 | 中 | MIME + 尺寸 + PIL 解码校验；不抓用户 URL；ComfyUI 只在内网；CORS 白名单 |
| 11 | **隐私与数据保留**：上传图、提示词、生成图留存 | 低中 | 上传不落盘/短 TTL；输出 7 天清理；隐私说明 |

**Go/No-Go**：未取得原作者「生成/公开传播」许可 → 不做公开服务；上游政策禁止 18+ 或参考图被拒 → 不用该上游（或只做全年龄子集）；10~20 样本姿势/解剖质量不达标 → 不推进 ControlNet 路径；无法实现年龄门禁/审核/硬限额 → 不做公开发布；单张成本超阈值 → 只做内部/本地或 BYOK。

## 8. 推荐路线

1. **Phase 0（1~2 天）**：样本实验——选 10~20 个覆盖 4 体系 × 5 视角 × 单人/双人的姿势，比较直接编辑 / ControlNet lineart / depth，记录姿势保真、解剖、耗时、显存、失败率。
2. **Phase 1（0.5~1 天，P0）**：上线「提示词模板 + 一键复制 + 参考图导出」；零算力、零输出合规风险，先验证需求。
3. **Phase 2（5~7 天，P1，仅内部/受控）**：确需站内生成时做方案 B——只开全年龄子集、Access/Turnstile + 每日硬限额、R2 存结果 + 7 天清理、强审核与 AI 标识、不放公开入口。
4. **Phase 3（公开在线生成）**：**暂不做**，除非同时满足原作者许可/资产替换、内容分级与审核、AIGC 标识、平台政策允许、成本可控、法务确认。
5. **若目标是服务自己的 `fashion-inspo`**：只导入全年龄子集、新增 `pose_gallery` 来源、复用现有 i2i，不需要改动这个静态仓库（本项目后来正是这么做的，但生成效果问题见结项报告）。

**Kill criteria**：原作者拒绝授权、上游政策不允许、样本质量不达标、无法控制成本或审核 → 立即停在 P0。

---

## 9. 最终结论

1. **技术可行性：高。** 没有阻碍 i2i 的技术债；900×1200 多角度白底线稿、筛选 UI 与结构化数据是优质输入侧；真正缺口是「推理 + 任务 + 存储 + 鉴权 + 审核」服务层。
2. **纯静态仓库内独立接入：不可行。** Pages/Workers 不能跑 GPU；Workers AI 无 ControlNet/OpenPose 姿态条件，内容政策也不适合本站素材。
3. **个人/本地：推荐。** 复用现有 ComfyUI + Qwen-Image-Edit；但后续实测表明「线稿直接作编辑参考」姿势不跟随，必须用 lineart/depth 控制，且仍解决不了身份/服装一致性（见结项报告）。
4. **公开/商用：条件性可行，当前不建议**——图片授权与成人内容合规是前置门槛，3.1k★ 会放大滥用与成本风险。
5. **一句话**：这个项目适合继续做「参考图库」，不适合直接变「公开生成站」；生成能力应放在用户自己的工具或一个受控的独立服务里。
