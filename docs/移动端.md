# 移动端（React Native / Expo）——移植判定与构建手册

> **状态**：现行（2026-10-31 合并《移动端移植方案》+《移动端构建》两份文档）。如与代码不一致，以代码为准。
> 本文两部分：**前半**说明哪些 Web 功能搬到手机、为什么；**后半**是本机 Android APK 构建与真机踩坑手册（环境特定，换机器需替换路径/端口）。
> 基线：Web 19 个页面 / 后端 24 个路由模块；手机端 4 个 tab（素材库 / 搜索 / 采集 / 设置）+ 详情页；**M2–M5 已完成**（2026-10-28，versionCode 28 / 0.5.0）。

---

## 1. 一句话结论

**手机是「随手采集 + 随手浏览 + 轻编辑」的工具，不是「桌面工作台」**。凡是需要表格批量操作、长时间跑任务、依赖 PC 环境（Playwright / ComfyUI）的功能，都留在电脑上。

判定标准（按顺序问）：

1. **数据是否已在手机上可获得？** 只调 `/api/*` 的天然可移植；依赖 PC 本地进程（ComfyUI、Playwright、Ollama）的手机只能当遥控器；
2. **交互是否适合触屏？** 瀑布流、多列网格、滑动、长按、拍照、相册多选适合；密集表格、右键、拖拽排序、多选批量打标签不适合；
3. **是否需要长时间驻留？** 采集/人脸扫描/批量出图是分钟级到小时级，RN 息屏即断，手机只适合「发起 + 看进度 + 看结果」；
4. **使用频次与场景？** 通勤翻素材、买衣服拍照入库是高频；改标签规则、清数据、管模型是低频且危险。

> 实践版判定公式：**只要有一步需要「盯着多个字段做决策」，就不移植。**

## 2. 功能矩阵（判定 + 现状）

### 2.1 已移植（M2–M5）

| 模块 | 手机能力 | 备注 |
| --- | --- | --- |
| 素材库首页 | 两列网格 + 下拉刷新 + 无限滚动 + 收藏；顶部胶囊（全部/收藏/已标注/未标注）+ 排序轮转（最新/最早/评分/随机） | 不做真瀑布流（高度测量抖动、收益低） |
| 长按多选 | 收藏/取消收藏、加合集、移入垃圾桶（软删除可恢复） | 批量接口 `batch-favorite` / `batch-trash` |
| 合集 | 合集宫格（封面/名称/数量）→ 分页网格；多选态「加合集」只列一级手动合集（智能合集/二级收藏夹不可投递） | 拖拽排序不做 |
| 素材详情 | 大图/全屏看图、标签编辑（弹层搜索/勾选/新建）、移入垃圾桶、相似推荐、加入合集 | 视频分流到播放器 |
| 搜索 | 关键词 + 分页；以图搜图（相册选图 → `POST /search/vector`）；标签多选弹层（2 万+ 标签虚拟化） | 语义搜索未上手机 |
| 上传 | 相册多选（≤20）+ 拍照，逐张进度 + 失败重试 + AI 分析状态轮询 | 不做拖拽/粘贴 |
| 任务中心 | 只读列表 + 失败原因 + 取消（二次确认） | 暂停/恢复/删除留 Web |
| 人物 | 穿搭博主 / 模特双 Tab 列表 + 作品墙（分页） | 不做新建/编辑/合并 |
| 标签管理 | 浏览（虚拟化）+ 搜索 + 改名 | 合并/删除/颜色/排序留 Web |
| 出图记录 | 只读：批次列表 → 候选图网格（`?w=400`）→ 全屏预览 | 不做参数面板/提交（依赖 PC ComfyUI） |
| 分享 Intent | 图片 → 入库；含链接文本 → `/inspirations/from-url`；其它提示不支持 | `expo-share-intent@3.1.0` |
| 视频浏览 | 卡片加「▶ 视频」角标；详情用 `expo-video` 播放（poster + 原生控件 + 全屏/PiP） | 2,760 条视频素材 |

### 2.2 不移植（理由）

| 页面 | 理由 |
| --- | --- |
| 采集管理 `/scraper` | 依赖电脑 Playwright + 浏览器环境，手机只能当遥控器 |
| 素材管理 `/admin` | 密集表格 + 批量勾选，桌面工作流，误触成本高 |
| 数据治理 `/admin/governance` | 批量清理/不可逆操作，危险操作不该放随手可点的设备 |
| 数据洞察 `/admin/insights` | 图表 + 向量库状态，屏幕也装不下 |
| AI 模型管理 `/models` | 运维配置（模型文件/显存/ComfyUI 参数），一年改一次 |
| 人脸库扫描 `/face-scan` | 分钟级批处理 + 逐条决策，手机只看最终人物列表 |
| 模特照片上传 `/model-photos` | 565 行重度上传流程（多角度/裁剪/绑定） |
| 标签高级管理 `/tags/advanced` | 分类树维护、规则配置 |

补充判断：**瀑布流**不做（RN 测量抖动）；**拖拽排序**不做（触屏与滚动冲突，改上移/下移）；**右键/hover** 改长按菜单；**批量打标签**不做（选完标签看不到画面，易打错）。

### 2.3 手机「反向优势」（比 Web 更强，优先做）

1. **拍照即入库**：相机 → 上传 → 自动 AI 打标；
2. **相册多选批量上传**：一次 20 张，逐张进度；
3. **以图搜图**：逛街拍同款找相似（手机是自然入口）；
4. **分享到 App**（Android Share Intent）：小红书/抖音点分享直接进素材库。

## 3. 跨端复用与统一约定

| 可直接复用 | 不可复用 |
| --- | --- |
| `shared/types/*`（`Inspiration`/`Tag`/分页结构，mobile 已 `@shared/*` 引用） | Vue 组件（模板/CSS/Arco 全不通用） |
| 接口契约与错误格式 `{detail: "..."}`；axios 客户端 baseURL 动态注入 + `normalizeBaseUrl` | 图表（Arco/自绘 → RN 需 victory-native/skia，本就不移植洞察页） |
| 纯函数：`sourceLabel`（两端各一份，需同步维护）、时间格式化 | 表格类页面（全部不移植） |

**新增功能时遵守**：图标一律用 `mobile/components/Icon.tsx`（不要写 `<Ionicons>`）；大图浏览用已封装 `ImageViewer`；列表用 `FlatList`（两列 `numColumns={2}`），分页用 `onEndReached`；后端字符串字段渲染前做类型兜底（`sourceLabel`/`getFileUrl` 已加）。

## 4. 构建 Android APK（本机手册）

手机没有 Google Play → 装不了 Expo Go → **只能自建 APK**。以下是实测撞出来的固定动作（2026-10-23）。

### 4.1 工具链（一次性）

| 组件 | 位置 |
| --- | --- |
| JDK 17 | `C:\Users\Administrator\jdk17\jdk-17.0.20.1+1`（系统默认 java 是 25，Gradle 8.10 不认，**必须显式 `JAVA_HOME`**） |
| Android SDK | `C:\Users\Administrator\AndroidSdk`（platform-tools / platforms;android-35 / build-tools 35 / NDK 26.1 / CMake 3.22） |

### 4.2 必须在短真实路径构建

项目在 `...\Desktop\Claude Code\...`（带空格），CMake 会把源路径压成 `Claude_Code`，react-native-reanimated 的 C++ 对象路径超 Windows MAX_PATH → ninja `mkdir` 失败。`mklink /J` 和 `subst` 都会被 Gradle/CMake 解回真实路径（都试过，无效）——只能**真实复制**到短路径构建：

```bash
robocopy "<repo>\mobile" "C:\mb" /MIR
cd C:\mb\android
set JAVA_HOME=C:\Users\Administrator\jdk17\jdk-17.0.20.1+1
set ANDROID_HOME=C:\Users\Administrator\AndroidSdk
.\gradlew assembleRelease
# 产物：C:\mb\android\app\build\outputs\apk\release\app-release.apk
```

**版本号**：`android/` 是 prebuild 生成物且已 gitignore；`versionCode`/`versionName` 直接改 `C:\mb\android\app\build.gradle`，且必须用**正则**改——`/MIR` 会用仓库里的旧 `build.gradle` 覆盖副本，按字符串替换会静默失配（踩过：打的包版本号没变）。

**prebuild 重跑后要补的两行**（`android/` 会被重置）：

- `android.kotlinVersion=1.9.24`——RN 0.76 带 Kotlin 1.9.24，`android/build.gradle` 的 ext 默认 1.9.25，会让 expo-modules-core 报 Compose 1.5.15 与编译器不匹配；
- `android.usesCleartextTraffic: true`（写在 `app.json` 的 `expo-build-properties` 里，不需手改 gradle）。

### 4.3 提速配方（实测 6m37s → 31s；无改动重跑 9s）

| 做法 | 收益 | 说明 |
| --- | --- | --- |
| **不要加 `--no-daemon`** | 最大 | 冷启 JVM + 重新配置 2~3 分钟，daemon 复用后配置阶段几秒 |
| **纯 JS 改动不要清** `android/.cxx` / `build/` | 最大 | 清一次就全量重编 reanimated、expo-modules 的 C++（几分钟）；只有动原生依赖才需要清 |
| `reactNativeArchitectures=arm64-v8a` | 中 | 手机是 arm64，编 4 个 ABI 纯浪费（仓库侧 `gradle.properties` 已配） |
| `org.gradle.caching=true` + `jvmargs -Xmx4096m` | 中 | 任务产物复用；2G heap 偏小（已配） |
| **Defender 排除** `C:\mb`、`~/.gradle`、`AndroidSdk`、仓库目录 | 大 | 实时扫描极拖慢（62s → 31s）；`Add-MpPreference -ExclusionPath` 需管理员（已配） |
| 不要开 `--configuration-cache` | — | Expo/RN 插件有 45 处不兼容，直接 BUILD FAILED（试过） |

**两个环境陷阱**：Gradle 依赖走本机代理（clash 7890，`android/gradle.properties` 里 `systemProp.http(s).proxyHost/Port`；代理没开就删掉，依赖已缓存时不影响增量构建）；**npm 不要设代理**（走 npmmirror，设了必 `ECONNREFUSED`）。

**日常改 UI 更快路子（未落地）**：装一次 debug APK + `npx expo start --host lan`，手机同网 Fast Refresh，改 JS 秒级生效、完全不用打包。

### 4.4 增量同步不要用 `/MIR`

`/MIR` 会删掉 `C:\mb\android\build`、`.cxx`，等于每次全量重编原生（几分钟）。日常改 JS 用 `/E`（只覆盖不删除），保留构建缓存后一次 **30~40 秒**；只有依赖大改/换 prebuild 产物时才 `/MIR`。

## 5. 真机踩坑（都已修，新增功能勿回退）

| 坑 | 现象 | 根因与修法 |
| --- | --- | --- |
| **图标空白** | 真机所有图标（tab/按钮/爱心/返回）全空白、无报错 | `@expo/vector-icons` 用**小写 fontFamily**（`'ionicons'`），字体必须内嵌 `assets/fonts/ionicons.ttf`；且组件挂载前判 `Font.isLoaded('ionicons')`，expo-font 只认自己 loadAsync 过的字体 → 判假渲染空 `<Text />`。结论：字体由 `app.json` 的 `expo-font` plugin 内嵌，`Icon.tsx` 直接用 family 画码点；**不要改回 `<Ionicons>`**，也不要在 `_layout` 用 `useFonts` 做字体门（加载失败会整页白屏）。这类只有真机能复现，用 `adb logcat` + 探针最快 |
| **视频播放** | 点开视频报「找不到模块」 | `expo-video` 是原生模块（SDK 52 对应 `~2.0.6`，`expo-av` 已弃用）；装完必须重跑 `prebuild` + 完整重建。`app.json` 配 `["expo-video", { "supportsPictureInPicture": true, "supportsBackgroundPlayback": false }]`；播放器封装 `components/VideoPlayer.tsx` |
| **冷启动请求竞态** | 首次进页面「加载失败」，重进又好，时好时坏 | 页面 mount 就发请求，而 `loadApiBaseUrl()`（读 AsyncStorage）未完成 → baseURL 还是默认 `10.0.2.2`。修法：`apiClient` 请求拦截器里 `await ensureBaseUrl()`（缓存 Promise），`saveApiBaseUrl` 后同步刷新；新增「启动即请求」页面不用再关心顺序 |
| **分享 Intent** | 分享后重复入库 / 不生效 | `expo-share-intent@3.1.0`（对应 SDK 52；4.x 起要 SDK 53+）；`app.json` 配 `androidIntentFilters: ["image/*","text/*"]` + `disableIOS: true`，prebuild 写入 `AndroidManifest` 的 `ACTION_SEND`（改配置必须重跑 prebuild）；处理逻辑在 `components/ShareIntentBridge.tsx`，处理完必须 `resetShareIntent()` |
| **npm 依赖被删** | 打包失败/缺包 | `npm i --legacy-peer-deps` 会**删掉一批包**（实测两次：删 `expo-linking`、删 63 个）；装完立刻检查 `expo-linking`/`expo-font`/`expo-asset`/`expo-router` 是否还在 |
| **mergeDexRelease 文件占用** | `:app:mergeDexRelease` 报「另一个程序正在使用此文件」 | `./gradlew --stop` + 删 `app/build/intermediates/dex/release/mergeDexRelease` 再构建 |
| **标签墙 ANR** | 2.2 万标签渲染 chip 墙 → JS 阻塞、系统无响应 | 改 FlatList 虚拟列表 + 默认 60 个 + 搜索最多 200 条，并加「标签库加载失败 → 重试」；`GET /api/tags` 一次 4.3 MB / 8.2 秒，需会话级缓存 |
| **分享文本 URL 解析** | 抖音/小红书文案中链接紧贴中文（`…/abc123/，谢谢`） | `utils/extractUrl.ts` 排除中文与全角标点；`shareIntent.test.tsx` 覆盖 9 项 |

## 7. 风险与注意事项

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 后台任务中断 | RN 息屏后 JS 停跑，轮询会断 | 任务中心只在前台轮询；文案「回到 App 自动刷新」 |
| 局域网依赖 | 手机必须与电脑同网，换 WiFi 就失效 | 空态给「检查后端地址」入口 + 一键重试 |
| 大数据量列表 | 后端 total 3 万+，翻到底不现实 | 必须筛选/搜索；列表用 `thumbnail_path`，详情/全屏才取原图 |
| 危险操作 | 删除/垃圾桶在手机上极易误触 | 一律二次确认；批量删除只给「移入垃圾桶」（可恢复） |
| 设备差异 | 只在 nova 7 Pro（1080×2340 / 423dp）验证过 | 布局用 flex + 百分比，不写死像素 |
