## 2. 安装 ComfyUI（Windows portable）

> 为什么用 ComfyUI：它是本次所有候选模型（Z-Image / Qwen-Image / Flux / HiDream / SDXL）**都能跑**的唯一界面，
> 且 RTX 50 系（Blackwell）首发即支持。不要装 A1111/ComfyUI 混合体，会互相污染环境。

### 2.1 下载与解压

1. 打开 ComfyUI Releases 页（见文末来源 6），下载 **Windows portable（NVIDIA）** 包，
   文件名形如 `ComfyUI_windows_portable_nvidia.7z`（以页面当前为准）。
2. 解压到第 1.2 节选定的目录，例如 `D:\AI\ComfyUI`。
3. 解压后目录里应有：`ComfyUI\`、`python_embeded\`、`run_nvidia_gpu.bat`。

- [ ] `D:\AI\ComfyUI\python_embeded\python.exe -V` 能打印 Python 版本（portable 自带，**不要**用系统 Python，也不要装进项目虚拟环境）。

### 2.2 校验 PyTorch 的 CUDA 版本（Blackwell 必查）

RTX 50 系**必须** PyTorch 构建于 CUDA 12.8 及以上；自带包若低于此，启动会报 `no kernel image is available` / `sm_120` 相关错误。

```powershell
cd D:\AI\ComfyUI
.\python_embeded\python.exe -c "import torch;print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0), torch.cuda.get_device_capability(0))"
```

- [ ] 能打印出显卡名与 `(12, 0)`（sm_120）。
- [ ] 若 `torch.version.cuda` 为空或 < 12.8，或上一条命令报错，执行升级：

  ```powershell
  .\python_embeded\python.exe -m pip install --upgrade torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
  ```

  升级后**重跑上面的校验命令**，必须打印 `(12, 0)` 且无异常。

- [ ] 再做一次真实显存分配测试（能排除「装上了但跑不了」）：

  ```powershell
  .\python_embeded\python.exe -c "import torch;x=torch.zeros(1024,1024,device='cuda');print('cuda ok', x.sum().item())"
  ```

### 2.3 首次启动

```powershell
.\run_nvidia_gpu.bat
```

- [ ] 控制台出现 `Starting server` 且提示地址 `http://127.0.0.1:8188`。
- [ ] 浏览器打开该地址能看到默认工作流。
- [ ] 接口自检：

  ```powershell
  Invoke-RestMethod http://127.0.0.1:8188/system_stats | ConvertTo-Json -Depth 4
  ```

  返回里有 `system.device`（显卡名）与 `vram_total`（≈16 GB）。

> 启动方式：日常用 `run_nvidia_gpu.bat` 双击即可；本清单**不创建**任何开机自启/服务。

## 3. 模型下载（按档位，可只做第 1 档）

> 目录约定（**portable 包的内层目录**，即 `D:\AI\ComfyUI\ComfyUI\models\...`）：扩散模型 `models\diffusion_models\`、文本编码器 `models\text_encoders\`、
> VAE `models\vae\`、单体 checkpoint（SDXL/Flux 合并版）`models\checkpoints\`、LoRA `models\loras\`。
> **放错目录 = 模型列表里看不到**（第 8 节有对照表）。

### 档位 A（必须先装）：Z-Image-Turbo —— 速度/画质最平衡

- 权重来源：`Comfy-Org/z_image_turbo`（见来源 5）。
- 典型文件（**以仓库当前文件名为准**，这里只是形态）：
  - 扩散模型 `z_image_turbo*.safetensors`（约 12 GB）→ `models\diffusion_models\`
  - 文本编码器 `qwen_3_4b*`（Z-Image 用 Qwen3-4B 作编码器）→ `models\text_encoders\`
  - VAE `ae.safetensors` → `models\vae\`
- 下载命令（示例，**先报体积给用户确认**）：

  ```powershell
  cd D:\AI\ComfyUI
  $env:HF_ENDPOINT="https://hf-mirror.com"          # 直连 HF 可用就删掉这行
  .\python_embeded\python.exe -m pip install -U huggingface_hub
  # 用 Python API 下载，避开 CLI 版本差异（hf / huggingface-cli / 子命令改名）
  .\python_embeded\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('Comfy-Org/z_image_turbo', local_dir=r'D:\AI\models\z_image_turbo')"
  ```

- [ ] 下载完成后按第 4.1 节跑通、并记录 1024² 的第二次耗时（第三方同款显卡实测约 **17.5 s**，见来源 1）。

### 档位 B（推荐）：Qwen-Image-2.1 int8 —— 2K / 透明 / 多参考图

- 权重来源：`Comfy-Org/Qwen-Image-2.1`（见来源 4）。
- 选 **int8** 扩散模型（约 7.26 GB；bf16 版 14.2 GB 会挤爆 16 GB 余量）+ 对应的 INT8/W4A8 文本编码器 + 专用 VAE。
- 工作流模板：`Comfy-Org/workflow_templates` 里的 `image_qwen_image_2_1_t2i.json`（文生图）与
  `image_qwen_image_2_1_image_edit.json`（编辑/多参考图）。
- ⚠️ **许可**：Qwen Research License——**默认仅研究/评估**，商用需另行授权。用户若要商用，先停下来确认，不要装。
- [ ] 装完能用 1 张参考图做「编辑」，并用 3~5 张单品图做一次「多参考拼穿搭」，确认不 OOM。

### 档位 C（可选）：FLUX.1 dev fp8 —— 生态最强（LoRA/ControlNet 最多）

- 选 **fp8**（约 12 GB，fp16 要 23.8 GB，见来源 3）；显存吃紧时换 GGUF Q4（6~8 GB）。
- 需要 `clip_l` + `t5xxl_fp8_e4m3fn` + `ae.safetensors` 三件套（目录见上）。
- GGUF 版本必须先装插件 **ComfyUI-GGUF**（见来源 7），否则 `Unet Loader (GGUF)` 节点不存在：

  ```powershell
  cd D:\AI\ComfyUI\ComfyUI\custom_nodes
  git clone https://github.com/city96/ComfyUI-GGUF
  D:\AI\ComfyUI\python_embeded\python.exe -m pip install -r ComfyUI-GGUF\requirements.txt
  ```

### 档位 D（可选，尝鲜）：HiDream-I1 fp8 —— 中文提示词理解强

- 显存对照（来源 2）：bf16 34.2 GB / **fp8 17.1 GB（标注 16 GB 显存）** / GGUF Q4≈12 GB / Q2≈8 GB。
- 代价：要额外 4 个文本编码器（clip_l / clip_g / T5-XXL fp8 / Llama-3.1-8B fp8），合计体积不小。
- 16 GB 显存跑 fp8 属于**刚好卡线**：分辨率不要超 1024²，batch 只能是 1。

### 档位 E（可选，批量基线）：SDXL

- 单体 checkpoint 放 `models\checkpoints\`（`sd_xl_base_1.0.safetensors` 一类）。
- 用途：批量初筛（配合 4 步加速 LoRA），单张 2~4 s；画质与文字不如上面几档。

## 5. 与 Ollama（项目打标服务）的显存互斥

16 GB 显存**不能同时**舒服地跑 `Qwen3-VL:8B` 和出图大模型。

### 5.1 出图前：让 Ollama 释放显存（用户手动执行，执行者不要代跑）

```powershell
ollama ps              # 看当前驻留的模型
ollama stop qwen3-vl:8b-instruct    # 卸载（名字以 ollama ps 输出为准）
```

项目侧还有现成接口（后端默认端口 **18888**，以 `backend\.env` 的 `PORT` 为准；需 api key，若已配置）：

```
POST http://127.0.0.1:18888/api/ai/unload-model
```

### 5.2 出图后：正常启动项目任务即可，Ollama 会自动重新加载模型

- [ ] 把上面的「出图前 `ollama stop`」写进使用习惯（本清单不改项目配置、不加脚本）。
- [ ] **不要**为了自动化去改后端代码/worker 逻辑。

## 8. 故障对照表（按症状查）

| 症状 | 常见原因 | 处理 |
| --- | --- | --- |
| 启动报 `no kernel image is available` / 提到 `sm_120` | PyTorch 的 CUDA < 12.8（Blackwell 不支持） | 按 2.2 升级到 cu128 及以上，重跑校验 |
| `torch.cuda.is_available()` 为 False | 装成了 CPU 版 torch，或驱动太旧 | 重装 cu128 轮子；确认 `nvidia-smi` 正常 |
| 加载模型时 `Allocation on device` / OOM | 选了 bf16/fp16 大模型，或 Ollama 还占着显存 | 换 int8/fp8/GGUF Q4；先 `ollama stop` |
| 模型列表里看不到刚下的文件 | 放错目录（diffusion / text_encoders / vae / checkpoints） | 按第 3 节目录约定移动，刷新页面 |
| 节点 `Unet Loader (GGUF)` 不存在 | 没装 ComfyUI-GGUF 插件 | 按档位 C 的命令安装并重启 |
| 出图糊 / 全黑 | 文本编码器或 VAE 选错（尤其 Flux 系要 `t5xxl` + `ae`） | 核对三个加载节点 |
| 下载到一半失败 | HF 直连不稳 | 设 `HF_ENDPOINT=https://hf-mirror.com`，用支持续传的命令重试 |
| 出图极慢（> 5 min/张） | 模型被 CPU offload（内存不足 16 GB 常见） | 降分辨率/换小模型；考虑加内存 |
| 浏览器打不开 8188 | 端口被占 / 进程已退出 | `Get-NetTCPConnection -LocalPort 8188`；换端口或重开 |
