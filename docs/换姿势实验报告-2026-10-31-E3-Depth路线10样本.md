# E3 实验报告：Depth 路线（Depth Anything V2 → SDXL depth ControlNet → 换脸）10 样本

> **状态**：已结项（2026-10-31）。本方向已停止测试与实验，完整复盘（11 轮失败实验、资产、教训）见
> [换姿势方向结项报告](换姿势方向结项报告-2026-10-31.md)；本文仅保留逐样本过程数据。


> 目的：绕开「lineart 关节圆」与「Qwen int8+LoRA 崩坏」，用**深度图**当姿势控制信号（社区 MOSS/Krea2 同思路），
> 先验证姿势与伪影，再用 A 方案换脸补身份。样本：10（与之前同一批素材/姿势，可直接对照）。
> 结论先行：**这是目前最好的一版**——**关节圆/护具伪影完全消失**，姿势均分 **3.7/5**，
> 换脸后身份余弦 **-0.08 → 0.81**，单张约 **20~25 秒**（比 R2-C 的 96 秒快 4 倍）。
> 仍未解决：**服装/发型/场景不是主体的**（生成的是通用紧身衣/黑裙），所以只能算「换姿势 + 换装」的可用链路。

---

## 1. 流程

```text
图库姿势线稿
   └─ Depth Anything V2 Small（ONNX，99 MB，CPU 推理）
        └─ 深度图（900×1200，近白远黑）
             └─ SDXL base + ControlNet-Union depth（strength 0.75，0~50% 步）→ 10 张
                  ├─ A: txt2img（只验证姿势/伪影）
                  ├─ B: img2img denoise 0.70（主体图初始化，保留身份/场景）
                  └─ C: img2img denoise 0.85（更强姿势控制）
                        └─ A 的结果再做 InsightFace 换脸（保留主体脸）
```

| 项 | 配置 |
| --- | --- |
| 深度模型 | `onnx-community/depth-anything-v2-small`（Apache-2.0，ONNX 99 MB；`D:/AI/ComfyUI/ComfyUI/models/depthanything/`） |
| 出图模型 | SDXL base 1.0 + ControlNet-Union SDXL promax（union type=`depth`） |
| 参数 | 30 steps / cfg 7 / dpmpp_2m / karras / 896×1152；depth strength **0.75**、控制区间 **0~0.5**（社区建议「提前结束深度控制」减少素体外观） |
| 样本 | 10（沿用 r2_batch10 的 10 素材 / 10 姿势，seed 20261029+i） |
| 换脸 | InsightFace inswapper_128（源=主体原图，目标=depth txt2img 结果），GFPGAN 修复略（本轮统计未做修复） |
| 脚本 | `make_depth_maps.py`（离线深度图） + `r2_controlnet_poc.py --control-type depth` |

## 3. 量化结果

| 指标 | 结果 |
| --- | --- |
| **关节圆/护具伪影** | **10/10 消失**（深度控制不渲染线稿线条，对比 lineart 的 10/10 出现） |
| 姿势保真（txt2img，人工 1~5） | **3.7/5**（站/跪/坐/扶墙都跟随；桥式仍偏差；俯仰角不保证） |
| 身份余弦（txt2img 原图） | **-0.081**（≈0/5，纯生成脸） |
| 身份余弦（换脸后） | **0.814**（9/10；s06 主体背身无脸→失败；s09 有面部遮挡伪影，0.636） |
| img2img 0.70 | 姿势下滑到约 2.5/5，身份/场景有部分保留（s02/s03/s04 明显更像主体） |
| img2img 0.85 | 姿势约 3.5/5，身份仍弱（≈1/5） |
| 画面质量 | 3/5（比 lineart 版干净很多，无护具；但服装是通用紧身衣，s09 面具伪影、s06 结构拉伸） |
| 单张耗时 | 深度图 ~1 s + SDXL 15~25 s + 换脸 ~3 s ≈ **20~25 s/张**（R2-C 为 ~96 s） |

## 4. 结论

1. **深度控制解决了 R2-A 最丑的问题**：关节圆圈不再变成护具/机甲装饰（这是之前「鬼图」的主因）。
2. **姿势可用**（3.7/5），且速度接近 R1（20~25 s vs 31 s）；比两段式 Qwen 快 4 倍。
3. **身份可以由换脸补到 0.81**（A 方案），但**服装/发型/场景仍是模型自由生成**；
   img2img 0.70 能保一点身份/场景，但姿势会掉——「姿势 vs 服装」的跷跷板仍在。
4. **当前最好的可用组合**：`depth 姿势 + txt2img + 换脸` ≈ 25 s/张，得到「姿势对、脸对、衣服不对」的图；
   如果产品定位是「换装 + 换姿势」（而不是严格保留原素材穿搭），这条链路已经可交付。

## 5. 下一步（只剩「服装/发型」一个核心缺口）

| 方案 | 思路 | 代价 | 判断 |
| --- | --- | --- | --- |
| E3+F 提示词补充服装 | 用 `/api/pose` 之类方式拿到主体服装描述后注入 SDXL prompt（**不依赖本地 VLM**：可让用户手填/从素材标题猜） | 0 | 最快；服装近似可做，但细节不保 |
| img2img 0.70 + depth 强度调高 | 在保身份与保姿势间找中间点（0.75） | 0 | 已看到跷跷板，收益有限 |
| 分割/局部重绘服装 | 用 mask 保服装区域，其余用 depth 生成 | 1~3 GB 模型 + 1~2 人日 | 唯一能真正保衣服，工程复杂 |
| 接受「换装」定位 | 文档/UI 明确「换姿势会重绘服装」 | 0 | 如果用户接受，当前链路即可用 |
