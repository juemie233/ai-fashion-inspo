# 手机图裁剪增强分析报告（100 张素材行剖面诊断）

> 分析时间：2026-08-20 ｜ 数据源：最近 100 张手动上传图片素材（`source_type=manual_upload`，未删除，竖屏）
> 分析脚本：`backend/scripts/analyze_crop_candidates.py`（只读，不修改任何数据）

## 1. 结论速览

- **100 张全部检测出内容区边界**（上下都有可裁区域），说明这批手动上传素材几乎全是「手机截图/视频截图」类图片，剪裁功能价值高。
- 用户预判的两种类型均得到验证，且参数高度聚类（见 §3）：
  - **类型一（灰带包夹）**：21 张（21%）——上下有明显分界，分界外侧是灰色/深色平坦地带，裁剪边界清晰。
  - **类型二（状态栏 + 播放器条）**：63 张（63%）——顶部手机状态栏（界限不明显）、底部视频播放器控制条/进度条（界限较明显）。
  - 两类同时命中 19 张（含状态栏的灰带包夹图）。
- 视觉抽查确认：灰带包夹样本的红/绿裁剪线正好落在「灰带 → 照片」边界；播放器条样本的线落在「状态栏 → 画面」「画面 → 播放器条」边界。

## 2. 检测方法与特征定义

对每张图统一缩放到 **96 像素宽**，逐行提取三个剖面（0~1 归一化）：

| 剖面 | 含义 | 典型取值 |
| ---- | ---- | ---- |
| 亮度 `b` | 行内像素灰度均值 | 灰带 ~0.1~0.3（深灰）、黑色区域 ~0.05 |
| 饱和度 `s` | 行内 HSV 饱和度均值 | 灰带 < 0.2，内容区更高 |
| 多样度 `d` | 16 级量化后行内唯一色占比 | 灰带 < 0.08，状态栏图标行 0.15~0.24，内容区 ≥ 0.22 |

**内容区边界检测**：内容行 = `d ≥ 0.15`；从图顶向下找首个「连续 ≥3 行内容」的区段起点为上界，从图底向上对称找下界；内容区内部容忍 ≤5 行缺口（照片中的纯色块/暗部）。

**状态栏修正**：顶部 12% 高度内的首个内容簇若多样度中位 < 0.25，且其后 20% 高度内存在多样度中位 ≥ 首簇 × 1.25 的内容簇，则首簇判定为状态栏图标行，上界后移到后续簇起点。

### 3.3 播放器条特征（视觉+剖面双重确认）

底部「进度条」区域 = 黑色条带 + 亮度层次：内容区底部（b≈160）→ 深色条（b≈65，d<0.05）→ **进度条亮点行**（b≈126，d≈0.07）→ 纯黑（b<30）。进度条亮点行的亮度突跳是底部边界的可靠锚点。

## 4. 增强方案建议

### 4.1 检测算法（建议落地到 `crop_service`）

在现有 `auto`（黑边检测）之外新增**内容边界模式**（如 `mode="content"`）：

```
行多样度剖面 d（缩放 96 宽，逐行量化唯一色占比）
  → 内容区边界（d≥0.15 连续 3 行起步，容忍 ≤5 行缺口）
  → 状态栏修正（顶部首簇多样度显著低于后续簇 → 后移上界）
  → 灰带确认（可选，用于分类标注：外侧 sat<0.2 且亮度平坦）
  → 输出 (top_frac, bottom_frac) 裁剪比例
```

### 4.2 待实验参数（前端可暴露调节，或先写死再按反馈调）

| 参数 | 当前建议值 | 实验方向 |
| ---- | ---- | ---- |
| 内容行多样度阈值 `min_d` | 0.15 | 调高 → 更激进（多裁）；调低 → 更保守 |
| 内容区最小连续行 `min_run` | 3 | 抗噪 |
| 内容区内部最大缺口 `max_gap` | 5 | 照片暗部抗截断 |
| 状态栏修正多样度比 | 首簇 < 0.25 且后续 ≥ 首簇×1.25 | 顶部分界不明显时的关键参数 |
| 顶部裁剪下限保护 | 建议 ≥ 1.5%（防误裁薄边框图） | — |
| 底部裁剪上限保护 | 建议 ≤ 32%（防裁进照片） | — |

### 4.3 前端配合

- 扫描结果卡片增加「裁剪预览线」（红线上界/绿线下界叠加缩略图），人工勾选前先目检。
- 「自动检测失败」时回退到当前固定比例模式，保持现有降级链路。

## 6. 遗留问题

- 状态栏与内容区多样度存在过渡带（0.15~0.24），个别图的状态栏修正可能多裁/少裁 1~3 行，需实际运行后人工抽查反馈调参。
- 内容区内部若有「大面积纯色块」（如照片背景是纯色墙），`max_gap` 容错可能越过真实边界，需在实测中验证。
- 本报告数据全部来自当前 100 张样本；新上传素材形态变化后参数可能需要微调。
