## 1. 素材与数据

| 术语 | 含义 | 真源 |
| --- | --- | --- |
| **素材 / 灵感** | 一条穿搭图片或视频记录，主键是 **UUID 字符串**（客户端可预生成，分享链接不可枚举） | `backend/app/models/inspiration.py` |
| **来源类型** | `manual_upload` / `scraper` / `xiaohongshu` / `douyin` / `browser_extension` / `generated` / `batch_import` / `url_import`；前端必须显示中文 | `web/src/utils/sourceLabel.ts`、`mobile/utils/sourceLabel.ts` |
| **垃圾桶 / 软删除** | 素材不物理删除，写 `deleted_at` / `trash_reason` / `trash_source` 三字段，可恢复 | `services/inspiration_trash.py` |
| **三字段同真同假** | 软删除不变量：进垃圾桶时三字段都有值，恢复时都清空；由 `verify_trash_invariants` 校验 | `services/inspiration_state.py` |
| **删除原因 vs 删除来源** | `trash_reason` = 为什么删（质量差/重复/不喜欢/隐私/其他/AI生成）；`trash_source` = 谁移入（manual/auto） | `schemas/inspiration.py` |
| **隐私** | 删除原因之一；**不进负样本**（隐私图不是“穿得不好”，学进去会误判露肤/私密场景） | `quality_learner.NEGATIVE_EXCLUDED_TRASH_REASONS` |
| **负样本** | 用于训练质量初筛器的“不想要”样本：垃圾桶素材（隐私除外） | `services/quality_learner.py` |
| **平台 ID** | 笔记/作品在来源平台的 ID（小红书 note id、抖音 aweme id）；库内受**部分唯一索引**约束，软删除后释放 | `models/inspiration.py` |
| **合成平台 ID** | f2 导入旧素材用文件名算出的 `f2:<19位作品ID>#<类型><序号>`；与真实作品 ID 无法互推 | `task_runners/f2_library_ids.py` |
| **内容哈希** | 文件 SHA-256，用于上传/导入去重；存量素材可回填 | `inspiration.content_hash` |
| **pHash** | 感知哈希（768 位 RGB dHash），用于近似重复检测 | `services/near_duplicate_service.py` |

## 2. AI 与质量

| 术语 | 含义 | 真源 |
| --- | --- | --- |
| **打标 / 分析** | 调 Ollama 视觉模型提取标签、主色并落库 | `services/ai_service/analyze.py` |
| **分析日志** | 每次分析的模型名、prompt 版本、原始输出、耗时、错误 | `ai_analysis_log` |
| **提示词版本** | Prompt 内容哈希前 8 位，用于 A/B 与历史追溯 | `ai_analysis_log.prompt_version` |
| **质量审核** | 穿搭二分类 + AI 生成检测，写 `quality_status`（pending/approved/rejected） | `services/ai_service/quality.py` |
| **原因码** | 结构化拒绝原因：`not_outfit` / `single_item` / `partial` / `low_quality` / `ad` / `other`（+ 初筛 `prefilter_reject`） | `services/quality_reason_codes.py` |
| **灰区** | 初筛置信度在 0.5~阈值之间的样本，优先人工复审 | `GET /api/ai/quality-gray` |
| **初筛器 / 负样本学习器** | 用 CLIP 向量训练逻辑回归，在 VLM 审核前拦截高置信度垃圾 | `services/quality_learner.py` |
| **纠错闭环** | 人工“判错了”反馈落 `quality_corrections`，同时改正状态并标 `human` | `services/quality_correction.py` |
| **人工判定保护** | `quality_reviewed_by='human'` 的素材不被随机复审覆盖 | `quality_status` 字段 |

## 3. 标签

| 术语 | 含义 | 真源 |

| **聚类** | 名称相似 + 共现辅助，产出“建议合并组”，人工确认后应用 | `services/tag_cluster.py` |

| **颜色剥离** | 把 `item_type` 标签名里的颜色前缀剥掉并合并撞名标签 | `services/tag_color_strip.py` |

## 4. 任务与采集

| 术语 | 含义 | 真源 |
| --- | --- | --- |
| **任务队列 / worker** | API 写 `task_queue`，独立 worker 进程认领执行；API 与 worker 通过表解耦 | `models/task.py`、`app/worker.py` |
| **认领** | worker 用条件 UPDATE 把 pending 改成 running，保证多 worker 不重复执行 | `worker._claim_next_task` |
| **心跳租约** | worker 每 10 秒刷新心跳；任务心跳超 90 秒视为 worker 已死，重置回 pending | `worker.py` |
| **重负载互斥** | GPU/整批 CPU 任务（分析、审核、向量、人脸、出图）全局串行，避免互相拖慢 | `GPU_EXCLUSIVE_TASK_TYPES` |
| **可暂停 / 可取消** | 按任务类型白名单；前后端两份必须一致，由测试锁定 | `routers/tasks.py`、`web/src/utils/taskPresentation.ts` |
| **断点续算** | 暂停/恢复后跳过已完成部分（按成功日志、已判定状态、`done` 游标等） | 各执行器 |
| **f2** | 上游开源抖音下载工具；本仓库只做调度、判重、入库、打标 | `task_runners/f2_*` |
| **五层判重** | 内容 SHA-256 → 垃圾桶 → 批次内 → 合成平台 ID → 参数过滤 | `build_import_plan` |
| **我的喜欢 / 我的收藏** | f2 两种“我的列表”下载模式；点赞列表只有本人可见，必须填自己的主页链接 | `F2_LIKE_USER` |
| **批次回滚** | 撤销某次 f2 导入；默认只撤“没被人动过”的，物理删除并写审计 | `POST /f2-tasks/{id}/rollback` |
| **采集会话任务** | 浏览器插件一次采集的 `scraper_tasks` 记录，与 `task_queue` 是两套表 | `routers/scraper.py` |

## 5. 人物与人脸

| 术语 | 含义 | 真源 |
| --- | --- | --- |
| **博主 / 模特** | 两张独立表（`bloggers` / `models`），业务分叉：博主按平台账号采集，模特按写真照片组 | `models/person.py` |
| **人物组** | 同一现实人物跨平台账号绑定；列表折叠为一条主账号，可切主 | `POST /bloggers/groups/link` |
| **人脸特征库** | 每位人物一条平均池化 512 维特征；博主可传 1~5 张，模特取写真 Top-K | `blogger_face.py`、`model_face.py` |
| **候选 / 确认 / 驳回** | 批量扫描结果 `pending` 不展示，人工确认后 `confirmed` 才写关联；驳回置 `match_excluded` | `models/face.py` |
| **匹配阈值** | 全局 `FACE_MATCH_THRESHOLD`（默认 0.5），可按人覆盖 | `bloggers.face_match_threshold` |
| **灰度阈值 vs 聚类阈值** | 匹配是一对一（0.5，人工兜底）；聚类是成组合并（建边 0.6，避免连锁误并） | `services/face_cluster.py` |
