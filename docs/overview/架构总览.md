# 项目整体架构

> **状态**：现行（2026-11-16 按代码与索引盘点）。
> 真源：`backend/app/**`、`web/src/**`、`mobile/**`、`scripts/**`；API / 数据模型 / 配置项的逐项清单以 `docs/overview/` 下自动生成文档为准。
> 本文只回答「系统由什么组成、东西放在哪、依赖往哪走、新功能落在哪」，不重复功能方案。

## 1. 一句话

这是一个**单机本地运行的单体多端应用**：Web / 移动端 / 浏览器插件都只通过 HTTP/WS 访问同一个 FastAPI 后端；重任务由独立 worker 消费 `task_queue`；素材、数据库、向量库都在本机，AI、出图、人脸、采集是可选外部能力。

**不采用微服务拆分**：当前只有一台机器、一个用户、一个 SQLite；引入消息队列/服务网格/容器编排只会增加运维成本，不会改善瓶颈。现有边界（API / worker / 独立子服务）已经足够。

## 4. 一条请求 / 一条任务怎么走

```text
Web / Mobile / Extension
  → /api 或 /ws（HTTP、WebSocket）
  → FastAPI router（参数校验、权限、HTTP 转译）
  → service（业务规则、事务、文件/向量/AI 调用）
  → SQLAlchemy model / SQLite + storage

需要重任务时：
  router 只创建 task_queue 记录，立即返回 task_id
  → 独立 worker 原子认领
  → task_runner 按 type 分发到 task_runners/*
  → 更新 progress/result/心跳；失败按可恢复/永久错误分类重试
  → 前端通过 WebSocket 实时刷新，断线时轮询降级
```

`main.py` 里还有三条**进程内周期循环**：垃圾桶清理、定时采集/出图清理、启动补备。它们是单机应用的简化取舍，不是通用调度器；新增「重任务」应走 `task_queue` + worker，不要继续往 API 进程里加长循环。

## 6. 依赖方向与硬规则

目标方向：

```text
view → composable → api/client → 后端 HTTP
router → service → model
worker → task_runner → task_runners → service → model
scripts（CLI/运维）→ app（允许）
app → scripts（仅小红书关注列表 1 处例外）
shared/types 只放跨端类型，不依赖运行时
```

### 已迁移：f2 实现归位到 `app/services/f2`

f2 的共享实现（common / hash_cache / plan / report / apply / fetch / collects / rollback /
inspiration_insert）已经迁到 `app/services/f2/`。应用层统一 `from app.services import f2`，
不再 import 脚本；`backend/scripts/f2_*.py` 只剩 CLI 与兼容转发壳（`import_f2_downloads`
也只剩旧入口转发）。

当前 `backend/app/**` 对 `backend/scripts/**` 的 import 只剩 1 处非 f2 例外：
`app/scrapers/xiaohongshu.py` 复用 `scripts.fetch_xhs_following` 的关注列表解析。
脚本 → app 方向仍然允许（CLI 依赖应用实现）。

处理原则：

- f2 新逻辑只写 `app/services/f2/`，不要再加回 `backend/scripts`。
- 旧的 `scripts/f2_*` 路径保留为兼容壳；新代码不要从这里 import。
- 小红书关注列表这一处后续若要彻底清掉，可把 `fetch_xhs_following` 的浏览器公共函数抽到
  `app/services/scraper` 后再迁；在此之前作为唯一例外明确记录。

### 其他规则

1. `routers` 不写业务规则与文件操作；只做参数、鉴权、HTTP 转译。
2. Web 页面不直接 import axios；统一走 `web/src/api/client.ts`。
3. 跨页共享状态才进 Pinia；页面内状态放 composable。
4. 新任务类型必须同时改 `TASK_HANDLERS`；重负载任务还必须登记 `GPU_EXCLUSIVE_TASK_TYPES`。
5. 新表必须走 Alembic；不要手改 `db_migrations.py` 的 `_SCHEMA_COLUMNS`。
6. 新配置写 `Settings` + `backend/.env.example`；运行 `gen_docs_from_code.py` 更新配置参考。

## 10. 明确不做

- 不把单体拆成微服务；
- 不为目录对称做全量 service 搬迁；
- 不在 API 进程里新增长耗时任务（走 worker）；
- 不引入多用户/权限体系（当前部署边界是单机单用户）；
- 不为了「以后可能」引入通用工作流引擎或消息队列。

后续若要改服务层包结构或测试门禁，按对应专题单独立项，不混在结构整理里。
