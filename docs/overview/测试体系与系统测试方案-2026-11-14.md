# 测试体系与系统测试方案（2026-11-14）

> 状态：**方案 + L2 系统测试已落地 Phase 1/2**（2026-11-14；API 冒烟 + 真 worker 批量分析链路，Phase 3+ 待做）
> 目标：补齐当前测试体系缺的「跨进程 / 故障注入 / 安全 / 契约」层，明确哪些测试值得做、怎么做、放在哪、怎么跑。
> 关联：[异步任务体系](../features/异步任务体系.md)、[备份恢复](../ops/备份与恢复.md)、`scripts/ci/test.sh`

## 1. 背景：现有测试盘点

| 层 | 现状 | 位置 |
| --- | --- | --- |
| 后端单元/集成 | pytest，**进程内 TestClient** + 临时 DB/存储；约 22,600 行语句，覆盖率 88%+ 棘轮 | `backend/tests/` |
| 前端 | vitest：composable / store / 纯函数 / 组件（140 文件 1200+ 用例） | `web/src/**/__tests__/` |
| 移动端 | jest-expo + RNTL（42 套件 400+ 用例）；含渲染裸字符串扫描、设计令牌与对比度扫描 | `mobile/__tests__/` |
| 契约 | `backend/tests/fixtures/api_contract.json` + `shared/types/` | 同上 |
| e2e | Playwright **20 条**，需**手动**起后端（`web/e2e/global-setup.ts` 预检 `/api/health`） | `web/e2e/` |
| 质量门禁 | `bash scripts/ci/test.sh` 13 项；CI 4 个 job（web / mobile / backend / subprojects） | `scripts/ci/`、`.github/workflows/ci.yml` |
| 专项 | 备份/恢复演练、Alembic 迁移链自检、死代码基线、a11y 用例、移动端卡片 fuzz | 分散 |

**结论**：单测与进程内集成已经比较厚；缺的是**跨进程边界**、**故障注入**、**安全**、**契约漂移**这几类。现有 e2e 依赖手动起后端，无法在门禁里稳定跑。

## 2. 缺口与目标

| 缺口 | 风险 |
| --- | --- |
| worker 是独立进程，单测只测函数、不测「API 建任务 → worker 认领 → 写回状态 → API 可见」 | 进程边界/事务边界问题只在真跑时暴露（如 SQLite 写锁、WAL、SIGTERM 回收） |
| 上游（Ollama/ComfyUI/face-service）在单测里都是假对象 | 真实的超时/重试/HTTP 契约错误（路径、字段名）无法提前发现 |
| 无故障注入 | 崩溃恢复、僵尸任务回收、断网/限流只靠人工演练 |
| 安全用例零散 | 认证、路径遍历、SSRF、上传伪造、CSV 注入没有系统清单 |
| OpenAPI/shared 类型无快照 | 前后端契约漂移靠人工发现 |

目标：**新增独立 L2 系统测试层**（跨进程、可手工/CI 按需跑），并列出其余测试方式与优先级；不追求把 L2 塞进每次提交门禁。

## 3. 测试分层与职责

| 层 | 范围 | 跑法 | 是否门禁 |
| --- | --- | --- | --- |
| L0 单元 | 纯函数/分支 | `pytest -m "not slow and not system"` / vitest / jest | ✅ 每次提交 |
| L1 进程内集成 | TestClient + 临时 DB/存储（现有） | 同上 | ✅ |
| **L2 系统测试（新增）** | 真 uvicorn + 真 worker 子进程 + 临时 DB/存储 + 上游 HTTP 桩 | `bash scripts/ci/system-test.sh`（手动/按需） | ❌ 默认不跑；CI nightly 待定 |
| L3 全栈 UI e2e | 浏览器 → API → DB/文件 | Playwright（需后端，手动） | ❌（现有 20 条） |
| L3 真机 | 移动端 APK 冒烟 | Maestro（待评估） | ❌ |

## 4. L2 系统测试设计

### 4.1 环境隔离（硬约束）

- 全部落在**临时根目录**：`<temp>/system-test/{storage,db,logs}`，通过环境变量注入：
  `STORAGE_ROOT`、`DATABASE_URL=sqlite+aiosqlite:///<temp>/db.sqlite`、`BACKUP_ON_STARTUP=false`、
  `LOG_LEVEL=WARNING`、`OLLAMA_BASE_URL=<桩>`、`COMFYUI_BASE_URL=<桩>`、`API_KEY=`（回环免鉴权）。
- 端口用**临时空闲端口**（bind 0 探测后释放），不碰真实 18888 / 17777 / 18889。
- **绝不读写**真实 `G:/fashion-inspo-storage`、`backend/fashion_inspo.db`。
- 子进程用独立进程组，teardown 时 `taskkill /F /T`（Windows）或 `kill -9` 兜底；失败用例也要清理。
- 断言只走**黑盒**：HTTP API + 直接 `sqlite3` 读临时库；测试进程**不 import app**（避免与子进程共享模块状态）。

### 4.2 组件拓扑

```
pytest (L2)
 ├── 上游桩: Ollama HTTP 桩、ComfyUI HTTP 桩、（可选）face-service 桩/真进程
 ├── uvicorn app.main:app  (临时端口, 临时 DB/存储)
 └── python -m app.worker   (同一临时 DB/存储, 上游指向桩)
```

### 4.3 用例场景清单

| 优先级 | 场景 | 断言要点 |
| --- | --- | --- |
| P0 | 健康检查 + 上传素材 + 列表 + 移入/恢复垃圾桶 + 搜索 | 跨 API 的状态与文件落盘一致 |
| P0 | 批量分析全链路（上传 → 建任务 → worker 执行（Ollama 桩）→ 任务 success → 素材标签/分析日志） | 任务状态机收敛；API 能读到 worker 写入结果 |
| P0 | worker 崩溃恢复：执行中 kill worker → 重启 → stale running 重置/重试 | 无永久 running；retry_count 递增；心跳租约生效 |
| P1 | 多 worker 并发认领同一 pending 任务 | 只有一个执行成功（原子认领系统级复验） |
| P1 | SQLite 写锁竞争：API 写 + worker 写并发 | 无 500；`database is locked` 静默重试 |
| P1 | 出图链路：建批次 → worker（ComfyUI 桩返图）→ 候选 → 确认入库 | 候选图落盘 + 入库记录 |
| P1 | 定时采集到点触发（短周期注入） | 同一到期点只触发一次（乐观锁） |
| P2 | 备份 → 改数据 → 恢复 | 行数/文件哈希一致 |
| P2 | face-service 503/超时 | 任务可重试/失败语义正确，不挂死 |
| P2 | 迁移升级：历史 DB 快照 → `alembic upgrade head` | 关键读接口可用 |

### 4.4 运行方式

```bash
# 手动（本地；不并入默认门禁）
bash scripts/ci/system-test.sh
# 只跑某一类
cd backend && py -3.12 -m pytest tests/system -m system -k smoke -q --no-cov
```

- marker：`@pytest.mark.system`；`pytest.ini` 默认 `-m "not slow and not system"`，不影响现有门禁。
- CI：先不加入 PR job（耗时/子进程兼容性）；待骨架稳定后再评估 nightly job。
- 项目约束「服务启停由用户手动执行」：本层只起**临时端口 + 临时目录**的一次性进程，跑完即清理，不触碰真实服务；脚本不叫 restart/ensure，也不停用户的服务。

### 4.5 断言与失败证据

- 失败时保留临时目录路径与 API/worker 日志路径（打印到 stdout），默认不自动删除（`SYSTEM_TEST_KEEP=1` 时保留）。
- 每个用例独立临时库；同一会话共享 server 进程（启动慢 ~5-8s）。

## 7. 约束与风险

- **不碰真实数据**：环境变量齐套 + 断言前先检查临时 DB 路径（避免误用 `backend/fashion_inspo.db`）。
- **Windows 子进程清理**：uvicorn/worker 必须用 `CREATE_NEW_PROCESS_GROUP` + `taskkill /T`，否则残留 python.exe 会占端口/锁库。
- **启动慢**：uvicorn 首次导入 + Alembic 迁移约 5~8s；用会话级 server fixture，不要把慢注入每个用例。
- **CI 兼容性**：GitHub Actions Linux 上子进程/端口行为不同，等骨架稳定再评估；代理/网络不稳时不要联网。
- **上游桩字段**：桩的响应结构必须与真实服务契约一致；字段名从客户端代码抄，不凭记忆。

## 8. Phase 1 实施记录（2026-11-14）

已落地文件：

| 文件 | 作用 |
| --- | --- |
| `backend/tests/system/conftest.py` | 临时根目录、动态空闲端口、真 uvicorn 子进程（`python -m uvicorn app.main:app`）、假 Ollama HTTP 桩、`api` 客户端；覆盖父级 autouse fixture（不启进程内 TestClient、不清库） |
| `backend/tests/system/test_system_smoke.py` | 3 条 smoke：健康检查；上传→列表→搜索→移入垃圾桶→恢复；直连临时 SQLite 校验隔离 |
| `scripts/ci/system-test.sh` | 手动触发入口：`-m system -n 0 --no-cov`，打印临时根与 uvicorn 日志路径 |
| `backend/pytest.ini` | 注册 `system` marker；默认 `addopts` 排除 `-m system`，不影响现有门禁 |

隔离要点（踩坑记录）：

- **父级 `tests/conftest.py` 在导入时就把 `DATABASE_URL` / `STORAGE_ROOT` / `IMAGES_DIR` 等
  环境变量指向它自己的临时目录**；系统测试的 `server_env` 必须**逐项覆盖**这些
  子目录变量，否则上传会写到父级的临时存储，隔离断言失真（已修复并在 conftest 注释）。
- 上传校验要求真实可解码图片：手写 PNG 字节容易 CRC 错（会 400「文件不是有效的图片」），
  用 Pillow 生成。
- 内容去重是**跨库全局的**：同一字节第二次上传会 409，用例每次用不同颜色生成图片。
- `trash → restore` 后文件名可能被规范化：恢复后的落盘校验以**接口返回的当前
  `file_path`** 为准，不沿用上传时的路径。
- 日志：`app/logging_config.py` 的 `LOG_DIR` 固定为仓库根 `logs/`（gitignore），
  系统测试的 uvicorn 日志另存临时根（失败时脚本打印路径）；业务日志仍会追加到
  `logs/backend.log*`，与开发服务共用目录（不影响数据隔离）。

验证命令与结果：

```bash
bash scripts/ci/system-test.sh          # → 3 passed（约 20s，含启动/迁移/清理）
cd backend && py -3.12 -m pytest tests/system -q   # 默认门禁：0 选中（被 marker 排除）
```

已知限制：worker 子进程、故障注入、ComfyUI 桩尚未接入（Phase 2/3）；Phase 1 只有
API 进程 + 上游桩。

### Phase 2 实施记录（2026-11-14）

新增：

| 文件/组件 | 作用 |
| --- | --- |
