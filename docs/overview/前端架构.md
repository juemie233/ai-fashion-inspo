# 前端架构（web/）

> **状态**：现行（2026-11-15 按代码盘点）。真源：`web/src/**`、`web/vite.config.ts`。
> 本文讲**骨架与落点规则**（放哪个目录、状态放哪、接口怎么调）；单个功能的方案见 [features/](../features/) 下对应文档。

## 1. 一句话

Vue 3 + Vite + TypeScript 的单页应用，**视图只做编排**：数据加载、子组件组装、事件接线；
业务细节沉在 `composables/`，HTTP 只在 `api/`，纯函数只在 `utils/`。

## 2. 目录职责（含当前规模）

| 目录 | 职责 | 规模 |
| --- | --- | --- |
| `views/` | 页面组件，只做编排；超 ~800 行优先拆 | 18 个文件 / 7,088 行（最大 `FaceScanView.vue` 721 行） |
| `components/{域}/` | 按业务域分子目录的子组件，props + emit | 15 个域 / 161 个 `.vue` |
| `components/common/` | 跨域基础件（ErrorBoundary / HoverImagePreview / LoadMoreBar / StatCardGrid / StatusTag / ThumbCard …） | 8 个 |
| `composables/` | 状态 + 逻辑单元，内部自己 `useMessage()`，不碰 DOM | 74 个 `useXxx.ts` |
| `api/` | 每个后端资源一个模块，只做请求/响应映射 | 15 个模块 + `client.ts` |
| `stores/` | Pinia：**只放跨页共享**的状态 | 5 个 |
| `router/` | 路由表（19 条）与 `meta.title` | 1 个文件 |
| `constants/` | 前端常量（`gridDensity` / `tag` / `upload`） | 3 个 |
| `styles/` | 全局样式（Arco 主题、场景样式） | 2 个 |
| `types/` | 跨组件复用的 TS 接口 | — |
| `utils/` | 纯函数（`format` / `apiError` / `apiGuard` / `sourceLabel` …） | 35 个 |

`@` → `web/src`，`@shared` → 仓库根 `shared/`（前后端共享类型）。

## 3. 一条数据怎么流

```
view（编排）
  └─ composable（加载/分页/竞态/校验/提示）
       └─ api/*.ts（请求封装 + 响应映射）
            └─ api/client.ts（axios：/api、超时、X-API-Key、错误归一）
                 └─ 后端（Vite 代理 → :18888）
```

判定规则：

| 状态用在哪 | 放哪 | 例 |
| --- | --- | --- |
| 只在单个页面/组件用 | `composable` 内 `ref` | 搜索筛选、分页游标 |
| 跨页且需持久（切换路由不丢） | Pinia `store` | 模型列表/活跃模型、素材列表、标签选中、UI 状态 |
| 只影响一颗子树 | props + emit | 卡片角标、弹窗开关 |

**为什么要刻意少用 store**：store 是全局单例，容易变成"什么都往里塞"的垃圾场；
本项目的 `useXxx` 模式下，绝大多数状态天然随组件生命周期，没必要全局化。

## 5. API 层约定（`api/client.ts`）

| 项 | 取值 / 行为 |
| --- | --- |
| baseURL | `/api`（同源，开发期由 Vite 代理到 `:18888`） |
| 超时 | 30 s |
| 认证 | 配了 key 时自动加 `X-API-Key`（来源：`localStorage.apiKey` → `VITE_API_KEY`） |
| 成功判定 | 仅 2xx；4xx/5xx 进 catch |
| 错误 | 响应拦截器统一取出 `detail`；同时记录响应头 `X-Request-ID`（后端每个响应都带），报障时可按 `req=` grep `backend.log` |
| 提示 | `utils/apiError.ts` 取文案，`utils/apiGuard.ts` 处理"部分失败但整体可用"（如批量操作里个别 4xx） |

惯例：**一个后端资源 = 一个 `api/*.ts`**；页面不要直接 `import axios`，也不要自己拼 `/api/...`。

## 6. 实时推送

`composables/useWebSocket.ts` 是模块级单例：任意组件首次调用 `connectTaskWebSocket()` 即接通 `/ws`，
断线指数退避重连（1 s → 30 s 封顶），重连成功广播 `reconnected` 事件。各页面的轮询在 WS 断开时自动降级。

## 7. 组件分层

- `components/common/` —— 无业务含义、可跨域复用（看图浮层、加载条、状态标签、错误边界）。
- `components/{admin|chart|collection|generate|home|inspiration|layout|model|person|scraper|search|tag|task|upload}/` ——
  有业务语义的子组件，按域存放。当前规模最大的三个域：`tag`(28) / `person`(27) / `admin`(19)。
- 域内再拆时保持"一屏一组件"，props 只传展示所需，事件用 emit 抛给视图。

## 8. 新增功能的落点 checklist

| 要加的东西 | 放哪 | 注意 |
| --- | --- | --- |
| 新页面 | `views/` + `router/index.ts` 一条 + 侧边栏菜单 | 页面超过 ~800 行先拆 |
| 页面内的状态/加载逻辑 | `composables/useXxx.ts` | 内部自己 `useMessage()`，不操作 DOM |
| 调新接口 | `api/{resource}.ts` | 不直接用 axios；响应用 `types/` 里的接口 |
| 跨组件类型 | `types/{domain}.ts` | 不在组件里另定义一份 |
| 纯函数（格式化/映射） | `utils/` | 多处重复的实现必须收敛到这里 |
| 下拉选项/默认值 | `constants/` | 与后端枚举保持同源（如 `sourceLabel`） |
| 全局交互状态 | `stores/ui.ts` | 其余场景优先 composable |

## 9. 构建与调试

```bash
cd web
npm run dev          # http://localhost:17777，/api 与 /ws 代理到 127.0.0.1:18888
npm run build        # vue-tsc + vite build
npm test             # vitest（纯函数 / composable / store）
npm run lint         # eslint（0 error 门槛）
npm run test:e2e     # Playwright（需后端在跑）
```

端口与代理在 `web/vite.config.ts`（`VITE_FRONTEND_PORT` / `VITE_BACKEND_URL`）。

## 10. 已知边界

1. **`composables/` 有 74 个**：按域切分后单文件都很小，但数量偏多；找逻辑先按页面名搜（`useHomeActions` / `useSearch` / `usePersonDetail`）。
2. **三个大域组件多**（tag / person / admin）：改动这些域时先看该域的 `__tests__`，多数交互已有单测锁定。
3. **无权限层**：不要在页面里假设"某个按钮只有管理员可见"。
4. **时间列必须单行**：表格里的时间列统一走 `utils/format.ts` 的 `renderTimeCell`（见 CLAUDE.md 核心规则 7）。
