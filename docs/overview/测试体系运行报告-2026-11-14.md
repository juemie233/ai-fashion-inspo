## 3. 判断：测试体系有没有问题？

**有，但不是“测试大面积红”**。当前属于：

> 核心单测/进程内集成很强；L2/L3 已经能跑通；问题是**门禁覆盖不完整 + 少数测试不稳定 + 度量范围偏窄**。

### P1 级问题

| 问题 | 影响 | 证据 |
| --- | --- | --- |
| **slow 用例不在任何门禁** | 重要迁移/竞态/依赖探测用例长期不跑 | `pytest.ini` 默认 `not slow`；CI/test.sh 未覆盖；手动补跑 38 passed / 1 skipped |
| **L2 系统测试不在 CI** | 跨进程、故障注入、worker 恢复只在手动跑时才知道 | 7 passed 仅来自 `system-test.sh`；CI 无 system job |
| **E2E 不在 CI** | iPad/关键页面回归依赖人记得跑 | 29 passed 仅来自本地 `playwright test`；CI 无 e2e job |
| **系统测试共享一个临时库** | 新用例可能顺序敏感；故障注入与普通用例互相污染 | `tests/system/conftest.py` session 级 `system_root` + 覆盖 `clean_state` 为 no-op |

### P2 级问题

| 问题 | 影响 | 证据 |
| --- | --- | --- |
| **前端 5s 默认超时在并发下假红** | 本地同时跑三端会把测试不稳误判为功能坏了 | 并行 1 failed；单独 1,246/1,246 通过 |
| **前端覆盖率范围窄** | 组件/视图没有进入覆盖率分母 | vitest coverage 只 include `utils/composables/stores/api`，门槛 50% |
| **后端门槛低于实际** | 88.3% 的现有保护没有被棘轮锁住 | 当前 88.30%，`test.sh` 82.9%，CI 82% |
| **warning/泄漏噪音** | 真正的回归容易被淹没 | 348 条 Vue warning；移动端 worker 强制退出；后端 23 条 warning |
| **E2E iPad 非 Safari** | Safari 特有布局/手势问题抓不到 | Playwright Chromium `isMobile` 模拟 |
| **测试文档仍有局部漂移** | 方案文档与当前 Phase 4/5 状态不完全同步 | 如 §4.1 仍写 `COMFYUI_BASE_URL` 为不可用端口，Phase 4 已接桩 |

### P3 级问题

- `integration` marker 已注册但全仓 0 处使用；分层 marker 目前只有 `slow`/`system` 真正起作用。
- E2E 的 25 个定义与 29 次执行容易在汇报里混淆，建议统一写「25 个用例/29 次执行」。
- L2 脚本用 `-q` 两次导致最终没有 “7 passed” 汇总行，只能看 7 个点/退出码。

## 4. 建议

### 4.1 门禁层

1. **加 slow 入口**：`test.sh --slow` 或 CI nightly 跑 `pytest -m slow -n 0`；至少每周一次。
2. **加 L2/L3 nightly 或每周任务**：system-test 7 条 + e2e 29 次；CI 可先只跑 Linux 兼容部分。
3. **统一覆盖率口径**：本地 82.9 vs CI 82 对齐；后端阈值考虑提到 87–88%；前端明确 components/views 是否纳入。
4. **CI 与本地 `test.sh` 对齐**：CI 后端仍写 `--cov-fail-under=82`，本地是 82.9。

### 4.2 稳定性

1. 给 `UploadView` 等挂载较重的视图测试设置 `testTimeout: 10000`，或修掉缺失 mock 后减少异步等待。
2. 系统测试加 per-test 命名空间/数据前缀，或在用例间重建临时库；至少把「不得假设库为空」作为硬约束。
3. 手机端补 `afterEach` 清理 timer/handle，用 `--detectOpenHandles` 定位强制退出。
4. 收敛前端 Vue warning（补 `fetchTagsGrouped` mock、生命周期调用位置）。
5. 设置 `asyncio_default_fixture_loop_scope`，消掉 pytest-asyncio 弃用 warning。

### 4.3 覆盖层

1. 把 `components/common` 与高频业务组件纳入前端 coverage，或明确在文档里写「views/components 不在覆盖率口径」。
2. E2E 增加 WebKit/Safari 真机或 BrowserStack 可选档；iPad 布局不能只靠 Chromium。
3. 契约快照扩到全量 OpenAPI + `shared/types` 对齐检查（方案文档 §5 已列为待做）。
