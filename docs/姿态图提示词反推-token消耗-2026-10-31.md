## 1. 目的与假设

**目的**：

- 验证「用 DeepSeek 接口读姿态图并反推出可复用提示词」这条链路是否可行、输出质量如何；
- 量化单张图的 token 消耗，给出平均水平与波动范围，便于估算批量反推的成本。

**不验证**：提示词反推结果对下游图生图的实际收益（那需要出图对比，另做实验）；也不比较不同模型/不同分辨率下的效果。

**假设**：输入 token 由「固定文本 + 图片」两部分构成，图片部分可能随分辨率/尺寸变化，文件体积不应影响 token 数。

## 4. 判断与下一步

**结论**：

1. 链路可行：10/10 全部成功（`stop_reason=end_turn`），提示词与姿态名称、角度基本一致，能写清重心、四肢位置、手部动作与景别；
2. 单张平均 **892.2 token**（804 输入 + 88.2 输出），估算批量成本可直接用 `样本数 × 892`；
3. 输入中 **670 token 是图片固定开销**，占 83.3%——同一尺寸下加不加文件压缩、换不换内容都不变；想压成本只能改图片尺寸/分辨率或减少输入图数量；
4. 输出只占约 10%，提示词长度控制在 80～150 字时输出 token 稳定在 77～105。

**成本换算**：按当前口径，反推 100 张约 8.9 万 token、1000 张约 89 万 token（输入 80.4 万 + 输出 8.8 万）。具体金额按所用模型的实时单价换算。

**下一步（可选）**：

- 若只需姿势骨架、不需要细节，可把图片缩到更小分辨率再送，观察 670 token 是否下降；
- 若提示词质量不够，可打开 thinking（会增加输出 token），或把 10 条结果喂给出图链路做 A/B；
- 本次未做「反推提示词 → 出图」的效果对比，报告中不评价下游收益。
