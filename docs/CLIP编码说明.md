# CLIP 编码说明（本项目向量化基础）

> 关联功能：管理页「向量管理」一键向量化、详情页相似推荐、语义搜索、质量初筛器。
> 背景：素材详情页打开卡顿的根因是「无图像向量的素材在请求链路内现场做 CLIP 编码」。

---

## 1. 一句话

**CLIP 编码就是把一张图片"翻译"成 512 个数字（一个向量），让计算机能用数学方式比较图片的相似程度。**

## 2. CLIP 是什么

CLIP（Contrastive Language-Image Pre-training）是 OpenAI 开源的**多模态模型**，同时理解图片和文字。训练时它学会了一件事：**语义相近的图片和文字，在向量空间里距离也近**。

- 输入一张"法式连衣裙街拍" → 输出的向量，和文字"法式连衣裙"的向量**方向接近**
- 这是它区别于传统图像模型（只看图片）的关键：**向量携带"语义"**，不只是像素特征

## 3. "编码"（Embedding）具体做了什么

```
图片（像素矩阵）──CLIP 模型──→ [0.021, -0.134, 0.087, ... , 0.053]  ← 512 个浮点数
                                ↑ 这就是"向量"/"Embedding"
```

编码 = 一次**前向推理**：图片经过模型的多层神经网络，最后压成固定维度的向量（本项目是 **512 维**，模型 `clip-ViT-B/32`，来自 sentence-transformers 库）。

**为什么是 512 个数？** 因为模型把图片"压缩"成 512 个维度的特征描述——每个维度代表某种抽象特征（可能有的接近"裙摆"、有的接近"暖色调"、有的接近"人像"）。固定维度让所有图片可以**直接比较**。

## 4. 向量能做什么（本项目的实际用途）

| 用途 | 原理 | 项目位置 |
|---|---|---|
| **以图搜图 / 相似推荐** | 两张图片向量**余弦相似度**接近 = 视觉/语义相近 | `similarity.py` 的 `cosine_similarity`、`find_similar_hybrid`（详情页"相似素材"） |
| **语义搜索** | 文本也编码成向量（384 维，Ollama all-minilm），文本向量与图片向量比对，实现"搜'白色连衣裙'" | 向量检索 + 关键词混合排序 |
| **质量初筛器** | 用图像向量训练 sklearn 分类器，识别垃圾素材 | `quality_learner.py` |
| **向量存储** | 所有向量存在 **LanceDB**（嵌入式向量库，本地文件 `storage/lancedb/`） | `vector/store.py` |

**关键：相似度计算（比较）极快**（微秒级），但**编码（生成向量）慢**（模型推理，单张数百毫秒～数秒，取决于 CPU/GPU）。

## 5. 为什么详情页会卡顿（痛点根因）

```
正常路径（已有向量）：
  打开详情 → 相似推荐 → 查 LanceDB 拿向量 → 比对（快，毫秒级）

卡顿路径（无向量）：
  打开详情 → 相似推荐 → 发现没向量 → 现场调用 CLIP 编码这张图（1~3 秒！）
               → 才拿到向量去比对 → 页面卡住
```

`_get_or_build_image_vector`（`vector/similarity.py`）就是干"没有就现场生成"这件事的——**编码是同步阻塞在请求链路里的**，所以打开无向量素材明显卡顿。

**解决方案**（已上线）：管理页「向量管理」→「一键向量化缺失素材」，提前把全部素材编码好存进 LanceDB（异步后台任务，由 worker 执行），让详情页永远走快路径。真实环境 3154 张图片中曾有 956 张（30%）缺向量。

## 6. 简单类比

- **CLIP 编码** = 给每张照片写一段"统一格式的语义简历"（512 个字）
- **向量库（LanceDB）** = 存放所有简历的档案柜
- **相似推荐** = 拿当前照片的简历，快速翻档案柜找"经历最像"的
- 卡顿 = 遇到没写简历的照片，现写一份（很慢），而不是直接查档案

## 7. 补充说明

- 本项目用的是 **`clip-ViT-B/32`**（ViT-Base 架构，32×32 patch，约 1.5 亿参数），512 维输出；首次使用会自动下载模型
- **编码结果可离线重复使用**——同一张图编码结果固定，所以"一次性编码、长期复用"才划算（这正是向量化任务的意义）
- 文本向量走 Ollama `all-minilm`（384 维），与图像向量分表存储（`text_vectors` / `image_vectors`）
- 如果编码慢到不可接受，可行优化方向：换更轻的 CLIP 变体（如 ViT-S/16）或换 GPU 推理；但对 3000+ 素材的规模，一次性后台编码是最优解
